# Engine PR #343 network E2E validation

This runner starts independent Engine processes with encrypted profiles. Linux network cases use network namespaces, a bridge, kernel WireGuard and nftables. The host uses production network policy. Its feature graph must not contain `uc-infra-p2p/test-util`.

The acceptance build enables only `production-e2e,clipboard-stream-fault,network-test-probe`. The normal control build enables only `production-e2e`. Check and retain both resolved feature graphs. Neither graph may contain `uc-infra-p2p/test-util`.

The runner owns process lifecycle, fault injection, readback assertions, privacy checks and cleanup. It does not implement Engine recovery or change production business code. The invitation fixture uses the existing codecs and communicates only through pipes.

## Requirements

- Linux, root or equivalent namespace/network capabilities.
- Rust toolchain supported by the pinned source, initialized submodules, Node.js, Python 3, iproute2, nftables, WireGuard tools, conntrack, ping and tcpdump (NFLOG support).
- One shared Cargo target and the repository compiler-cache setup.
- An isolated disposable container or machine. Do not use the host network of a production server for fault injection.

The host uses an in-memory clipboard and secure-storage adapter. These cases do not validate a Desktop GUI, native clipboard watcher, platform keychain or real sleep/wake transition.

## Run

From the repository root:

```bash
bash scripts/testing/run-pr343-e2e.sh \
  --case L01 --repeat 1 \
  --evidence target/connection-recovery-evidence/pr343-minimal
```

After the minimal case completes, run independent cases:

```bash
bash scripts/testing/run-pr343-e2e.sh \
  --repeat 3 \
  --evidence target/connection-recovery-evidence/pr343-full
```

`--case` accepts a comma-separated list of prefixes. Each iteration creates fresh profiles and namespaces. Use `--address-probe disabled` for a same-binary L03 observer control; this removes probe installation, expected-socket updates and snapshots. Also build `--no-default-features --features production-e2e` separately for the feature-off control. Neither control changes guard, transfer or deadline assertions. `S03` includes allowed overlay (`S03A`), configured (`S03C`), full-invitation (`S03I`), persisted (`S03P`) and discovered (`S03D`) address cases. Each subcase records its own result.

`S05` requires `--baseline-host`. Build that host from base `80bda137541f1a054897f8d1474634dac9d752e8` with the same test-host adaptations and pinned submodules. If archived source snapshots share a target, refresh snapshot source timestamps before switching snapshots; do not clear the compiler cache.

`S04` runs the existing `connection-recovery-network.mjs` suites for direct, known-peer, relay and both legacy directions. Supply `--regression-host`, `--relay` and `--legacy-host`. Freeze these executables separately from the production-policy host.

## Evidence and failure policy

`result.json` contains source labels reported by the host, binary and runner SHA-256 values, per-case outcomes, fixed failure codes, safe diagnostic counts, payload hashes, network counters, lifecycle events and cleanup/privacy results. `complete: true` means the selected cases finished. It does not mean they passed.

A product, environment or evidence failure produces `outcome: failed`, `failed_attempt: true`, a category and a reason. The runner then continues with the next case. It stops repeating the failed case. An unexpected test-code exception produces `test_error` and stops execution so the harness can be repaired. Preserve the first artifact and use a new evidence directory for each repair or experiment. Any failed case makes the process exit with status 1.

Only actual receiver readback proves delivery. Online state and a successful send response do not prove delivery. Text and file bytes must match their expected hashes. Recovery cases must show native stream RESET or an exact held completion and preserve presence. A shared UDP loss rule does not isolate content streams. R01/R02 isolate the independent ActiveClipboard pull using a native pull request send-half RESET. Receiver-path events identify actual persistence outcomes. R02A is a positive diagnostic: it permits normal active pull while all ordinary push attempts fail, and requires an attributed active-pull commit and hash readback. R03 verifies a second bounded window after one offline/online transition. R04, R04F and R04E force a late success or failure while a newer item has an active or exhausted retry budget. R05T checks real terminal receiver refusal across a quiet window and resume. R05O pauses after actual acquisition but before opening a content stream. R05I holds the caller after a real registered acquisition and an observed native first poll of Pending. It does not claim that the native backend remains pending at suspend. R05A holds the actual Applied receipt before ACK and requires the exact release/cancellation outcome, preserved receiver content, and post-resume duplicate confirmation. R05G tests the final global receive gate for an existing-content write using actual preparation, clipboard invocation and readback.

The privacy scan checks full short canaries and multiple fragments of long canaries across files under each temporary profile, including databases, WAL files and logs. It records probe and file counts. The runner stops processes and removes profiles, namespaces and bridges after each case. Do not export profile copies, secure-storage state, full invitations, keys or raw network captures.

The zero-packet address assertions are stronger than a guarantee about initial dial candidates. Iroh can learn and probe authenticated remote paths after a connection exists. Report observed packets and this boundary explicitly. Do not weaken a failed assertion to claim isolation.

Keep the original report under `.planning/2026-11-01-engine-343-e2e/` immutable. Development evidence belongs under `.planning/2026-11-01-engine-343-development/`. Device and product acceptance remains separate from Engine laboratory results.

## Dynamic subnet lifecycle evidence

S03N starts with real global-IPv6-only bidirectional text and file transfers. It changes the same local address from /64 to /128 using delete/add, while preserving the final address set, listener and explicit peer route. This is a transient address removal, not an atomic prefix-only operation. The case requires native invalidation and same-generation false publication, fixed-local bidirectional text/file completion, then native restoration and global bidirectional text/file completion. Ordinary renewal cannot substitute for either native event.

Two independent tcpdump NFLOG processes observe the peer-global UDP predicate in each network namespace. The same OUTPUT rule increments its cumulative counter and logs the event before later drop rules. Capture starts before pairing and remains active through host shutdown. Export only packet observation time, sequence, node/direction alias and predicate alias. Never export raw tcpdump lines, packet payload, addresses, ports or pcap. Require exact final counter/parsed/captured/received agreement and zero drops, parser errors and overflow.

Libpcap 1.10.3 timestamps NFLOG events with userspace gettimeofday. This is an external observation envelope, not kernel-send time or hook-admission causality. Require zero A-to-B global observations from the matching native invalidation through the restoration-command start. Treat overlap/clock ambiguity as non-passing. Retain the complete ledger, including authorized, mutation, detection and restored intervals. A Linux CLOCK_REALTIME timerfd with absolute cancel-on-set flags guards the whole capture interval against discontinuous clock changes. Retain paired realtime/monotonic brackets and the probe clock journal. Quantization and measured journal offset spread expand the checked interval conservatively; they do not permit delayed traffic.

Keep whole-window cumulative deltas and historical zero comparisons as conservative diagnostics. That window includes initially authorized traffic and cannot locate admission by itself. Preserve all historical failures. The five static S03C/A/I/P/D zero assertions retain their original intervals, predicates and positive controls. Dynamic global captures do not replace them.

M03V removes all non-loopback IPv4 addresses before Engine bootstrap. It proves that wildcard IPv4 binding succeeds while default multicast membership fails, then requires IPv6 pairing, bidirectional text/file completion, changed-port cold reconnect, and fresh mDNS candidates. It does not claim isolated coverage of every private socket sender branch.
