# Uni Rust 开发

开始前完整阅读根 `AGENTS.md`、目标目录最近的 `AGENTS.md` 和 `docs/design-docs/rust-style.md`。再按修改范围读取它们直接引用的领域规则，不复制这些规则到本 skill。

## 工作方式

1. 在动手前定义完成标准。写清完整负责人、调用方唯一动作、成功与失败结果、重试或重启责任，以及实际验证方式。
2. 检查现有依赖和相邻实现，选择满足需求的最小完整方案。跨层或长期行为变化先核对 active plan；缺少计划且任务需要时补充计划。
3. 先实现并运行一个端到端切片。只在该切片证明方向正确后扩展剩余范围。
4. 名称在模块入口集中引入。函数签名和正文避免重复完整 `crate::` 路径；仅按 Rust 编写规范使用带理由的例外。
5. 先运行直接相关的测试。通过后执行根 `AGENTS.md` 的交付检查，并检查实际输出和工作区差异。
6. 本次引入的失败必须修复并重跑。已有失败或设备缺口记录实际证据，不标成通过。
7. 修改仓库内容后同步 `docs/architecture/architecture-bible.md`，并保留用户已有和范围外改动。

## 完成条件

- 请求的行为形成可使用、可验证的完整结果。
- 新增 Rust 代码通过格式、编译、相关测试和 Rust 风格门禁。
- 没有通过临时旁路、重复实现或扩大公开接口掩盖未完成工作。
- 汇报只陈述实际执行过的验证和仍未执行的环境。
