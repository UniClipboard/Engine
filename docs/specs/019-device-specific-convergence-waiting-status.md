# 工作空间收敛等待状态按设备精确公开

## 状态

等待名单已实施（Engine、绑定与移动测试宿主）。ADR-020 已改变等待名单的含义：它只描述本机
已知传播，不能证明全局一致；待用户移除决定、分叉关系以及独立在线状态待重新同步。产品仓投影
和界面验收不在本仓执行。

本文落实 ADR-019，定义工作空间收敛在等待离线成员时如何给出准确的设备名单。它修订
[工作空间全局收敛](016-workspace-wide-convergence.md) 和
[uc-engine 跨平台核心接口](uc-engine-interface.md) 中“快照不含设备编号”的旧约束：快照现在
可以只在严格限定的等待场景中公开阻塞设备的稳定标识。

## 目标

- 用户能在对应设备条目上看到“此设备需要上线完成资料更新”，而不是只能看到笼统的顶部提示。
- 只有确实阻塞当前收敛的设备才会被标记；普通离线设备不能被误标。
- 查询、实时通知、绑定、宿主和产品侧投影始终得到同一份名单与数量。
- 成员移除、重新加入、确认和重新可达后，名单无需产品端补偿即可立即反映当前事实。
- 不增加新的持久化事实、产品端队列、重试逻辑或在线状态推断。

## 非目标

- 不用此状态表示设备版本、功能能力、升级要求、配对状态或一般在线状态。
- 不让产品端选择交接设备、发送资料、驱动重试或决定何时完成。
- 不公开设备名称、成员实例、地址、签名、密钥、安全变化、内容或底层错误。
- 不为旧客户端保留“只给数量、由客户端自行猜测名单”的兼容路径。
- 不改变默认 P2P 行为，也不因等待状态进入 LAN 兼容线。

## 已确认的现状

当前 `WorkspaceConvergenceState` 已保存推导所需的全部事实：

| 现有事实 | 当前作用 | 本规格中的作用 |
| --- | --- | --- |
| 有序成员变化 | 计算当前有效成员集合 | 排除历史和已移除成员 |
| 当前确认 | 判断哪些有效成员已跟上当前目标 | 排除已完成成员 |
| 待交接记录 | 证明当前仍有资料等待交接 | 判断等待阶段是否成立 |
| 暂时不可达成员集合 | 记录已知成员离线 | 识别当前需要重新上线的成员 |
| 成员实例到设备标识的映射 | 向对应设备发送或验证资料 | 将内部成员实例转换为产品可匹配的设备标识 |
| 本机成员实例 | 标识本机当前身份 | 排除本机 |

当前完成阶段判定已经要求：只有存在待交接记录、且所有尚未确认的当前有效成员都暂时不可达时，
`workspace_completion` 才进入 `WaitingForOfflineMember`。已实施摘要使用单一阶段；ADR-020 实施时
必须改为独立的成员变化和工作空间完成两条进度，不保留单一阶段兼容映射。

不可达事件由收敛运行期接收设备可达性变化后写入当前收敛状态；写入时只接受当前有效实例。新的
成员变化会清除已移除实例的确认、待交接和不可达记录；同一设备重新加入后，可达性更新总是定位到
最新成员实例。这些既有规则是名单正确性的唯一来源。

## 责任边界

| 范围 | 必须负责 | 不得负责 |
| --- | --- | --- |
| `uc-core` 工作空间收敛状态 | 从已保存事实推导当前等待设备名单和等待数量，保持成员实例规则与阶段规则一致。 | 不知道页面、HTTP、设备名称或产品提示文案。 |
| `uc-application` 收敛负责人和运行期 | 在成员变化、确认、待交接和可达性变化后保存并发布新快照。 | 不维护另一份可展示名单，不由产品调用决定名单。 |
| `uc-engine` | 将完整快照转换为稳定对外结果；查询与事件复用同一转换。 | 不重新判断在线、确认或成员资格。 |
| iOS、Android、HarmonyOS 绑定与测试宿主 | 完整映射名单和数量。 | 不补充、删减、重排或根据本地在线状态猜测名单。 |
| 产品侧 HTTP 投影与实时事件 | 原样透传 Engine 结果和生成类型。 | 不自行计算等待设备。 |
| 产品界面 | 用设备条目的稳定标识匹配名单，只在命中的条目显示等待状态。 | 不显示统一顶部等待提示，不保存本地等待队列。 |

## 对外数据

ADR-020 的目标 `WorkspaceConvergenceSummary.workspace_completion` 包含必填字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `waiting_member_device_ids` | 有序字符串列表 | 当前确实阻塞收敛、需要重新上线或完成确认的设备稳定标识。 |
| `waiting_member_count` | 无符号整数 | 始终等于 `waiting_member_device_ids` 的长度。 |

内部快照以受校验的设备标识类型保存这份派生结果；Engine 在稳定边界转换为字符串列表。名单的顺序按
设备标识升序固定。若多个当前成员实例意外对应同一设备标识，对外名单只保留一次该标识，数量按去重后
的设备数计算。

`workspace_completion.waiting_member_device_ids` 是完整替换快照的一部分，不是增量事件。
`QueryWorkspaceConvergence`、
`RemoveMember` 成功结果和 `WorkspaceConvergenceChanged` 都必须返回同一字段及相同语义。

## 推导规则

### 前置条件

只有 `workspace_completion` 为 `WaitingForOfflineMember` 时才推导并公开名单。任何其他完成阶段，
包括 `Converging`、`Complete` 和 `RecoveryRequired`，都必须返回：

```text
waiting_member_device_ids = []
waiting_member_count = 0
```

这条规则优先于单纯的离线记录：设备在 `Converging` 时离线、但还有可达设备尚未完成，不能出现在
名单中。`membership_transition` 可以同时为 `LocallyApplied`、`AwaitingCommit`、`Committed` 或
`AwaitingActivation`；它不得清空、替换或遮住提交后等待名单。

### 成员筛选

在等待阶段，候选成员实例必须同时满足：

1. 位于当前有效成员集合；
2. 未确认当前工作空间摘要；
3. 位于暂时不可达成员集合；
4. 不等于本机当前成员实例。

阶段本身已经保证当前未确认成员只剩不可达成员，并且仍存在待交接事实；上述筛选仍必须显式执行，
以保证快照不会因历史记录、重复事件或本机可达性事件泄露无关成员。

每个候选实例必须由当前实例到设备标识映射解析，再按设备标识去重和排序。成员实例、历史映射和
设备名称不得进入对外结果。

### 一致性不变量

下列条件必须始终成立：

1. `waiting_member_count == waiting_member_device_ids.len()`；
2. 仅工作空间完成的等待阶段可以有非空名单或非零数量；
3. 名单中的每个设备都有一个当前有效、未确认、不可达且非本机的成员实例；
4. 每个满足上述条件的设备都出现在名单中；
5. 名单稳定排序，不因事件到达顺序、哈希遍历顺序或产品端缓存变化；
6. 已移除实例和本机实例永远不出现在名单中；
7. 同一设备重新加入后，只能由新成员实例贡献名单项。

有效成员实例缺少设备标识映射表示已保存状态不完整，不能静默跳过该成员并返回部分名单。负责人必须
将其视为无法安全继续的状态：不发布部分等待名单，进入 `RecoveryRequired`，并通过既有稳定失败类别
表达；不得用设备名称、在线事件来源或历史缓存补造标识。

## 状态变化

| 事件 | 公开结果必须如何变化 |
| --- | --- |
| 某未确认有效成员离线，且其余未完成成员均已离线并存在待交接 | 进入等待阶段；名单列出所有满足筛选条件的设备。 |
| 仅部分未完成成员离线，仍有可达成员可继续处理 | 保持 `Converging`；名单和数量均为空/零。 |
| 名单中的设备重新可达 | 立即退出等待阶段或继续收敛；名单和数量立即清空，运行期继续内部交接。 |
| 名单中的设备完成当前确认 | 该设备不再满足未确认条件；若所有成员完成，进入 `Complete` 且名单为空。 |
| 下一项成员变化开始但尚未正式提交 | 保留最新已提交目标的完成阶段和名单；成员变化进度单独更新。 |
| 新成员变化正式提交形成更高目标 | 按新目标重新判定；不得沿用旧目标的名单。 |
| 成员被移除 | 清除其不可达和待交接事实；该设备不再出现在名单。 |
| 同一设备以新实例重新加入 | 旧实例不会贡献名单；新实例按当前变化、确认和可达性重新判定。 |
| 进入 `RecoveryRequired` 或无有效成员 | 名单和数量清空；不得把需要人工处理误标为“等待设备上线”。 |

## 绑定、宿主和产品侧要求

Engine 新字段必须进入以下现有出口：

1. Rust 稳定结果和 `WorkspaceConvergenceChanged` 事件；
2. UniFFI 的 `WorkspaceConvergence` 查询结果和事件载荷；
3. HarmonyOS N-API 的 `OhWorkspaceConvergence` 查询结果和事件载荷；
4. 移动测试宿主的查询 JSON 与事件记录；
5. 产品仓的 `GET /member/workspace-convergence`、`workspace-convergence.changed` 和生成的客户端类型。

产品界面以 `waiting_member_device_ids` 与设备条目的 `peerId` 精确匹配。命中时显示设备条目末尾的
等待状态与“此设备需要上线完成资料更新”说明；不命中时不显示该状态。页面不得以所有离线设备、
当前连接状态、旧事件、缓存数量或等待时长推断名单。产品端移除顶部统一等待提示，而不是在新旧提示
之间保留兼容分支。

## 持久化、隐私和日志

名单是由已加密保存的工作空间状态在读取时派生的结果，不新增数据库列、迁移、缓存或搜索索引。成员
变化、确认、待交接、不可达记录和实例到设备标识映射继续作为敏感业务载荷加密保存。

对外结果只在严格等待场景公开已经属于当前成员设备列表可见范围的稳定设备标识。它不得带出设备名称、
成员实例、地址、签名、密钥、安全变化、资料内容或底层错误。生产日志不得输出完整等待设备标识或
名单；如需观察，只记录等待数量和既有脱敏流程标识。

## 失败处理

| 情形 | 必须行为 |
| --- | --- |
| 收到未知设备或已移除实例的离线事件 | 忽略，不改变名单。 |
| 设备重新可达但尚未确认 | 清空等待名单并继续内部收敛；不得继续显示离线等待。 |
| 收到过期确认或旧目标确认 | 不改变当前名单，仍按当前目标重新计算。 |
| 当前有效等待成员缺少设备标识映射 | 不返回部分名单；进入 `RecoveryRequired`。 |
| 消费者错过状态事件 | 收到通用刷新要求后重新查询，得到完整当前名单；不得通过缓存修补。 |
| 绑定或产品投影未识别新字段 | 视为版本未同步，不能用本地推断替代；发布新 Engine 产物并同步固定版本。 |

## 测试与验收

### 核心状态测试

1. 三台设备中仅 B 未确认且不可达：阶段为等待，名单为 `[B]`，数量为 1。
2. B 与 C 未确认且不可达：名单稳定为 `[B, C]`，数量为 2；反转事件到达顺序后结果相同。
3. B 离线但 C 仍可达且未完成：阶段为收敛，名单为空，数量为 0。
4. B 重新可达后：名单和数量立即清空；B 完成后不再进入名单；全部完成后阶段为完成。
5. 移除 B 后：B 的不可达和待交接记录不再贡献名单。
6. 同一设备移除后重新加入：旧实例的不可达、确认和待交接事实不会污染新实例。
7. 本机被错误标记不可达：本机不出现在名单。
8. 当前等待成员缺少设备标识映射：不产生部分名单，进入需要恢复状态。

### 稳定接口与绑定测试

1. Engine 查询、移除结果和实时事件返回完全相同的名单与数量。
2. `waiting_member_count` 总是等于名单长度；非等待完成阶段始终为空/零。
3. 后一项变化处于 `AwaitingCommit` 时，前一项完成进度和等待名单仍由查询与事件完整返回。
4. UniFFI、HarmonyOS 和移动测试宿主完整映射名单，查询和事件一致。
5. 所有手写快照、公开合同测试和生成绑定测试都显式构造新字段，避免默认值掩盖遗漏。

### 产品验收

1. HTTP 查询、实时事件和生成客户端类型均带有同一名单。
2. 设备页只在命中 `peerId` 的条目显示等待图标和说明。
3. 非阻塞离线设备不会显示等待状态；顶部统一提示不存在。
4. 设备上线并完成资料更新后，其条目状态随新摘要消失。

### 交付检查

实现后至少执行：

```bash
cargo metadata --locked --format-version 1
cargo check --workspace --all-targets --locked
cargo fmt --all -- --check
node scripts/architecture/check-engine-repository.mjs
git diff --check
```

设备、模拟器、发布产物和产品仓验证未执行时必须标记为“跳过”，不能标记为“通过”。
