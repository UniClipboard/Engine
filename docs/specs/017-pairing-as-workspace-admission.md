# 配对作为工作空间准入通道

## 状态

ADR-017 的职责收口已经实施：成员加入由 `WorkspaceConvergence` 完整负责，配对只是其内部
通信通道。本文关于 OpenRaft、learner、多数提交、最终成员配置和提交引用的条款已被 ADR-020
取代，待重写后才能作为实现或验收依据。当前加入成功只表示发起方与加入方已经保存并启用同一
新增事件；旧成员上线后可自动补齐，但不能越过尚未决定的移除。

## 概述

本文只定义工作空间准入：谁推进加入、配对可以传什么、何时产生正式成员资格、失败和重启后
由谁继续。成员事件、上线核对、移除决定和分叉关系由
[工作空间全局收敛](016-workspace-wide-convergence.md)统一负责；当前规则由
[ADR-020](../adr/020-membership-reconciliation-and-user-decisions.md)定义。

产品端仍只执行一次 `JoinSpace`。Engine 对这次操作只给出三类明确结果：

- **已激活**：加入方已经核对本机已提交并应用的最终成员配置、保存并启用目标安全状态，可以参与普通
  内容收发；
- **等待**：加入尝试已加密保存，可能正在等待排序记录或最终成员配置提交，也可能已经
  正式提交、正在等待交付或激活；两者都不是加入成功；
- **已拒绝**：邀请、身份、链头或候选无法接受，当前 Space 和安全状态保持不变。

配对握手完成、本机准备完成、发起方单机保存、网络发送成功或等待超时都不属于加入成功。
等待中的流程由 `WorkspaceConvergence` 跨重启继续，产品端不重排内部步骤，也不重复创建成员实例。

## 目标

- 成员加入、重新加入及其恢复由 `WorkspaceConvergence` 从一次请求负责到激活或稳定拒绝。
- 配对在正式提交前只交换邀请、秘密、身份、挑战和 KeyPackage 等公开准入材料。
- Welcome、内容密钥和目标 MasterKey 只在最终成员配置提交后，以绑定提交引用且只可由加入方
  解开的交付包发送。
- 待加入设备不属于上一份已提交成员集合，不能参与旧配置对自己的加入授权；新配置多数可以包含
  或不包含它，但它本机未提交并应用最终配置前不能激活。
- 发起设备中断后，其他旧成员可以继续同一候选和同一交付包，不能创建第二成员实例或另一份
  安全状态。
- 同一 Space 的链头比较先于历史备份、MasterKey 替换和成员清理；较旧状态立即拒绝。
- 配对会话和邀请不是成员资格依据；持久准入尝试、OpenRaft 排序记录、最终成员配置、提交引用和
  激活进度才是恢复依据。
- 配对会话消失后使用独立准入续接通道恢复同一尝试；新设备不需要也不能伪造历史成员恢复密钥。
- 不因 P2P 失败自动切换到 LAN。

## 范围

本文取代以下旧语义，不保留兼容入口：

- `JoinSpace` 以“本机已准备”作为成功结果；
- 发起方与加入方两台设备保存后即可形成正式成员资格；
- 配对在多数提交前传递 Welcome、内容密钥目录或目标 MasterKey；
- 加入前同步失败或固定超时后继续准入；
- 空间切换在比较同空间链头前先准备备份或替换安全状态。

本文不定义：

- 底层拨号、报文编解码和密码握手的具体实现；
- 工作空间提交后的完整收敛判定；
- 离线移除意图的合法性与合并规则；
- 不同 Space 之间如何正式退出来源 Space 和完成原子切换；
- 容忍已被完全控制且可任意使用当前成员签名密钥的设备；
- LAN 兼容线的行为。

## 术语

| 术语 | 含义 |
| --- | --- |
| 已提交链头 | 本机已验证并保存的最新正式成员状态，由空间沿革、连续序号、摘要和成员集合共同标识。 |
| 邀请基础链头 | 创建邀请时绑定的已提交链头。链头变化后邀请失效，不得自动改绑。 |
| 准入尝试 | 从一次已验证邀请形成的持久流程，绑定加入方、基础链头、候选和恢复进度。 |
| 准入续接凭据 | 首次配对建立并由双方加密保存的高熵凭据，绑定同一准入尝试、基础链头、加入方身份和 KeyPackage；只允许重新认证该尝试。 |
| 提交前材料 | 邀请、秘密证明、双方身份、挑战、能力和加入方 KeyPackage；不含 Welcome、内容密钥或目标 MasterKey。 |
| 候选核心摘要 | 在生成交付包前确定，绑定基础链头、成员操作、目标安全状态、加入方身份和 KeyPackage。 |
| 候选变化 | 从邀请基础链头出发、包含新成员实例、目标安全状态结果和交付包摘要的不可变变化。 |
| 提交引用 | 绑定空间沿革、OpenRaft `LogId`、候选摘要和最终成员配置摘要的稳定引用，必须指向加入方本机已提交并应用的事实。 |
| 提交后交付包 | 绑定基础链头、候选核心摘要、加入方身份和 KeyPackage，且只可由加入方解开的 Welcome 与目标安全材料；最终候选绑定其内层包摘要，排序日志保存旧 Space MasterKey 包裹的外层密文。 |
| 激活确认 | 加入方核对本机已提交并应用的最终成员配置和提交引用，保存交付包并一次性启用目标状态后返回的确认。 |
| 加入成功 | 加入方完成激活并具备普通内容权限；不表示所有既有成员都已恢复，后者仍由 `Complete` 表达。 |
| 配对会话 | 一次邀请验证期间的受限内存会话；不是持久事实，也不是成员资格。 |

| 产品端 | 提交一次加入、查询状态、订阅变化和展示结果。 | 不根据握手或网络状态推断成功，不重复驱动内部步骤。 |

删除检查：假设删除 `WorkspaceConvergence`，排序、成员配置、交付、激活和恢复会重新散落到配对、

## 对外入口与结果

| 入口 | 输入 | 结果 | 稳定拒绝 |
| --- | --- | --- | --- |
| `IssueInvitation` | 当前 Space | 返回绑定当前已提交链头的一次邀请。创建邀请不改变成员集合。 | 当前状态不可读、需要恢复或不允许创建邀请。 |
| `JoinSpace` | 邀请码、口令、可选设备名 | 返回“已激活”或带阶段的“等待”；等待包括提交前确认不足和提交后交付/激活未完成，后续由 Engine 自动继续。 | 邀请无效、口令不符、旧链头、同序号摘要冲突、身份冲突、候选已失效或协议不兼容。 |
| `QueryWorkspaceConvergence` | 无 | 同时返回 `membership_transition` 和 `workspace_completion`；提交前等待、激活和此前已提交变化的完成进度互不遮挡。 | 当前 Space 不可读或会话未就绪。 |
| `WorkspaceConvergenceChanged` | 订阅事件 | 与查询相同的完整状态。 | 不适用；消费者滞后后重新查询。 |

产品端只需要理解“已激活、等待、已拒绝”三种加入结果。`membership_transition` 的等待原因至少
区分 `AwaitingCommit` 和 `AwaitingActivation`；此前正式变化的完成情况始终由
`workspace_completion` 单独表达。脱敏计数可以随统一状态展示，但产品端不能选择确认设备、降低
数量或要求从内部步骤继续。

### 同一 Space 必须先判断链头

已配置设备执行 `JoinSpace` 时，Engine 在进入 Space Switch 前先比较空间沿革和已提交链头：

- 对端链头更旧：立即返回不可重试冲突，保留本机链头、成员、内容权限和当前 Space；
- 链头相同：返回幂等的“已经加入”，不生成新成员实例；
- 对端带有可验证的较新连续链：只执行追赶，不能进行历史迁移；
- 同一序号但摘要不同：进入 `RecoveryRequired`，不能任选一份状态。

真正加入不同 Space 时，目标准入仍按本文执行，但来源 Space 的正式退出不在本文范围内。等待目标
确认期间不得破坏来源 Space；在独立的跨空间决策完成前，不能把“目标加入”解释为“来源已退出”。

## 固定加入顺序

一次已有 Space 的加入只能按以下顺序推进：

1. **创建邀请**：绑定空间沿革、已提交序号和摘要；创建本身不产生候选或成员资格。
2. **验证加入方**：配对验证邀请、秘密、双方身份和能力，只取得加入方 KeyPackage 等提交前材料，
   并建立双方加密保存的准入续接凭据。
3. **登记 learner**：OpenRaft 为加入方建立不可关联到设备身份的共识节点编号并启动复制。
   `add_learner` 的成功或等待返回不证明完整追平或本机应用；负责人按目标日志位置保存并观察进度。
   业务日志和快照仍由旧 Space MasterKey 包裹，加入方不能解开。
4. **保存准入尝试**：负责人形成候选核心摘要，生成只可由加入方解开的内层交付包，再用旧 Space
   MasterKey 包裹外层。排序记录包含外层密文和摘要，绝不在正式提交前发送内层包。
5. **形成唯一顺序**：当前 leader 追加候选，旧配置多数复制后提交；随后 OpenRaft 提交包含加入方
   的联合配置和最终配置。新配置多数可以包含或不包含加入方；超时、离线和同步失败不降低任何
   配置的多数。
6. **正式提交**：排序记录、最终成员配置和提交引用加密保存后，正式成员链头才推进。
7. **交付并激活**：任一已跟上提交的保留旧成员解开外层密文，把提交引用和同一内层交付包发送给
   加入方；加入方核对本机状态机的成员配置位置等于目标最终 `LogId`、配置不是联合配置、投票成员
   集合与目标一致且 `last_applied` 已到达该位置，再验证候选、包摘要和包内绑定，保存并一次性启用
   目标状态，然后返回激活确认。
8. **返回成功**：只有加入方完成激活后，`JoinSpace` 才能报告成功。现有成员在收到激活确认前不向
   新成员发送普通内容。
9. **继续收敛**：负责人向其他当前成员交接同一正式变化，直到规格 016 的 `Complete`。

候选提交后不可因加入方离线而回滚。加入方重新可达时继续同一交付；若它永久失联，当前成员可以
从新链头提交移除该成员的新变化，不能复用旧链头另选后继。

## 消息职责

| 消息 | 允许承载 | 不得承载 |
| --- | --- | --- |
| 加入方请求 | 邀请码、加入方身份指纹、随机数、传输地址、安全能力、KeyPackage | 成员名单、空间内容、Welcome、目标密钥 |
| 发起方验证要约 | 空间沿革指纹、邀请基础链头、KDF 参数、挑战、会话标识 | 当前成员明细、内容、目标密钥 |
| 加入方证明 | 加密证明、KeyPackage 绑定和会话绑定 | Welcome、内容密钥、成员资格声明 |
| OpenRaft 排序 | 不可关联的共识节点编号、协议框架、旧 Space MasterKey 包裹的候选和双层加密交付包 | 设备身份映射、加入方可直接解开的目标安全材料、业务内容 |
| 准入续接 | 尝试标识、新鲜挑战和续接凭据证明 | 成员名单、历史恢复资料、目标密钥、业务内容 |
| 提交后交付 | 提交引用、最终候选、候选绑定且只可由加入方解开的 Welcome 和目标安全材料 | 无关成员资料、业务内容、未提交候选材料 |
| 激活确认 | 候选摘要、提交引用摘要、加入方已激活的签名确认 | 密钥、内容、其他成员状态 |
| 拒绝 | 稳定类别 | 成员名单、摘要原文、安全状态或区别性内部错误 |

配对只负责验证和传输，不解释 OpenRaft 提交结果。重复、乱序、跨空间、错误会话、错误链头或已关闭尝试的
消息一律拒绝，不产生持久化副作用。

## 会话与邀请生命周期

配对会话只存在于内存，绑定邀请、双方身份和一次准入尝试。连接中断或进程退出后会话消失；
恢复由持久准入尝试和独立准入续接通道继续，不能复活旧会话、进入要求共同历史 Transport 密钥的
工作空间恢复通道，或要求产品端重新拼步骤。

准入续接通道使用新鲜挑战验证加密保存的高熵续接凭据，并绑定尝试标识、空间沿革、基础链头、
加入方身份和 KeyPackage。加入方可以向可达旧成员重新证明同一尝试；候选已进入排序日志时，新
leader 必须从同一日志位置继续，尚未写入日志时只能从同一尝试形成候选。续接凭据不是成员资格，
不能读取成员名单、普通恢复资料、目标安全材料或业务内容；只有最终成员配置提交后，该通道才允许
返回提交引用和候选绑定的交付包。

邀请只存在于内存持有人中，一次只能由一个加入方赎回。过期、消费、取消或基础链头改变后立即
失效；不得自动改绑到新链头。外部渠道保留的邀请码只能发起一次新验证，不能恢复旧成员资格。

每个 Space 同时最多有一个尚未完成正式加入或清理的准入节点。失效尝试的清理由
`WorkspaceConvergence` 按已提交配置跨重启继续：纯 learner 才用 `RemoveNodes`；联合配置记录未提交
时先等待提交或截断；联合配置已提交时用 `change_membership(old_voters, false)` 收束回旧最终配置并
删除节点；新最终配置已提交时走普通成员移除。
清理完成前，其他已验证请求只能等待，不能登记新的 learner。

## 持久化与重启

以下业务负载必须经 MasterKey AEAD 加密保存；加入方在取得目标 MasterKey 前使用其本机受保护的
MasterKey 保存准入尝试，不能提前保存目标 MasterKey：

| 事实 | 保存方 | 保存边界 |
| --- | --- | --- |
| 准入尝试、身份和 KeyPackage 绑定 | 加入方与受理旧成员 | 验证后、参与后续流程前 |
| 准入续接凭据和接管记录 | 加入方与参与尝试的旧成员 | 初次配对完成前；排序提交或交付前 |
| OpenRaft 投票状态、排序日志、成员配置、快照、候选和双层加密交付包 | learner 与当前旧成员 | OpenRaft 回复和正式提交前；learner 用本机当前可用的受保护 MasterKey 再包裹不可解密业务密文 |
| 提交引用和正式链头 | 当前成员 | 宣布正式提交或开始交付前 |
| 已消费消息、交付和激活进度 | 双方 | 回复对应确认前 |

不保存邀请本体、会话消息原文、握手临时密钥或未验证的网络输入。日志不得记录这些内容。

| 中断时点 | 重启后行为 |
| --- | --- |
| 准入尝试保存前 | 会话消失，无成员资格和普通内容权限，可重新发起新尝试。 |
| 准入尝试已保存、尚未进入排序日志 | 通过准入续接通道继续同一基础链头和尝试；若链头已被其他候选推进，则稳定拒绝，不能改绑。 |
| 排序记录或联合配置已保存、最终配置未提交 | OpenRaft 重新选主；`WorkspaceConvergence` 从加密保存的同一目标再次调用 `change_membership` 完成最终配置，不能另建成员实例或另一候选。 |
| 最终配置和提交引用已提交并应用、加入方未激活 | 当前成员继续同一交付包；新成员资格不回滚，双方仍不交换普通内容。 |
| 加入方已经激活 | 重放同一激活结果并继续提交后收敛，不能再次切换密钥或创建成员。 |

## 失败与恢复

| 情形 | 必须行为 |
| --- | --- |
| 邀请无效、过期、已消费、已取消或基础链头变化 | 稳定拒绝；当前状态不变，不区分可枚举细节。 |
| 口令、身份、证明或 KeyPackage 无效 | 关闭会话；不创建候选，不保存成员资格。 |
| 本机同 Space 链头比邀请更新 | 立即返回不可重试冲突，不等待其他设备，不进入 Space Switch。 |
| 同一序号但摘要不同 | 进入 `RecoveryRequired`，停止自动成员变化。 |
| 对端提供可验证的较新连续链 | 先追赶；断档时等待资料或进入恢复，不能跳过。 |
| 当前 Space 没有 OpenRaft 创世记录 | 停止成员变化和新内容共享，保留本机历史并要求用户创建新 Space 沿革；不得本机初始化或回退旧协议。 |
| OpenRaft 暂时无法提交排序记录或成员配置 | 返回并保存对应“等待”；不上报成功、不降低多数、不自动切换 LAN。 |
| 候选输给同一链头的已提交后继 | 拒绝该尝试并按本机已提交配置清理：纯 learner 才用 `RemoveNodes`；已提交联合配置用 `change_membership(old_voters, false)` 收束并删除节点；新最终配置已提交则走正式成员移除。不能在新链头上静默重试。 |
| 原 leader 中断 | OpenRaft 重新选主；新 leader 从同一排序日志、成员配置和交付包继续。 |
| 提交后加入方离线 | 保持已提交状态，等待加入方恢复并激活；现有成员不向它发送普通内容。 |
| 配对会话在等待或提交后消失 | 使用准入续接通道重新认证同一尝试；不要求历史成员恢复密钥，不生成第二成员实例。 |
| P2P 传输失败 | 保留进度并等待恢复，不自动切换到 LAN。 |

## 安全与隐私

- 最终成员配置提交前，加入方捕获全部配对和 OpenRaft learner 流量也不能取得 Welcome、内容密钥、
  目标 MasterKey、成员身份映射或可解密候选。
- 提交后交付包必须绑定空间沿革、基础链头、候选核心摘要、加入方身份和 KeyPackage，最终候选
  必须承诺内层包摘要，提交引用指向该候选；两者不存在循环绑定，内层包只能由该加入方解开。
- 准入续接凭据必须高熵、每次尝试唯一、经 MasterKey AEAD 加密保存，并以新鲜挑战使用；它不能
  授予成员资格、目标安全材料或普通恢复资料。
- 正式成员在收到激活确认前不得向加入方发送普通内容；激活前旧连接也不能绕过该门。
- OpenRaft 投票状态、排序日志、成员配置、快照、共识节点映射、准入尝试、候选、签名、提交引用、
  交付包和进度在 SQLite、WAL、SHM、缓存与索引中保持密文。
- OpenRaft `NodeId` 随机生成，`Node` 使用空或完全不透明类型，不得使用携带地址的 `BasicNode`；
  真实映射只存在于已认证网络适配器的加密负载中。learner 可以看到成员数量、角色、任期和日志
  位置，但这些事实不能关联真实设备。生产环境关闭 OpenRaft 原始 tracing，不把第三方错误的
  `Display` 或 `Debug` 内容写入日志。
- 日志只记录脱敏流程标识、阶段、所需和已取得确认数、重试次数与稳定失败类别；不得记录设备名、
  设备标识原文、地址、邀请、签名、安全材料、密钥、文件名、路径或内容。
- 拒绝消息只返回稳定类别，不泄露成员名单、摘要原文、安全世代或内部失败详情。

## 删除并行责任

实施 ADR-020 时必须删除：

- `JoinSpace` 的“本机已准备即成功”结果和相关测试；
- 配对在多数提交前发送 Welcome、密钥目录或目标 MasterKey 的消息；
- 发起方单机保存成员变化并回送“准入变化已保存”即形成成员资格的路径；
- 加入前同步失败或二十秒超时后继续准入的路径；
- 配对持有或逐步调用 OpenRaft、正式保存、交付和恢复的公开接口；
- 自研投票、签名集合或与 OpenRaft 并行的成员决定记录；
- Space Switch 在同空间链头判断前准备备份、替换 MasterKey 或清理成员的路径；
- 旧协议回退、平行加入入口和产品端补偿重试。

删除后，调用方仍只提交一次加入并读取少量明确结果。内部实现可以包含选主、排序、接管和恢复，但这些
步骤不能成为产品端或 `uc-engine` 需要理解和排序的接口。

## 实施顺序

| 阶段 | 必须完成的工作 | 完成条件 |
| --- | --- | --- |
| 1. 固定失败证据 | 保留四设备旧发起者端到端红测。 | 测试证明 D 的链头更新，却仍被当前实现的旧 A 覆盖，并只在该行为上失败。 |
| 2. 收口持久事实 | 增加准入尝试、OpenRaft 加密日志/状态/快照、目标配置、候选、提交引用、双层加密交付、清理和激活进度；没有创世记录的旧 Space 要求新建沿革。 | 每个回复前先加密保存；故障注入后状态不倒退；旧设备不会各自初始化同一沿革。 |
| 3. 接入唯一决定 | 锁定 OpenRaft `0.9.25`，由 `WorkspaceConvergence` 通过私有接口驱动 learner、排序、联合成员配置和分段清理。 | 同一链头并发候选只有一个提交顺序；不以 `add_learner` 返回证明追平；联合配置中断后以同一目标完成；调用方无库内部步骤。 |
| 4. 拆分安全材料 | learner 和配对提交前只得到不可解密材料，最终配置提交后才传内层交付包。 | 抓取提交前全部流量得不到目标解密材料或成员身份映射。 |
| 5. 前置同空间判断 | 在 Space Switch 之前比较沿革、序号和摘要。 | 较旧同空间邀请无备份、换钥或名单副作用。 |
| 6. 接线状态与恢复 | 统一公开等待、激活、拒绝和提交后收敛状态。 | 重启、换发起者和离线恢复不要求产品重做步骤。 |
| 7. 删除旧路径并验收 | 删除旧成功、提前材料和超时继续路径，执行完整矩阵。 | 全仓搜索只剩新流程；未执行设备项明确标为“跳过”。 |

## 验收场景

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| P01 | 产品端只调用一次 `JoinSpace`。 | 内部完成验证、learner 追赶、排序、联合成员配置、交付和激活；产品只看到已激活、等待或拒绝。 |
| P02 | 加入方捕获最终成员配置提交前的全部配对和 OpenRaft learner 流量。 | 不含可解密的 Welcome、内容密钥、目标 MasterKey、候选或成员身份映射。 |
| P03 | B、C 是上一份已提交成员，D 请求加入。 | D 不参与旧配置授权；B、C 形成旧配置多数并提交包含 D 的联合/最终配置后才能正式加入。 |
| P04 | B、C、D 是上一份已提交成员，D 发起加入 E。 | D 加 B 或 D 加 C 可形成旧配置多数，不要求 B、C 都回来；新配置多数可以包含或不包含 E，但 E 本机提交并应用最终配置前不能激活。 |
| P05 | D 已有排除 A 的较新同 Space 状态，B、C 离线，旧 A 邀请 D。 | D 立即不可重试拒绝；摘要、成员、可接收状态和当前 Space 不变，A 从不出现。 |
| P06 | 全新设备经旧 A 尝试加入，当前多数暂不可达。 | 只进入等待且无目标安全材料；较新成员恢复后拒绝旧候选。 |
| P07 | 两成员 Space 中一台离线，另一台发起加入或正式移除。 | 只能等待；本机移除限制可立即生效，正式名单不变。 |
| P08 | 同一链头并发提出不同加入候选。 | 经乱序、重复、leader 中断和重新选主后，排序日志仍只有一个提交顺序。 |
| P09 | OpenRaft 在写投票状态、日志、联合配置或最终配置前后崩溃并重启。 | 加密持久状态不丢失或倒退，不会为同一日志位置提交两个结果。 |
| P10 | 候选提交后原 leader 崩溃。 | 新 leader 延续同一日志和配置；其他保留旧成员交付同一提交引用和包，不生成第二 Welcome 或成员实例。 |
| P11 | 提交后加入方离线并重启。 | 正式链头不回滚；恢复后只激活一次，激活前无普通内容。 |
| P11a | 配对会话消失，加入方没有任何历史 Transport 密钥。 | 以准入续接凭据恢复同一尝试；不能进入普通工作空间恢复或读取成员资料。 |
| P12 | 邀请创建后基础链头推进。 | 旧邀请失效，不能自动改绑或恢复旧权限。 |
| P13 | 已配置设备使用相同链头的同 Space 邀请。 | 幂等返回已经加入，不创建新成员，不进入迁移。 |
| P14 | 已配置设备从对端取得可验证的较新同 Space 连续链。 | 只追赶状态，不备份历史、不替换 MasterKey。 |
| P15 | 已配置设备加入不同 Space。 | 等待目标确认期间来源 Space 保持可用；正式退出来源 Space 留给独立决策。 |
| P16 | 删除 `WorkspaceConvergence` 的准入负责人。 | 测试应显示复杂度重新散落，证明不能把确认和恢复交给调用方编排。 |
| P17 | 扫描数据库、WAL、SHM、缓存、索引和日志。 | 无邀请、身份、候选、签名、密钥、地址、文件名、路径或内容明文。 |
| P18 | 在桌面、iOS、Android 和 HarmonyOS 查询结果与错误。 | 契约一致；未执行设备项标记“跳过”。 |
| P19 | learner 抓取本机数据库、WAL、SHM、快照与网络流量。 | 最终配置提交前只有不可解密业务密文和不可关联共识编号；没有设备身份映射或目标安全材料。 |
| P20 | 准入分别在纯 learner、联合配置未提交、联合配置已提交和最终配置已提交时取消并重启。 | 只对纯 learner 使用 `RemoveNodes`；已提交联合配置用 `change_membership(old_voters, false)` 收束并删除节点，正式成员走普通移除；清理前不登记下一 learner。 |
| P21 | 多台旧设备打开没有 OpenRaft 创世记录的同一 Space。 | 全部停止新共享并要求创建新 Space；不从各自本地名单初始化相同沿革。 |
| P22 | learner 检查 OpenRaft 成员配置、`Node` 元数据和生产日志。 | 只有随机不透明编号；无设备身份、地址映射或第三方原始 `Debug` 输出。 |

## 当前证据边界

ADR-017 的职责收口已经落地：配对不再是独立公开流程，成员保存和后续收敛由工作空间负责人
承担。该历史实现仍采用“加入方准备、发起方保存、回送确认”的旧成功边界，并在多数提交前传递
目标安全材料。

ADR-020 的修订尚未实施。新增四设备端到端红测已经证明：A 的同 Space 状态明确落后于 D，B、C
离线后，当前 Engine 仍让 D 通过旧 A 返回加入成功。OpenRaft 排序、持久接管、提交后材料交付和同空间
前置拒绝均不得描述为已经交付；旧 P01-P17 或 W01 的历史通过结果也不能作为本规格的新证据。
