# 移动端日志文件层与连接中继日志

## 状态

已采纳，待实现。

## 概览

移动绑定在系统日志（OSLog / logcat）之外叠加一层按天滚动的文件日志，写入宿主
cache 目录的 `logs/` 子目录。每次拨号或连接恢复后的连接刷新，核心会记录当前仍
在线且经中继连接的对端所最终选择的中继地址。

## 目标

- 移动端排障可直接读取宿主 cache 目录下的日志文件，不依赖系统日志采集通道。
- 文件层只接收 `info` 及以上级别，按天滚动，避免无限增长。
- 连接路径可观测：每次拨号或恢复后都能看到“这次连接最终选择的 relay”。
- 系统日志层（OSLog / logcat）保留原有行为，不因文件层改动。

## 非目标

- 不改变 Engine 日志事件内容、级别或既有脱敏规则。
- 不记录剪贴板内容、密码、密钥、完整令牌、文件名或文件路径。
- 不做日志压缩、保留期限、清理策略或上传采集；宿主的清理与采集方式自行决定。
- 不记录直连或离线对端的地址。

## 责任边界

| 范围 | 负责事项 |
| --- | --- |
| 移动绑定 | 启动时先解析宿主能力取得 `HostDirectories.logs()` 路径，再安装文件层；文件层 writer 的 worker guard 常驻进程生命周期，不得提前释放。 |
| 核心 | 连接刷新成功后查询对端快照，只对在线且经中继的对端输出中继连接日志；快照查询失败只写一条脱敏警告，不改变刷新结果。 |
| 宿主 | 提供 cache 目录；按需读取、清理或采集日志文件。 |

## 行为约定

### 文件层

- 日志目录为宿主 cache 目录下的 `logs/`，即 `HostDirectories.logs()`。
- 文件名按天滚动，格式为 `engine.2026-08-08.txt`（`engine.` 前缀 + 日期 + `.txt` 后缀）。
- 文件层只接收 `info` 及以上级别；系统日志层不加级别过滤。
- 安装顺序：先构造宿主能力取得日志路径，再安装系统层与文件层；日志目录创建失败时降级为仅系统层，不影响 Engine 启动。

### 中继连接日志

- 触发点：`refresh_peer_connections` 成功完成拨号或恢复之后。
- 输出条件：快照中 `connected` 为真、连接通道为 `Relay`，且存在连接地址。
- 字段：`device_id`（对端稳定标识）与 `relay_url`（本次连接最终选择的中继地址）。
- 中继地址是用户配置的连接端点，不包含访问令牌，与“记录实际使用中继路径”的隐私条款一致。
