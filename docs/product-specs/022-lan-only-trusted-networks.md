# PRD-022：仅局域网模式与可信网络

## 状态

草案。

## 背景

选择“仅局域网”的用户希望数据不经过公共基础设施。其中一部分人使用自建 VPN（如 WireGuard）连接设备，而不是让设备处于同一物理网络。

当前在这类网络里，设备无法发现、配对或连接：

- 仅局域网只用 mDNS 发现对端，而 mDNS 是链路本地组播，VPN 通常不转发。
- 短邀请码只是 mDNS 的查找键，本身不含连接信息，组播不通时无法解析。
- 已保存的对端直连地址在端口变化后失效，且没有可靠的更新渠道。
- “允许 overlay 地址”开关只放行 Tailscale 地址段，无法表达用户自己的网络。

来源：GitHub issue UniClipboard/UniClipboard#1750。

## 产品承诺

开启仅局域网后：

> 不使用公共发现和中继，设备之间只直接连接；在用户自己控制的 VPN 里同样可用。

这是“不经过公共基础设施”的承诺，不是网络隔离承诺：对端地址只能来自本机网络广播（mDNS）、邀请或已保存的地址，
其中能直接连通的地址都会被尝试。除永久排除的地址和未放行的 CGNAT/Tailscale 段外，不按网段限制直连。
遥测与更新检查不属于公共发现或中继，不受此开关约束。

2026-09-29 用户确认保留现有的排除式过滤，不改为只允许指定网段的白名单。“可信网段”因此只是放行规则，
不是隔离边界。

## 目标

- 用户能在自建 VPN 内完成配对、连接和日常同步，而不必关闭仅局域网。
- 组播不可用时，配对仍可完成。
- 一端重启后，在合理条件下无需人工干预即可恢复连接。
- 界面说明与实际行为一致，用户能清楚知道开关带来的保证和限制。

## 需求

### 可信网段（放行规则）

- 用可信网段列表取代“允许 overlay 地址”开关，不并存两套概念。
- 默认情况下，除永久排除的地址与 CGNAT/Tailscale 段外，其他地址（包括 `10.x` 等 WireGuard 常用私网地址）都可直连，无需配置。
- 可信网段只有一个作用：放行本来会被跳过的 CGNAT（`100.64.0.0/10`）与 Tailscale IPv6（`fd7a:115c:a1e0::/48`）段内地址。
  条目只接受私有地址空间，但落在其他私网段的条目不改变任何行为；它不限制其他可达地址，也不阻断任何流量。
- 用户以 CIDR 添加网段，并可一键加入本机当前 VPN 网卡所在网段。
- 拒绝公网网段和 `0.0.0.0/0`。
- 同一放行规则用于三处：地址发现结果、本端写入邀请的地址、出站拨号的对端地址。
- Clash fake-ip（198.18.0.0/15）与链路本地地址始终排除，不受用户配置影响。
- 修改后重启生效，界面明确提示，不假装实时生效。
- 迁移：旧开关为开的用户自动追加 Tailscale 的 `100.64.0.0/10` 与 `fd7a:115c:a1e0::/48`，行为不变；旧开关为关的用户无变化。

### 组播不可用时的配对

- 完整邀请（`ucspace1_` 前缀）自带发起端路由，加入方可直接使用，不依赖 mDNS 或云端解析。
- 发起端可选择把哪个本机地址（如 VPN 网卡地址）写入邀请。目前只有开发操作支持，产品使用前需要 Engine 新增公开操作；
  不选时邀请包含所有未被过滤的本机地址，通常已含 VPN 地址。
- 产品界面提供完整邀请的复制与粘贴入口。
- 仅局域网下，邀请的生成与解析不访问云端。

### 地址新鲜度与重启恢复

- 保存对端最近一次成功使用的私网直连地址（公网与 NAT 映射地址不保存），下次与 mDNS 结果同时尝试；该地址失效时不拖慢连接。
  2026-09-29 起默认模式同样保存。
- 固定端口是保存直连地址可靠的前提：随机端口重启后地址会变，本机端口修改后需重启，重启后本机主动连接各对端，对端由此更新本机地址。
- 地址双向学习：任一方的入站或出站连接成功后，双方都更新对端地址。
- 向用户开放固定监听端口设置。通过 VPN 使用仅局域网时，界面建议同时设置固定端口。
- 保存的地址属于敏感数据，按持久化规则加密存储。
- 仅局域网下，连接失败不得自动改用中继或公共发现，界面须说明失败原因。

### 说明文案

- 文案须与实际行为一致，不得暗示网络隔离，也不得写成“只连接可信网段”。建议文案：
  - 仅局域网：“不使用中继服务器和公共发现服务，设备之间只直接连接。可以通过局域网或你自己的 VPN 连接。
    这不是网络隔离：能直接连通的地址都会被尝试。遥测和更新检查不受影响。”
  - 可信网段：“默认会跳过 Tailscale 和运营商共享地址段（100.64.0.0/10、fd7a:115c:a1e0::/48）中的地址。
    如果你的设备通过这些网段互通，请在此添加。WireGuard 常用的 10.x 等其他私网地址无需添加。
    这里只会放行地址，不会限制其他地址的连接。修改后需重启生效。”
  - 界面名称宜体现放行含义（如“放行的 VPN 网段”），避免“可信网络”被理解为隔离边界；字段名 `trusted_networks` 暂不改。

## 非目标

- 严格的网络隔离或子网访问控制。可信网段只放行 CGNAT/Tailscale 段内地址，不限制其他可达地址，也不阻断任何流量。
- 让整个应用离线。
- 按设备手动填写对端地址。
- 通过中继、公共 DNS 或云端目录传递地址，即使作为兜底。
- 保证两端同时重启且都使用随机端口时自动恢复。该情形需要固定端口或用完整邀请重新配对。
- 可信网段实时热生效。

## 约束

- 日志、公开错误与观测事件不得包含地址、网段内容或邀请内容。
- 新增持久字段默认敏感，按密文保存。例外：可信网段列表与固定端口经用户批准明文保存在 settings.json（见 `docs/SECURITY.md`）；保存的对端地址仍须加密。
- 持久化格式变更遵守持久化格式演进规则，同一未发布功能分支只新增一个最终版本。
- 变更经由 `uc-engine` 稳定入口。iOS、Android、HarmonyOS 绑定目前没有任何设置读写操作，移动端设置界面需要 Engine 先新增绑定，尚未列入计划。

## 验收标准

- 两台设备仅通过 WireGuard（`10.x` 等非 CGNAT 私网地址）连通、组播不通时，开启仅局域网且不添加任何网段，能用完整邀请完成配对，并互相同步。
- 设备通过 CGNAT/Tailscale 段互通时，添加对应网段后同样可配对和同步；未添加时这些地址被跳过。
- 已配对设备在单端重启后，固定端口下自动恢复；随机端口下，重启端主动连接后双方恢复。
- 整个过程中不产生对中继、公共 DNS 或云 rendezvous 的访问。
- 添加公网网段或 `0.0.0.0/0` 被拒绝并给出明确原因。
- Clash fake-ip 与链路本地地址不会出现在邀请或拨号候选中，即使落在用户配置的网段内。
- 从旧版本升级后，旧开关为开的用户行为不变；旧开关为关的用户无变化。
- 连接失败时不发生降级，且界面给出可理解的失败原因。
- 保存的地址不以明文出现在数据库、日志或观测事件中。
- 界面说明文案与上述行为一致。

## 未决问题

- Desktop 与移动端的具体入口和布局，由各产品仓在跨仓任务中设计。
- 完整邀请在仅局域网下不携带中继提示：已确认并以测试固定（本端关闭中继时路由不含 relay）。
- 本端地址列表的选择在移动端的交互形式。
