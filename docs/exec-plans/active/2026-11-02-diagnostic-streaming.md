# 诊断持续文件流实施与验收

状态：实现与短场景验收完成；长时间主机验收待结算。完整实现、集成、验证和交付负责人：Engineer。

## 行为所有权

Engine 观测运行时拥有白名单、运行身份、编码槽、队列、分段、淘汰、计数与关闭。
Desktop 归档模块拥有在线准备、离线读取、有限前缀、ZIP、完整性清单与目标原子替换。
调用方只执行导出诊断包。成功返回归档结果；失败保留原目标，不修改源文件。
正常关闭停止采样，SDK 收尾后排空文件队列并关闭文件。突然退出丢失排队记录及未结束 span；无法保存的计数未知。
重启建立新运行身份，保留旧文件身份。无历史重放，无密钥依赖，无密文恢复或自动删除。

## 最终文件合同

`diagnostics/engine/<run_id>/run.json` 与 `lease.lock`；三个单信号文件族
`logs.<YYYYMMDD>.<sequence>.jsonl`、`metrics.<YYYYMMDD>.<sequence>.jsonl`、`traces.<YYYYMMDD>.<sequence>.jsonl`。
格式版本 1；日志行沿用本地版本 2，Metrics/Traces 每行一个上游 OTLP 请求。
run.json 只含版本、运行身份、启动时间、构建来源与预算。运行身份由文件运行时唯一生成。
Logs 不双写 OTLP。仅经过现有类型化过滤的记录允许明文。旧密文不读取、不导出、不删除。
单段 4 MiB；单运行三类信号合计 16 MiB；根目录目标 100 MB，保留 7 天。
根目录仅回收非活动运行；多个活动进程及清理失败允许超出目标，不能宣称全局硬上限。
队列 8 条，每条含换行最多 64 KiB；只有一个非阻塞编码槽；编码使用限制长度的 Write。
队列负载最多 512 KiB，writer 与编码槽各最多 64 KiB；不等同于堆或 RSS 上限。
导出从打开的句柄获取截止长度，逐完整行读取，跳过残行和超限行；记录缺失、读取失败、截短和无效行。
哈希、字节和记录数对应实际 ZIP 输出。清单声明其他进程未刷新及突然退出计数未知。

## 失败矩阵（实施前）

- 编码槽忙、编码超限、队列满：立即拒绝并分类计数；业务线程不等待磁盘。
- 慢盘：队列固定；生产端丢弃；刷新受期限约束。
- 磁盘满、权限拒绝：记录写失败，沿用有界退避；不重放失败记录。
- 部分写入：丢弃当前文件句柄，后续创建新分段，残行不导出。
- writer panic：关闭队列，标记不可用，报告已接收但未完成的记录。
- flush 超时：报告超时；不能伪报成功。
- 清理失败：保留源文件，报告失败，不扩展内存。
- 轮转删除竞争、截短、残行、坏行、权限失败：归档清单分别记录。
- ZIP 写失败：删除本次临时文件，保留既有目标。
- 不逐条 fsync；已写入不保证断电零丢失。
