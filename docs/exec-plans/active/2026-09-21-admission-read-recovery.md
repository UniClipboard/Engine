# 升级后准入读取受限恢复

状态：受限恢复入口与分类已实施，自动资料修复及 Desktop/CLI 展示待下游交接。来源：t-0031 的隔离复现和 issue #1713；不把合成损坏认定为用户现场根因。

## 负责人和结果

- Space Admission 的恢复模块拥有完整的资料核验与恢复决定；Infra 返回带来源的失败与可证明的分类，Engine 只保留受限运行期并公开稳定结果。
- 调用方仅启动 Engine 并查询恢复状态；健康资料照常启动。无法核验时停止所有准入、成员维护和同步，只允许安全的状态查询与诊断导出。
- 每次装配业务会话前由 Space Admission 通过专用核验端口完整核验一次，常规恢复读取保持轻量；启动后恢复前台或重建会话时发现的失败同样转入受限实例。锁定、存储暂不可用与并发变化保持可重试，不进入受限恢复。
- 受限会话跨启动重新校验同一资料；不删除、忽略或重写权威记录，不把重试当修复。已有升级游标保持完成。现有旧格式迁移及摘要缺失时补建的写入行为仍沿用既有路径，不属于本轮可安全承诺的资料修复。

## 分类与动作

区分凭据缺失、认证不匹配、当前格式外壳或元数据解码、旧格式回退解码、旧格式迁移失败、记录或指针不完整、派生摘要损坏、代次不一致及其他存储故障。只有可证实的原因使用精确类别；无法区分密钥不匹配和密文篡改时合并为认证不匹配。对外仅输出类别、阶段、处理方向和允许动作，不输出原始失败文本或资料内容。

备份优先，且仅在隔离副本上核验后原子切换。摘要只在权威记录与身份、签名全部可验证时定向重建；元数据必须能唯一重建才允许自动处理。缺失凭据使用已有受支持的口令恢复；有完整旧备份且匹配凭据时可从副本重新升级。权威事实或密钥不可恢复时拒绝自动处理，交给用户明确选择可信备份、导出诊断或确认重建本机资料。未经证明的恢复动作不在本轮伪装为成功。

## 验收

1. 现有 `bad-meta` 复制资料先红灯；Engine 三次启动受限且可查询类别，成员维护与同步均未运行。Desktop 旧二进制不能证明新接口的 CLI 展示，须下游接入后再补真实后台对照。
2. 只通过准入仓库公开读取、Engine 恢复状态及真实后台/CLI 边界增加分类测试，逐项红绿，不从实现复制预期。
3. 同一资料三次启动类别稳定，升级游标及业务密文不变；健康 0.19.1 和 alpha.10 对照继续通过。
4. 定向测试、全量测试、workspace check、格式、架构、隐私及差异检查；任何未通过项写入报告，不得记为通过。

未验证 Windows 或移动实体设备；Desktop 展示与操作只做接口交接，本 thread 不改 Desktop。
