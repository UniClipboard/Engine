# 接收拒绝原因与单向同步调查

状态：本机诊断修复与定向验证已完成；现场根因与同步修复尚未完成，手机当前不可用。

## 责任与完成标准

- Application 接收负责人执行策略检查、解密和保存，调用方只交付一条接收任务并等待原有保存回执。
- Infra 协议负责人按回执回复；失败、没有消费者、回执丢失和超时均不得回复保存成功。
- 固定的本地详情沿不透明在线观测上下文交接，不扩大 Engine 接口，不改变协议和远程摘要。
- 重试与重启恢复保留既有完整流程所有权；诊断信息不持久化业务状态，也不触发重试。
- 首个切片用真实本机协议、回执和实际日志文件证明普通模式可解释拒收，再扩展接收策略、解密与保存原因。
- 补齐安全状态缺失、乱序、重复与恢复验证；只修复已证实的业务问题。
- 本机验证与手机验证分开。用户当前无法提供手机，真机双向、后台和重启验收记为跳过。

## 验证进度

- 现有解密失败后继续接收测试通过；不证明现场解密失败。
- 接收关键路径与故障手机所用版本一致。
- 真实本机协议与普通、详细模式实际文件已证明：无消费者、回执丢弃和处理超时均明确拒收并保存各自原因；超时使用可控时钟验证原有 60 秒等待，不改变生产等待时间。
- 接收队列与回执测试覆盖策略、成员查询、解密、内容格式和保存权限失败，原因随原任务返回，不新增业务事件。
- 已修复查询与保存错误来源被字符串化的问题；保存失败仍撤回已发布文件，禁止伪报成功。
- 接收相关 Application 测试 408 项通过；缺钥与代次不符的真实加解密测试通过。
- 根目录要求的 metadata、全工作区全目标编译、格式、Rust 风格、架构与隐私检查、差异检查已通过。HarmonyOS 原有公开入口测试有未使用导入警告，未改动该测试。
- 两端真实安全状态与加解密测试重现单向成功、前序更新缺失、乱序拒绝、重复幂等及补齐后双向恢复。此测试人工按序补齐缺失更新，不证明自动分发或进程重启恢复已修复。

## 已确认与未确认

确认的代码问题是接收诊断丢失具体原因，以及查询和保存错误转换丢失原始来源。二者均有先失败后通过的测试。
故障手机是否缺少内容密钥仍未知。测试证明该条件能产生交接中的现象，不把可解释现象等同于现场根因。
没有修改安全更新校验、成员接收策略、重试分发或用户资料，也没有清空资料、重置空间或重新加入。
