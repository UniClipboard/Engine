## 1. 概述（Overview）

文件／blob 当前直接使用原生 Endpoint 与 SDK Downloader 的连接池。Application 虽有
`BlobTransferFacade`，但尚未统一承担底层任务停止、有限调度和实际结算：取消按对端执行
`shutdown_endpoint`，可牵连共用连接的其他下载；取消入口还先等待反向通知，才触发本地停止。
单纯套一层 port 不会改变这些行为。

本片把真实下载和提供服务接入独立的 Uni 连接管理能力，由 Application transfer 模块统一负责
下载调度、重试、取消及结算，并补齐独立文件部分失败后的用户单项重试。已有文件夹完整发布、
加密与资料兼容合同保持。工作范围包含这些已确认的行为，不能按纯连接替换估算或验收。

## 2. 目标（Goals）

- 共用真实连接的独立任务 A、B 中取消 A，B 不被中断、失败或被迫重试，且最终内容精确一致。
- 对端离线或反向通知永久阻塞时，本地仍开始停止；实际停止、所需结算及资源归还后才报告取消成功。
- 真实 blob 下载与提供服务都经过 Uni；SDK 不再另拨连接，不留原生旁路生产实现。
- 全局／每对端有限并发、有限排队、公平启动和明确期限可由可控时钟与真实网络分别验证。
- 仅明确可恢复的网络错误自动重试，预算不因重连重置；没有可靠分类的错误不自动重试。
- 独立文件逐项保留成功结果，失败项可手动重试；文件夹成功前不交付残缺目录。
- 保持旧版文件互通、现有 ticket、blob 字节和持久格式；大文件保留流式处理与有界内存。

## 3. 非目标（Non-Goals）

- 不实现跨进程自动恢复、持久重试队列或跨重启可靠通知；不承诺断点续传。
- 不要求新增同内容下载去重；已有共享行为必须满足本规格的等待者隔离。
- 不在本片实现第八片新版进度协议、终态 ACK、终态补发或完整发送侧状态投影。
- 不改变文件夹发布事务、文件集身份、成员历史、配对规则或 LAN 显式选择合同。
- 不发布产品页面，也不让宿主编排核心重试步骤；需要的稳定业务操作及薄绑定属于本片。

`124780fb69768b8506565b2760c435182f9e2d20`。下载端 `Remote::execute_get` 接受

## 5. 设计（Proposed Design）

### 5.1 组件与完整负责人

**完整负责人为 Application `transfer` 模块。** 模块内部按以下知识拆分，`mod.rs` 只声明和导出：

- `transfer/receive/` 承担一次接收／重试的完整调度及结果聚合，复用现有 attempt 和产物结算；
  接收主流程只提交完整意图、取得物化结果，再继续既有保存动作，不逐文件拼接网络步骤。
- `transfer/blob/transport/` 为计划新增的模块，持有独立 blob Uni manager，负责实际交换、
  服务端准入、流级取消及受监督的 SDK 工作；只接受完整获取或提供请求。
- SDK 字节流、BAO、store 导入导出和 tag 操作留在 Infra。Application 专属 port 定义在
  消费模块附近；Application／Core 不出现 Iroh 或 iroh-blobs 类型。
- `transfer/file/` 继续承担会话事实与事件，receive 流程决定何时结算；原超时扫描不能与新负责人竞争宣布终态。
- Engine 仅构造 manager、adapter、完整能力及稳定操作映射；Router 一次交接完整入站连接。

调用方唯一动作：正常接收提交一次接收计划；手动重试提交条目、预期旧尝试及所选项；取消提交
具体尝试／任务。重试、排队、网络重连、校验、输出和清理均由同一个 transfer 模块完成。

### 5.2 数据模型与权威

| 模型 | 字段及生命周期 |
| --- | --- |
| 接收尝试 | 复用条目、当前 attempt 与提交 CAS；手动重试创建新 attempt，自动网络重试保持同一 attempt |
| 接收项 | 条目、attempt、现有清单中的稳定项位置／item_id、来源设备、预期内容身份、必要获取材料、输出所有权 |
| 调度项 | 内存状态 Queued／Running／Recovering／Cancelling／Settling／Terminal，单调时钟、累计次数及恢复耗时；不新增持久枚举 |
| 共享获取 | 仅在现有 SDK 共享或经证明需要时使用；以来源及内容能力区分，持有等待者集合，每位等待者独立输出及结算 |
| 结果 | 单项成功、明确失败、已取消；批次按所有有效项汇总，不能由最后一项代替全批结果 |

用户路径和文件名不能充当任务身份或日志字段。重复文件行即使内容相同，也保留独立项身份。
单项获取标识不能继续仅使用整条记录 ID，否则同一记录的多文件会覆盖在途注册。

队列只持有必要元数据与获取材料，不预读整个文件。容量检查与入队原子完成；满额立即返回繁忙。
不持久化连接、调度队列、重试预算或通知队列。复用既有加密清单／接收材料；普通同进程重试必须
能够重建原始文件集合与身份，不得把失败占位文本重新当成来源文件。

### 5.3 下载预算与调度

以下为用户已确认默认值，均须通过实现验收；不是性能实测结论：

| 项目 | 数值 | 计数／计时边界 |
| --- | --- | --- |
| 活跃下载 | 全局 4，每对端 2 | 包括当前获取、恢复等待及尚未结算的本地工作；结算前不能虚放额度 |
| 等待队列 | 全局 64，每对端 16 | 仅未取得活跃许可的逻辑请求；不含已经运行的任务，不另藏无界 waiter |
| 排队 | 60 秒 | 从接受入队起，取消、重复等待及重新排队不得刷新 |
| 首批数据 | 60 秒 | 获得活跃许可后开始，覆盖准备、准入、拨号和首次有效数据；不是从回调注册才计时 |
| 数据停滞 | 300 秒 | 从上次有效新增且通过对应校验的数据起；重复字节、重复回调及 keepalive 不续期 |
| 取消调用等待 | 5 秒 | 从接受取消意图起，覆盖本次等待；超时返回尚未完成，原任务继续受监督收尾 |
| 获取尝试 | 含首次共 4 次 | 每个用户发起的接收项累计；共享获取不因增加等待者重置当前网络轮预算 |
| 退避 | 200、800、2000 毫秒 | 分别用于第 2、3、4 次尝试前；取消和会话关闭可打断 |
| 故障恢复 | 累计 30 秒 | 覆盖故障后的重拨、退避和恢复等待；有效数据再次到达后暂停累计，累计值不清零 |

多个期限同时适用时取最早者。例如故障后的重拨不能再获得独立 60 秒，从而绕过剩余恢复预算。
正常持续下载不受固定总时长限制；校验／输出不能靠进度回调伪装为持续网络接收。
首次 60 秒或停滞 300 秒耗尽即按相应超时结算，不在该期限外再追加重试。
原 pending 60 秒扫描不得从入队时同时覆盖排队和首批数据两个阶段；运行期由本负责人按内存阶段
计算到期，既有 sweep 仅触发同一负责人的核验与结算。不得以伪造数据进度刷新活动时间来规避旧扫描。

同一对端内部按接受顺序；有名额时在可启动对端间轮转，不抢占运行中的下载。
过载、排队超时均不触发新的业务自动重试。自动恢复期间仍持原活跃许可，以避免恢复任务
重新入队产生隐形队列、预算重置和对其他请求的超额启动。

未新增共享去重时，一个逻辑接收项对应一份下载许可。已有物理共享时，实际获取只占一份
活跃许可，额外等待者仍必须受同一全局／每端等待额度约束；最后一位退出并结算前不归还实际获取许可。

### 5.4 Uni、SDK 与提供端

独立 blob manager 共享现有 Endpoint 和权威身份目录，不复用 presence、普通剪贴板、成员历史
或第八片进度 manager。blob 连接使用既有 ALPN 与原始字节，不增加自定义业务协议头。

优先通过通用流桥接 SDK 的 `GetStreamPair`／`provider::StreamPair`。必要的流 ID、finish、
stop、reset 能力以传输无关的通用能力补充 Uni，由 Infra 映射 SDK trait；不得为取得原生连接
向 Application 暴露 downcast 或 Endpoint。每个流的丢弃／取消只终止该交换。
固定 SDK 高层获取在网络错误时丢弃私有 import 完成等待，实施采用同一 SDK 的公开
`get::fsm`／`ImportBaoHandle` 驱动接收，并用 `provider::StreamPair` 读取既有请求、
SDK export 字节流驱动提供；错误或取消后仍等待本次 import／排空本次 export 至通道关闭。
协议解析、BAO 校验和编码继续归 SDK，不复制一套线上格式。SDK 原有 provider 事件追踪仍不启用，
业务进度仍归现有 Application 通知能力。Uni 的 I/O 与本地工作许可可拆分持有，后者保留连接、活动和额度至实际结算。

SDK 的 future、其启动的工作及导出都必须有明确完成等待方；若公开 API 无法保证停止并 join，
阶段 0 即失败，不能用关闭整条连接或仅丢弃进度流冒充成功。

本片提供端也必须有界，采用独立于本地下载的资源池，避免两端互相下载时互锁。设计默认
服务交换全局 4／每端 2，未识别入站准入全局 16／识别后每端 2，准入及请求头整体 60 秒；
满额仅拒绝本次新交换。以上是技术资源策略，实施阶段 0 须确认旧端在该界限内正常互通。
禁止 SDK provider 在外部再次无界 spawn。连接仅按受管请求需要保留，无工作时采用 30 秒空闲回收；
不因连接空闲规则终止活跃流，本片不维护类似 presence 的永久在线连接。
每个已授权对端每方向至多一条连接，建立中和退出未完成也占对应名额；未知身份的临时入站另受
全局 16 限制，不保留第二套原生连接缓存。不能只限制 SDK 交换数而放任空连接无限积累。

旧下载器先开空预热连接，再由 SDK 池获取。提供端因此在首 QUIC 流出现后才识别并做成员准入：
空预热仍是受全局 16 限制的未绑定候选，无流时按 30 秒回收，不占已授权方向名额。
首流只由 Uni 暂存，不解析自定义头；准入与 SDK 原请求头继续使用同一个入口起算的 60 秒截止时间。
空闲保留集合容量为 16，满时允许淘汰无工作连接以接纳新对端；该缓存容量不作为服务任务总数门槛。
连接监督继续持原 Uni 租约到实际工作及结果交接结束，不与未知候选、下载队列或 4／2 服务交换池共用额度。

所有服务请求都须核对当前成员与当前会话代次，认证身份不能代替授权。成员移除、切 Space、
锁定或关闭使旧授权失效，停止相关交换；重新加入不复活旧任务。旧 ticket 不授予撤销后的权限。
核对既有普通成员、历史旧端与受管身份映射；不能修改 ticket 格式或配对规则来绕过准入问题。

### 5.5 取消、竞争与生命周期

1. 原子记录本次取消意图，封住后续排队启动、重试和结果发布；先触发本地停止。
2. 排队项直接退出队列；运行项只停止自身流和 SDK 工作。共享项只注销该等待者，最后一位退出才停止共享获取。
3. 反向通知使用有界、非阻塞交接，按任务合并中间进度；网络写、拨号或通知失败均不进入取消关键等待。
4. 等待已启动的不可安全中断本地工作完成，处理属于本次的输出、临时文件、tag、引用及事件结算。
5. 自身停止且结算成功后报告取消成功；取消项不再发布成功或继续写自身输出。

超过 5 秒只结束调用等待，返回尚未完成；负责人、实际任务及许可继续存在。重复取消接入同一次收尾，
不能因注册项被先移除而返回已经成功。真实清理失败保留 source，返回明确失败／未完成；不按连接已消失吞掉所有停止错误。

复用现有提交 CAS：取消先取得权威则禁止提交；提交已经取得不可撤销边界时返回 TooLate 或实际终态，
不能承诺撤回已发布输出。相同任务只结算一次，旧尝试不能改变新尝试。调用方丢弃等待 future 也不放弃已接受的停止责任。

退出、暂停、锁定、切 Space、离组、成员撤销及删除走同一负责人的封口与停止路径；先封口，通知所有任务停止，
再收集结果，不能等待第一个慢任务后才通知其余任务。关闭超时保持原关闭状态和清理监督，不能假报资源全释放。
删除不留下任务在后台重建记录；已归用户所有的最终文件按既有所有权规则保留，不能为取消随意删除。

重启先运行现有 readiness／reconciliation：终结旧非终态尝试为中断的业务失败，清理受管 staging、
恢复未结算发布，之后才放行新任务。复用现有失败分类映射“中断”，不新增持久状态字符串。
不从旧队列或旧 attempt 自动恢复网络下载，不因旧恢复记录删除已交付的成功文件。

### 5.6 重试与部分成功

自动重试白名单只包含有具体来源证明的暂态网络错误。磁盘满、权限拒绝、校验／解密失败、
无效 ticket、明确来源不存在、访问被拒绝及未知错误直接结算。不能把宽泛 `Unavailable` 全部视为网络抖动。
相同失败保留原始 source chain，公开边界只返回稳定分类。
若失败事实或清理责任的本地结算写入本身失败，原接收负责人仍持有原许可和内容保护，向调用方返回实际错误并继续修复本地结算；不重新下载或重新保存业务内容。保存失败且本次输出的物理清理也失败时，同一负责人先完成该清理再交接失败事实；同进程确认清理成功后，后续存储重试不再删除相同路径。修复以 1／2／4／8／16／30 秒间隔退避，最长间隔 30 秒，不建立持久重试队列。取消或关闭的等待期限不终止已开始的本地结算；只有权威尝试、失败事实及清理责任真正结算后才能释放资源。

不承诺断点续传。可安全复用且仍通过内容校验的已获取数据可以保留；不能复用时重新拉取，
重复数据不刷新“有效新增数据”时间。界面进度按该项已验证的唯一内容范围计算，不把重复传输
累计成超过 100%；确需从头获取时允许如实说明重试，不能为了数字不倒退而宣称输出仍可用。
这不改变第八片“迟到消息不得导致倒退”的约束。

独立文件逐项结算：每个成功项在持有原下载许可期间完成持久保存，随后归还许可；保留全局 4／每端 2 的预算，不积累整批许可等待统一保存。失败不取消其他项；批次未结束时显示仍在接收，结束后按全部项的结果汇总。已经保存的成功项不因后续项失败、取消或重启而回滚，也不因重试其他项再次下载。保存条目、逐项交付事实与清理日志中该项的责任移交必须原子提交，不能让恢复清理删除已交付文件。
有失败且有成功为部分失败，无成功则显示实际失败／取消；最后一个成功不能覆盖前面的失败。
所需引用、输出及提交失败不能报告完成，完成不包含系统剪贴板应用或用户打开。

文件夹沿用目录完整组装与发布。任何成员失败都不把残缺目录作为成功结果交付；保留现有回滚和
产物日志恢复，回滚本身失败须如实记录残留，不能宣称跨多个根存在文件系统单事务。
文件夹重试整个原始接收单元，不在本片新增目录内部单文件修补。

手动重试允许选择失败／已取消的独立文件；文件夹选择整个原始接收单元。成功项不重新下载。
对同一条目使用预期旧 attempt 的 CAS 新建尝试；重复点击只得到同一在途结果或 AlreadyReceiving，
不叠加下载。同一条目一次只有一个权威接收尝试，本次选中项作为一个重试集合；另一次不同集合不能在其运行时覆盖它。
原任务仍在清理时明确返回 CancellationIncomplete，等待完成后才允许创建新尝试。

重新发起前重新检查当前成员资格、源材料、预期内容身份及目标所有权；来源删除或 ticket 不可用时返回
SourceUnavailable／AccessDenied 等固定原因，不改为下载来源端当前另一份内容，不自动要求源端重新发布。
重启后可以由用户重新发起，但只有仍能从既有材料完整重建的来源才可开始；材料不可恢复时明确不可用。
保持持久格式是本片前提，不能为保存重试 recipe 新增明文或新 schema。

### 5.7 API / Interface

以下是拟新增／修改的业务契约，实施时统一迁移内部消费者；不是当前已存在的接口：

| 接口 | 输入 | 结果与错误 |
| --- | --- | --- |
| Application 接收计划入口 | 既有 ReceiveWorkPlan、当前尝试和所选原始项 | 完整物化／部分结果；内部完成调度、获取、输出和逐项结算 |
| `RetryEntryReceive` | `entry_id`、`expected_attempt_id`、`item_ids` | 新 attempt 已接受、AlreadyReceiving、Superseded、CancellationIncomplete、Unavailable；参数为空或不是允许重试项则 InvalidInput |
| 既有接收查询的逐项业务结果 | 条目标识 | 返回项 ID、独立文件／目录单元、当前状态与固定失败原因，供宿主选择；不返回 ticket、原始路径或密钥 |
| `CancelEntryReceive`／`CancelInboundTransfer` | 既有条目尝试或具体传输标识 | 保留原有明确结果，并表达 CancellationIncomplete；不得将等待超时映射成 Cancelled／NotInflight |
| Application 专属 blob 交换能力 | 已准入的通用流租约、ticket 解析后的内容请求、取消上下文 | 一次获取／提供交换的真实结果；typed source 与停止完成可等待 |

item_id 使用既有清单／产物的稳定项身份并绑定旧 attempt，不使用文件名或路径。若现有逐项查询无法提供，
在既有接收查询结果中增加业务必要的项集合，不新增观测专用查询。Engine 不返回内部调度状态对象。
稳定入口位于 `uc-engine`，UniFFI／N-API 同版本映射完整动作；宿主不接触 Application/Core。
接收查询的聚合计数沿用成员粒度，目录的 `items` 集合仍为整个目录单元。已完成项数与字节使用业务保存事实，不能仅以底层网络 Completed 为依据；原始计划中的未启动成员也须包含在总量中。

### 5.8 第八片边界、兼容与观测

本片必须解决本地通知背压，否则离线取消合同无法成立。中间进度按任务保存最新值并有界交接；
最终结果交给现有通知能力，不承诺本片实现可靠送达。仍保留现有最多 5Hz 的正常进度报告上限。
不得为了避开通知而偷偷丢掉现有正常互通，也不能提前发 Completed 让旧端误认成功。

新版进度的独立尝试标识、跨设备投影、迟到消息、结果未确认及有限补发由第八片负责；终态 ACK 尚未确认。
第七片本地单项重试不得依赖第八片已经发布，当前旧协议的远端投影不作为新版尝试隔离已通过的证据。

保留 blob ALPN、ticket、BAO／字节语义、加密格式、tag 和旧资料可读性，不新增 schema。
业务授权采用当前权威，不因兼容给已撤销成员放行。若旧版在固定角色下无法遵守现有安全合同，
保留真实失败并作为前置阻塞，不能以禁用授权换取兼容通过。

观测遵循[业务记录组织标准](../../design-docs/observability.md#业务记录组织标准)：手动重新接收是完整业务动作，
其排队、网络轮次和清理是子工作；正常 GC／空扫描不生成业务入口。Application 持不透明关联，
Engine 只装饰完整能力，不新增阶段读取。错误保留 source，日志只用固定分类与 `uc_*!`，
不得输出文件名、路径、ticket、设备身份、摘要或错误正文来拼接任务。

### 5.9 工作流（Workflow）

1. 接收入口校验当前会话、原始清单与接收权威；完整计划一次交给 transfer 模块。
2. 接收项原子申请活跃／排队名额，明确返回已接受、繁忙或已有任务。
3. 公平调度获得名额后开始首批数据期限；通过 Uni 准入与开流，由 SDK 通用流能力处理 blob 字节。
4. 按唯一有效数据更新停滞时钟，非阻塞交接进度；网络失败进入同一负责人的有限恢复。
5. 对获取内容按适用路径校验、解密和输出，完成引用与产物结算；部分项失败不终止其他独立项。
6. 目录按原完整发布路径结算；接收主流程依既有规则保存记录及决定系统剪贴板后续动作。
7. 取消或关闭随时进入同一停止路径；用户手动重试只在旧尝试结算后创建新尝试。

## 6. 实施步骤（Implementation Plan）

详细阶段、命令及退出条件只维护于[执行计划](2026-10-21-blob-connectivity-plan.md)，顺序为：

1. 冻结协议／旧端，证明 SDK 双向接缝、任务停止和原始项重试材料；失败即停止生产迁移。
2. 落地纯规则、精确计时、公平调度及 Application 专属 port，不另写第二套连接池。
3. 迁移真实获取与提供服务，统一取消、错误分类、停止监督和生命周期。
4. 接通独立文件部分失败、完整目录发布、手动重试与同版本绑定。
5. 删除旧连接／SDK 自拨旁路，执行真实矩阵、资源／隐私验收与必需 CI。

## 7. 边界情况（Edge Cases）

| Scenario | Expected behavior / Implementation |
| --- | --- |
| 零字节文件、空目录 | 无数据回调也可由已验证的合法结束完成；不误判停滞，保留原目录语义 |
| 重复行、同名文件 | 项身份不同；复用已有安全命名／拒绝覆盖能力，不按名称合并 |
| 队列满、慢对端 | 原子拒绝或按已接受期限退出；其他对端仍可公平启动 |
| 取消与提交同时到达 | 以既有 CAS 为准，仅一个权威结果；TooLate 不伪装成成功取消 |
| 通知阻塞、对端离线 | 下载与本地取消独立；反向通知有界，不拖住数据回调 |
| 本地写盘不能立即停 | 5 秒调用返回未完成，工作仍受监督并占用许可；清理结束前不重试 |
| 撤销／切会话后迟到完成 | 旧授权及旧 attempt 不发布结果，不复活已删除记录 |
| 校验损坏、存储错误 | 不进入网络自动重试；不输出错误正文；保留 source 与产物事实 |
| 来源材料丢失／旧票据不可用 | 手动重试明确失败，不取另一份当前内容替代 |
| 旧端及极端帧 | 保留协议向量及有界解析；畸形请求仅拒绝本交换，未授权不发送业务内容 |
| 回滚／引用提交失败 | 如实保留未结算／失败，不发送完成或伪报清理成功 |

## 8. 测试策略（Testing Strategy）

### Unit Test

- 可控时钟驱动 4／2、64／16、60／60／300／5／30 秒及 4 次尝试边界，验证恰好到期、重复等待不续期。
- 多对端排队、取消、重复点击和队列满同时发生；验证公平启动、原子额度及关闭后不启动。
- 注入具体网络／磁盘／校验／授权 source，断言重试白名单和错误链；未知来源不重试。
- 共享两个等待者，分别取消第一位及最后一位，验证自身结算与物理任务停止责任。
- 批次各位置失败、最后一项成功、失败集合重试、目录成员失败及回滚失败，验证准确汇总。

### Integration Test

- 两个真实 blob 流共用一条连接：取消 A，B 不失败、不重试、精确读回；观察实际开流与尝试次数。
- 用永久阻塞 reporter、真实本地慢写和已离线对端验证停止先发生、5 秒未完成、最终 join 与额度归还。
- 通过真实 SQLite／加密资料执行部分失败、单项重试、重复点击、取消提交竞争及强杀重启清理。
- 至少 1GiB 文件流式收发，采集峰值内存和 tag／临时产物；不得分配与文件大小成比例的整文件缓冲。
- 新新、冻结开工 main、受支持历史锚点各自真实资料：新版主动获取／新版提供两角色 × Direct／强制 Relay。
  先验证旧旧资料基线；路径、实际 ALPN、字节读回和身份不变有证据，旧库不打补丁。
- 成员撤销、锁定、切 Space、删除和 shutdown 后检查任务、流、连接、FD、许可及未完成产物。

### Regression Test

- blob 内存路径、文件路径、目录完整发布、引用／GC、保存目录所有权、搜索与资料升级相关测试。
- 前六片连接功能、成员 E2E、现有升级 smoke、全部 workspace；P2P 不自动切 LAN。
- 同版本桌面与移动绑定编译和业务结果映射；真实设备未执行明确记为跳过。
- 真实 Engine 流程的完成／部分失败／取消／通知失败记录及隐私输出；只查模拟日志不替代真实验收。

## 9. 验收标准（Acceptance Criteria）

* [ ] 阶段 0 的双向 SDK／Uni 与任务停止证明通过，原始项手动重试无需新增持久格式可运行。
* [x] 共用连接取消 A 不影响 B，B 无被迫重试且内容正确；实际完整 Application／Uni／SDK 的 Direct 重复验收见[执行计划](2026-10-21-blob-connectivity-plan.md#2026-10-22-同连接双流取消硬验收)。
* [ ] 反向通知失败或永久阻塞不阻止离线本地取消；此项为硬验收。
* [ ] 取消成功仅在实际结算后返回，5 秒超时明确未完成，重复调用及调用方取消不遗弃清理。
* [ ] 共享等待者、提交竞争、各生命周期和重启清理符合 §5.5，无旧任务迟到发布。
* [ ] 所有数量／时间／次数边界及跨对端公平性通过，无隐形无界队列或伪释放。
* [ ] 暂态网络错误有限重试，永久失败不重试，重连／重复字节不刷新预算或活动证据。
* [ ] 独立文件部分成功与失败项手动重试通过，成功项不重传；文件夹不交付残缺目录。
* [ ] 只有数据校验、适用解密、所需输出和业务提交成功才报告完成。
* [ ] 真实收发全部经过独立 Uni 管理；旧 Downloader 自拨、对端级取消和旧生产 handler 已删除。
* [ ] 原协议、ticket、加密／持久格式、旧新双角色 Direct／Relay 及大文件资源边界通过。
* [ ] 业务接口及薄绑定一致，错误链和隐私验收通过，未为观测增加内部步骤接口。
* [ ] 本地必需门禁、网络矩阵及当前 head 的必需 CI 通过；设备跳过项明确，证据可定位。

## 10. 风险与取舍（Risks and Trade-offs）

- SDK 通用流接口不等于任务可取消、可等待；若阶段 0 失败，不能以关闭对端连接满足形式上的取消。
- 原始单项重试需要准确来源材料，保持旧持久格式可能限制重启后的可恢复材料；必须如实返回不可用，
  且同进程正常失败后的单项重试是必过能力，不能把所有请求都降级为不可用来通过。
- 公平调度和每端 2 的上限可能使单一对端不能用满全局 4，选择隔离与可预测资源，而非最大吞吐。
- 恢复中保留活跃许可避免超额和重排队，代价是暂时降低吞吐；累计 30 秒限制故障占用。
- 目录完整发布意味着不能只补一个目录成员；保留现有事务和文件集身份，避免本片引入目录修补协议。
- 具体默认值经过用户确认但尚未实测；不适配真实正常场景时保留失败证据并修改本规格，不通过放宽测试伪造成功。
- 未授权旧 ticket 的行为须按当前安全合同拒绝，不能以旧版互通为由降低授权。

## 11. 未决问题（Open Questions）

第七片产品行为与默认预算已定；以下为实施前置技术证明，不是默认已完成的工作：

1. 固定 SDK 的接收／提供端通用流、reset／stop 与后台工作 join 能否满足完整任务停止？
2. 现有加密材料能否准确重建失败项的来源、项身份与原始预期内容，而不新增持久格式？
3. 原始旧端资料及当前成员授权下，双角色旧新互通是否满足本片协议／身份边界？

阶段 0 对任何一项给出失败或无法证明时，计划进入设计阻塞，不进入生产迁移。替代 SDK、blob 协议、
新持久格式均超出已定范围，须先提出明确取舍。第八片终态 ACK 仍未获用户确认，不在本片补作决定。
