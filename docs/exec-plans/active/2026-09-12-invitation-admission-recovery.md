# 历史可读时的邀请失败

状态：根因修复、Engine 与本机 Desktop 后台验证完成；纳入 v1.1.0-rc.15 发布准备，远端发布结果以实际工作流及发布清单为准。

## 责任与结果

Application 的成员维护流程负责继续完成移除，调用方只请求生成邀请。Infra 的撤销仓储只在前一次本地安全变更尚未激活时排斥另一移除；已激活、仍待远端确认的记录保留原有消息和重试责任，不阻止后续本地安全变更。邀请资格检查保持不变，不跳过未完成的本地安全效果。

## 证据与验收

- 当前固定版本的本地资料副本已复现：禁止自动解锁恢复返回未解锁，但实际会话可用且历史可读；邀请返回成员关系尚未确认。
- 延长运行后确认原始原因：前一次撤销尚未得到全部远端确认，仓储返回固定的“另一项移除仍在进行中”，后一次移除因此停在成员事实已应用、安全效果未应用的阶段。仅取消 peer 关系门禁仍失败，此尝试已撤回。
- 同一份隔离资料副本修改前失败、修改后通过三次启动；关闭自动解锁两次、允许自动恢复一次，历史非空且邀请可生成。此资料已有可恢复会话，不据此宣称验证了输入密码的手动解锁路径。
- 仓储回归先失败后通过；21 项仓储测试通过，覆盖重启后保留远端待确认记录及消息，并允许后续本地移除。
- 新增端到端测试通过：B 离线时 A 连续生成并取消三次邀请，再邀请独立实例 C 加入；B 返回后成员关系补齐，A 到 B、B 到 C 均实际发送并接收成功。
- 新增端到端测试通过：B/C/D 离线时 A 先后移除 C/D，每次均可继续生成邀请；A 重启后仍可邀请，B 返回并接受移除后补齐变化，A 到 B 实际发送并接收成功。
- 这两项测试不等于同一设备反复移除再加入的覆盖，也不等于被移除设备返回时的验收。
- 邀请错误分类测试、完整工作区编译检查、格式与差异检查、仓库与 Rust 规则检查通过。
- Desktop 的邀请错误映射及其测试已更新；独立资料副本实际启动桌面后台两次，每次历史非空且邀请生成成功，未改原资料和设置。验证使用 Desktop 已有的本地 Engine 覆盖配置；固定依赖版本尚未正式升级，发布采用须在修复提交后另行固定版本。
- 独立实例加入和收发由 Engine 端到端测试验证；Desktop 界面点击、手机及其他平台、手动密码解锁跳过。
