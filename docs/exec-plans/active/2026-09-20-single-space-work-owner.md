# 单一空间工作负责人：配对与正式成员维护互斥

## 状态与完整责任

- **状态**：实现和自动验证完成；实体设备验收待单独授权。
- **日期**：2026-09-20。
- **依据**：t-0010 的待确认加入与正式提交修复、t-0025 的最终确认重试被普通维护延后约 9.5 秒的真实双端记录。
- **完整负责人**：Application 的单一空间工作模块负责配对与普通成员维护的运行资格、串行边界、重新唤醒、结果及重启恢复；配对协议和成员历史仍分别拥有自己的规则与持久事实。
- **调用方唯一动作**：宿主只发出“可能有变化”的唤醒，并查询稳定状态；认证消息交给同一负责人路由，不要求调用方理解最终确认、让路、队列合并或维护步骤。
- **成功结果**：配对终结后，邀请方在唯一确认点一次正式提交新成员；随后普通维护传播正式历史。加入方可恢复同一个加入编号并在收到完成回复后使用新空间。
- **失败结果**：暂时失败保留配对与下次重试时间；稳定拒绝、取消和安全超时保留明确终态；无法证明提交或安全恢复时进入 `NeedsAttention`，包含稳定原因与可执行的恢复动作。
- **重启与重试责任**：同一个 Application 负责人从既有加密配对记录和正式成员 ledger 恢复运行资格；运行期只实现唤醒与生命周期，不保存第二份模式事实。

# 1. Overview

目前普通成员维护把配对恢复当作首个步骤，随后根据 `Continue/Yield` 决定是否执行成员效果、群组更新和历史同步。设备联系另有直接执行历史同步的路径；入站成员历史处理又独立于后台维护。加入方首次最终确认连接暂时失败时，配对恢复返回“本次没有立即工作”，同一轮仍进入两个各约 4.5 秒的网络步骤，延后下一次确认约 9.5 秒。仅在失败分支增加让路条件无法覆盖其他触发和入站写入。

本计划把“当前空间只允许哪一种控制工作”收归一个负责人。未终结配对只运行配对恢复；配对安全终结后才运行普通成员维护。候选资料留在配对记录或私有暂存区，不能进入正式成员历史。已有正式成员内容传输默认仍使用已提交的安全资料，不将待确认设备授权为内容对端。

# 2. Goals

- 任何未终结的本机配对存在时，普通成员效果、受限投递、冲突恢复、群组更新、历史同步和投影清理的后台入口均不执行；入站成员历史不写入正式 ledger。
- 最终确认第一次连接失败后，不发起群组更新或历史同步网络连接；到保存的时间直接重试配对。
- 邀请方只有在验证最终确认的唯一提交点才写正式成员与安全资料；正式提交前第三台设备看不到候选。
- 邀请方已经提交而回复丢失、双方分别重启、重复消息和重复申请仍收敛成一个正式成员。
- 从同一份既有加密配对记录推导运行资格，重启后恢复同一加入编号、阶段和下一次尝试；不增加持久的 `Joining/Active` 开关。
- 配对结果与普通成员历史收敛健康分别可查询；后者持续失败时报告稳定原因、下次重试和恢复方式，不无限显示“更新空间”。
- 配对完成后一次完整普通维护能补上期间合并的触发，普通加入、切换、移除、重加和已有异常成员清理继续通过。

# 3. Non-Goals

- 不修改或清理真实 Android、Windows、Linux 资料；实体设备须另行授权。
- 不按离线状态自动删除设备、不放宽邀请或成员身份确认、不从历史直接去重或任意选择凭据。
- 不把连接、内容传输或所有运行生命周期合并进空间成员维护。
- 不新增第二套配对状态、第二套正式成员事实或产品侧持久加入编号。
- 不为保留旧调度结构而永久保留 `Continue/Yield` 兼容层。
- 本阶段不改变 P2P 默认能力，也不自动切换 LAN 兼容线。

# 5. Proposed Design

## Components

- **SpaceWorkOwner（Application 内部）**：在同一串行边界内读取配对与正式成员事实，裁决后台工作和认证成员消息的运行资格。输入为无业务含义的唤醒或认证消息；输出为稳定状态/回复及内部下一次唤醒时间。它不重新实现签名历史或网络通信。
- **Admission recovery（保留、收口）**：推进配对状态，持久保存请求/回复证据与重试期限。只返回自己的等待、完成、稳定失败或需要处理，不再知道普通维护。
- **Ordinary member maintainer（保留、收口）**：只针对正式历史运行既有效果、群组更新、反熵与清理。它不读取候选或配对阶段。
- **Runtime adapter（精简）**：合并唤醒、暂停、恢复与关闭；不判定 `Pairing/Active`，不解释协议步骤。配对终结后立即安排一次完整普通维护扫描，避免暂停期间丢弃工作。

删除 SpaceWorkOwner 后，运行资格、串行竞争、重试时间、入站门禁和状态投影会重新散落到调度器、准入恢复、历史处理与 Engine，这才是该模块存在的理由；若新对象仅转发旧用例，不满足本规格。

## Data Model

- `Pairing`：至少一个本机未终结的有效准入义务。加入方保存 `CompleteAck` 但仍等待 `Settled` 时也属于此类；不能把内部 `Terminal::Active` 直接当成“配对已完成”。
- `Active`：没有未终结配对，普通维护可运行。邀请方完成正式提交后，即使 `Settled` 回复丢失，也可以进入此类，并保留终态回复重放。
- `NeedsAttention`：持久记录损坏、来源无法验证或无法证明正式提交与安全回退；必须带稳定原因、明确恢复动作及可用时的下一次重试时间。
- 正式成员仍由 `VersionedMembershipHistory` 与 `MembershipLedger` 唯一决定；候选资料和待发消息由既有加密准入记录或私有暂存保存。
- 若新增持久重试字段，先盘点当前受支持格式，在本功能分支只形成一个最终目标格式，旧记录有明确读取/升级或需处理结果；所有字段默认使用既有 MasterKey AEAD。

## API / Interface

宿主生命周期适配器只唤醒 `wake()`，产品只查询 `status()`。发起加入的开始/查询/取消仍走稳定 SpaceFacade，认证 admission 与 membership 消息交给同一负责人路由。它的内部结果只包含“当前状态、下一次唤醒”和脱敏失败分类；不给调用方返回 `CompleteAck`、`Settled`、普通维护步骤或队列指令。

入站成员历史在 `Pairing` 中返回固定可重试结果，不解析/写入 ledger；已有正式成员的正常内容传输不经过此门禁。业务门禁结果不伪造下层异常；真实网络/存储错误必须保留 source chain。Iroh framing 使用独立 BUSY 状态：新版明确延期，旧版按未知传输状态延期，均不会误作成功或永久拒绝。

## Workflow

```text
普通状态 Active
  └─ 经认证且版本兼容的配对请求 → 持久 Pairing
       ├─ 临时失败 → 保存 next_retry_at，仅配对恢复有资格
       ├─ 明确拒绝/取消/确认前安全超时 → 稳定终态 → Active
       ├─ 邀请方验证 CompleteAck → 唯一正式提交 + 保存可重放 Settled → Active
       └─ 加入方验证并保存 Settled → 本地配对完成 → Active
            └─ 运行一次完整普通成员维护；向第三方传播正式历史
无法证明提交或恢复 → NeedsAttention（明确原因与恢复动作）
```

每次唤醒先从持久记录确定一种运行资格。开始配对与普通维护选路必须经过同一串行边界：已经开始的完整维护动作可先完成，新申请排队后才持久进入 `Pairing`；一旦进入 `Pairing`，不得再启动普通维护。入站消息使用相同裁决，不能从独立端点越过它。

配对协议完成、正式成员成立、历史收敛、产品传输四者不是同一个时点：邀请方在最终确认处将前两者合并为一次提交；加入方在保存 `Settled` 后完成配对和本地可用；第三方历史收敛是之后的普通维护，其失败不能反写配对结果。已有正式成员在配对期间默认继续按原已提交安全状态传输；新成员和未收敛的第三方按原安全范围暂停。

# 7. Edge Cases

| Scenario | Expected behavior | Implementation |
| --- | --- | --- |
| 无 Space 或无配对记录 | 不创建模式事实；只执行适用的原正常维护或返回当前无空间状态 | 从仓库派生，不存布尔开关 |
| 正常维护与新配对同时到达 | 完整已开始动作结束后才接受配对；配对写入后不再开始普通动作 | 统一串行边界与持久提交校验 |
| 最终确认请求丢失 | 加入方保持 Pairing，按保存时间重发相同请求 | 加密记录保存精确消息与退避 |
| 完成回复丢失 | 邀请方已正式提交并重放相同回复，加入方继续 Pairing 直到收到 | 幂等提交与终态回复缓存 |
| 任何一方先重启、重复消息 | 恢复同一加入编号和动作；不重复创建成员 | 持久聚合和消息证据 |
| 确认前超时 | 稳定失败、不创建正式成员；迟到确认稳定拒绝 | 截止先于网络工作，保留旧异常记录的显式处理 |
| 完成已提交后超时 | 邀请方仍为 Active，重复确认仅重放回复 | 正式提交结果优先于超时 |
| 多个旧身份 | 不静默重写历史；用户确认移除时沿用全部旧身份安全撤销 | 正式成员 ledger 原有移除路径 |
| 候选或状态记录损坏 | NeedsAttention，拒绝邀请和成员变更，保留原事实 | 分类并保留错误来源，不清空资料 |
| 旧版对端 | 正式写入前稳定拒绝并提示升级 | 协议能力检查，旧异常状态显式恢复 |
| 已有正式成员继续传输 | 使用已提交的原安全范围，候选不能参与 | 内容授权不从候选推导；验证远端移除延迟取舍 |

# 8. Testing Strategy

## Unit Test

- 输入持久记录包含待发最终确认且网络首次失败；唤醒后断言仅配对工作开始，群组更新和历史同步网络 recorder 均为零。
- 输入 `Pairing/Active/NeedsAttention` 的已有记录与损坏记录；查询对外状态、重试时间及恢复动作，重启后相同。
- 输入重复唤醒和两个并发开始请求；断言一次完整动作和一个活动配对，不产生第二身份。

## Integration Test

- 经空间负责人公开维护入口依次执行启动、恢复、周期、状态变化、上线和联系；每种 Pairing 阶段普通维护所有端口零调用，成功终态后执行完整正常维护。
- 经认证入站历史端点发送有效成员历史；Pairing 时稳定可重试且正式 ledger 不变，Active 后正常处理并确认；不同网络消息类别与旧端兼容结果有测试。
- 三设备邀请方、加入方和既有第三方：最终确认前第三方不见候选、不接候选历史；确认后只见一次。双方分别在每个持久阶段重启，丢失请求和回复分别收敛。
- 配对期间既有正式成员内容双向传输继续，候选无内容权限；历史同步持续失败单独显示等待/重试/需处理，恢复后收敛。

## Regression Test

- 普通首次加入、已有空间切换、正常移除及重新加入、同设备不同凭据、已有异常历史的安全移除和全部旧身份清理。
- 普通历史同步、群组更新、成员效果、安全范围、会话暂停/恢复/关闭、旧版配对拒绝和双向内容传输。
- 先跑定向测试和 `cargo check`；完成后运行相关完整套件、workspace check、fmt、Rust 风格、架构仓库、隐私以及 `git diff --check`。失败项区分本次回归与已存在基线。

# 10. Risks and Trade-offs

- 成员控制面暂停会延迟本机得知远端移除，最长受配对期限约束。默认保留已有正式成员内容传输，但必须通过安全验收确认延迟可以接受；否则配对期间连内容也暂停，不能假装移除即时生效。
- 单纯后台门禁不能阻止入站历史写入；两者必须共用一个裁决边界。
- 当前未确认成员可能进入历史同步选择范围；迁移候选资料时不可改写已存在正式历史，需保留旧异常记录的处理路径。
- 新版截止规则可能与旧版迟到确认不同，必须在正式写入前协商协议能力并在稳定设计中写明。
- 并行维护两份历史头能减少暂停，却引入冲突、双运行器和资源争用；独立 `Joining/Active` 开关则引入第二份真相，均不采用。

# 11. Open Questions

- 已有正式成员间内容传输在本机最多约五分钟未获远端移除更新时，产品安全要求是否允许继续？当前推荐继续；若安全评估证实不可接受，改为明确暂停内容并更新验收。
- 现有入站成员历史协议是否已有旧端可识别且稳定可重试的回复类型？第一条入站红灯测试应验证；没有时须在正式写入前确定兼容能力与失败编码，不伪造成功 ACK。
- 普通历史同步健康的现有持久事实能否给出稳定的下次尝试时间与可执行恢复动作？若不能，先建立稳定 Engine 契约和测试，将完整产品展示列为后续阶段，不宣称旧无限提示已修复。

## 实体设备验收计划（待用户单独授权）

Windows 邀请方、Android 加入方和已在线第三设备使用同一可追溯 Engine 修订。分别核对构建、安装、真实启动；阻断第一次最终确认连接与完成回复、双方分别重启，验证没有普通维护插队且只形成一个成员；正式提交前第三设备看不到候选，之后才能看到并双向传输。配对期间验证已有正式成员的内容传输，另外阻断历史同步验证清晰失败与恢复。最终以两端历史、安全成员集合和实际内容传输验收，不以“在线”代替。旧版混用只验证稳定升级结果，不在真实空间清理资料。

## Phase 9–12 配对失败双端收敛证据

- 多个待确认候选现在分别可查，已有正式设备继续可用；候选安全终结后仍保留最小失败投影，但不进入正式设备列表，也不补造已经清理的设备资料。

- 最终确认仍是邀请方正式成员的唯一提交点。提交后的成功结果越过期限仍只重放，不能回滚；成员只能再由用户明确移除。
- 旧记录按持久证据分为三类：未提交者原地收尾，已提交者保留成功，证据不足者保留原资料并公开 `NeedsAttention`。该状态带固定原因、明确处理方向和空重试时间，不伪装自动恢复。
