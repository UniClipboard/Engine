# 移动 LAN 入站激活所有权

状态：待验收与下游接入。修复实现与本地 LAN 验收已完成；基线 416fcca，验收修复来源 c235ae2b；既有契约断言修正后的 cead274a 已复跑原生 LAN 12 场景。

交付：[Engine #177](https://github.com/UniClipboard/Engine/pull/177) 待审查与合并；[Desktop #1961](https://github.com/UniClipboard/UniClipboard/pull/1961) 为依赖草稿，尚未更新正式 Engine 固定来源。

完整负责人是移动兼容层的 ApplyIncomingMobileClipUseCase。调用方只提交文档；共享入站管线负责存储和系统剪贴板写入，兼容层在成功后负责本地登记及状态传播。P2P 入站仍由共享入站管线登记发送者激活。

基线真实 Desktop daemon 的 LAN PUT→SSE→GET 验收中，新内容、A→B→A 与同内容再次激活都产生两次登记推进。共享管线先使用 mobile_sync 来源身份登记，兼容层随后使用本机身份和新时间登记。两个订阅者各收到两条，产生 19 次 GET，预期 11 次。

修复：入站请求明确选择登记负责人；共享登记辅助方法统一处理所有权。移动兼容层已装配本地激活公告时，由公告负责唯一登记；未装配时保留入站登记。已有内容的系统写入使用 RemotePush 自回声抑制，因为兼容层已经负责内容与状态的传播，不能再由 watcher 创建第二次激活。

验收目标：一次成功落地对应一次登记和通知；失败、取消、未完成文件不创建额外本地激活。重试与重启沿用既有入站和生命周期机制，不增加持久状态或协议字段。

## 已完成验收

- 真实隔离 daemon 的 LAN PUT→两个 SSE 订阅者→GET 文档闭环：每次激活从两条通知降为一条，总 GET 从 19 降为 11。覆盖新内容、连续不同内容、A→B→A、同内容再次激活、初始 hello 和重连。
- 私有命名 NSPasteboard 上的真实 macOS watcher：原生文字、文件、图片与实际 B→历史恢复 A 各一条通知，基线和修复版一致。LAN 文字、同内容重激活、文件及图片入站均从两条降为一条。文件字节精确回读，文档 contentId 与事件一致。
- 既有 P2P admission 后互传验收通过：配对、接收端重启、发送文字及持久化文字精确回读。宿主剪贴板使用测试替身，Engine、存储与 Iroh 为真实实现。
- Workspace/all-targets、格式、Rust 风格、仓库结构与差异检查通过。生产剪贴板及应用未改动，隔离资源已回收。

原 CI run 38137456396 的单项失败是已装配公告的 resurface 用例仍要求 LocalRestore，实际路径使用 RemotePush。cead274a 只调整该既有用例名称、说明与断言，仍要求一次写入、一次公告，没有新增单元测试。关联入站 28 项与原生 LAN 回放通过。

后续 run 38139104876 的 LAN 用例通过，但 UniFFI 生命周期公开契约在并发关闭阶段返回 AlreadyStopped。首个调用方设置 pending 后尚未取得发送者，另一个关闭等待者提前释放生命周期通道；最小修正为在既有生命周期通道锁内同时确认关闭请求所有者和克隆发送者，保留等待前释放通道触发最终收尾的原有行为，以及超时、重试与 worker 错误结果。修正后公开契约 30 项、既有 shutdown 6 项和 worker_join 4 项及格式/结构检查通过；远端 CI 尚待闭环。该关闭问题与 LAN 双登记根因分别记录。

## 范围和归档条件
