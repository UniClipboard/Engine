# 后台暂停安全

状态：已修复已复现的租约与取消完成缺口，完整后台安全验收尚未完成。

后续实施以[统一暂停、恢复与中断恢复规格](2026-09-12-unified-runtime-lifecycle.md)为准；本文件保留已完成局部修复与验证证据。

## 完整责任

Engine 生命周期负责人统一拥有暂停、恢复和最终关闭。宿主只调用暂停或恢复，不维护内部资源清理列表。
暂停成功必须意味着停止接受工作、旧工作退出且交接所需文件锁已释放；恢复重新读取持久状态后才接受工作。
失败不能发布暂停成功；重试与恢复由同一生命周期负责人串行处理。最终关闭不可恢复，暂停必须可恢复。

## 最小切片与后续范围

1. 真实 Engine 创建 Space、保存内容、暂停后由独立文件描述符验证锁释放，恢复后验证内容读取与再次暂停。
2. 检查旧操作、后台自动重建、取消与停止超时，禁止暂停后重新占用资源。
3. 核对所有停止工作的共同预算和平台绑定等待语义，不能用停止等待代替完成收尾。
4. 执行相关回归、workspace 检查、格式及架构检查。

## 已有证据

- 交接程序在本机重复得到暂停后锁不可获取、最终关闭后可获取，退出码 101。
- 当前提交与交接源码检查提交一致；该独立程序链接的是已有产物，尚不能代替当前源码重新构建验证。
- 暂停仅停止 session，最终关闭另行永久关闭安全状态；操作等待两次超时后仍返回成功。
- 自动网络恢复有独立生命周期，需继续核查暂停期间的重建入口。

## 已实现

- SessionSupervisor 持有暂停边界，暂停后拒绝网络重建，停止 session 后交接安全资源。
- Clipboard 进程级 blob 物化与 spool 清理共用活动许可；暂停等待当前完整磁盘动作退出，阻止排队动作继续，恢复保留原队列。
- Vault 等待当前读写完成后撤销复用与缓存，暂停期间拒绝新读写；恢复先重新取得文件租约，失败继续保持暂停。
- 完全关闭仍不可恢复，暂停恢复不复用旧安全缓存。
- Engine 取消调用后保留真实在途登记，暂停等待其退出；操作门超时返回失败，之后可重试停止。
- TaskRegistry 和传输超时工作者取消后等待任务退出；资源未析构不能当作关闭完成。
- 取消传输失败后的重试仍执行取消，不因 session 已被取走而跳过。

## 2026-10-03 成员记录读取阻塞移动运行线程

- UniFFI 的密钥读取阻塞验收暴露了两个边界：零期限暂停返回只证明通知入队，不能立即放行密钥；成员维护的异步仓储入口直接执行同步事务，首次解密触发宿主密钥读取后会阻塞单线程运行期。
- `SqliteMembershipRecordStore` 在内部阻塞线程执行异步读取、提交与暂存的完整同步事务，沿用当前 tracing 上下文并保留任务失败来源。成员维护及生命周期负责人继续等待完整结果；不拆开事务，不改变重试、持久化格式或宿主接口。
- 公开契约统一阻塞该密钥的并发读取，防止后台维护抢走唯一阻塞机会；放行密钥前通过同一生命周期通道的查询确认暂停已转交 Engine，仍要求旧恢复返回 `InvalidState`，随后完整暂停、恢复、业务查询与并发关闭成功。临时调度延迟仅用于诊断，不进入产品实现。

## 2026-10-04 准入读取与恢复事务阻塞移动运行线程

- TestFlight 后台终止（`RUNNINGBOARD 0xdead10cc`）现场栈位于成员记录读取。同一后台生命周期中，`SqliteSpaceAdmissionState`
  的当前加入与展示状态读取，以及成员维护轮次调用的准入恢复状态读取与提交（`verify_readable`、`load`、`commit`、
  `commit_sponsor_deadline`、`commit_sponsor_abandonment`）仍在异步入口直接执行同步事务；三个提交在即时写事务内逐条解密、
  加密并写回。
- 以上入口统一经仓储内部的阻塞执行入口，在同一阻塞闭包内完成整个同步访问，不拆开连接或事务；调用方等待完整结果，
  暂停仍等事务提交或回滚。阻塞线程沿用当前本地工作观测上下文（span、延续、维护轮次、配对工作），嵌套的仓储读写记录不丢失。
  不改变持久化格式、重试、错误分类或宿主接口。
- 验证（隔离副本注入写事务及读取闸门，不进入产品）：真实双 Engine 配对，加入方运行于与移动绑定同构的单线程运行期。
  修改前写事务在运行线程持有写锁，生命周期查询与暂停在闸门释放前均无响应；修改后运行期持续响应，暂停在写锁持有期间
  不报告成功，正常预算在事务结束后完成暂停并释放写锁与内容文件租约。观测上下文另以对照实验确认：不携带上下文时嵌套记录丢失。
- 预算耗尽（2026-10-04 后续修改，见统一规格同日记录）：期限只结束宿主等待，已接受暂停在事务结束后自行完成本地资源交接；
  在途工作超过系统后台时间时的锁持有仍是剩余风险。以下为修改前的实测：
- 预算耗尽仍是未解决的实际风险：调用方期限到达后转换保持未完成，Engine 停在 `Quiesced`；事务结束后 SQLite 写锁随之释放，
  但内容文件租约（`profile-content-key-vault.lease`，与资料库同在 App Group 共享容器）在重试暂停前一直持有，
  不会自动完成收尾。移动宿主现有策略只调用一次暂停、失败时不重试也不结束后台任务，回到前台时只从 `Suspended` 恢复，
  实测会使 Engine 停留在 `Quiesced` 并拒绝操作，直到下一次后台/前台循环。
- 恢复会话时，当前空间身份读取活动 manifest（`ActiveSpaceGenerationManifestStore::load_runtime`）曾在运行线程同步解密；
  资料密钥未激活时会经恢复存储读取宿主钥匙串。UniFFI 公开合同 `lifecycle_targets` 的闸门追踪显示首个被阻塞的密钥读取就在此处，
  运行线程因此无法回应暂停后的状态查询；该测试对时序敏感，准入入口移出运行线程后失败更频繁。主线 PR #153 已将 `load_runtime`
  的解密移到阻塞线程，本分支以其为唯一实现。异步 `load` 没有生产调用方，不做迁移；`is_admission_target_stopped` 只在已激活目标
  被终止后才可达，且在同一恢复路径上总在 `load_runtime` 之后执行，此时资料密钥已在内存中，不再读取宿主钥匙串，未找到真实生命周期
  复现，保持不变并列为线索。
- 其他线索未处理：续接凭据的入站认证读取、加入方与邀请方状态写入只在配对进行中触达；准备类适配器只有 MLS 计算，无 SQL 锁。
