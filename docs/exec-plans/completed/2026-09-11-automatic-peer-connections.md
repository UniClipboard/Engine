# 已配对设备自动连接与恢复 Spec

状态：已实现，完成用户指定的 Mac 桌面端与 iOS 模拟器本机验收；未发布。研究基线：`fe67a438`。

## 1. Overview

用户报告两台设备启动后需要点击刷新才显示对方在线。2026-09-11 导出的单侧 macOS 日志中，54 条主动 presence 拨号结果全部属于 `/presence/refresh` 请求；北京时间 08:07:19.652 发起刷新，08:07:19.972 标记一个目标在线。08:05:54 曾收到对方连接，08:06:22 对方关闭连接，说明不能把全部现象归因于发现服务不可用。

研究基线中的主动 presence 生产调用集中在 `MemberRosterFacade::refresh_presence`。`peer_keepalive.rs` 只转发状态通知，成员后台维护处理准入、成员效果、冲突和历史，不负责持续建立 presence 连接。旧名称和注释不能作为自动连接已经存在的证据。

另一个需要覆盖的代码事实：研究基线的 presence 入站 handler 在连接关闭后只删除入站连接记录并写日志，没有在该分支直接发布 Offline。因此不能仅补一个等待 Offline 的协调器就认为断线恢复完整；须核对目标是否仍有其他有效连接，再统一更新状态。它与本次对方关闭连接的日志吻合，但不是对方关闭原因的证明。

本需求面向**已有配对和当前通信资格的设备**：任一端启动、恢复运行或网络条件改善后主动连接，错过通知时仍能周期恢复。新设备的发现不意味着自动配对或自动授权。

日志没有准确 Engine 提交，也没有另一台设备日志；上述代码缺口不能据此认定为这次运行的唯一根因。后续验收必须从公开入口复现，不把源码搜索或日志计数当成功证明。

## 2. Goals

- 任一端均可主动连接；不依赖 Sponsor、Joiner、桌面或移动的固定主动方。
- 已配对的两端同时启动、先后启动、单端重启后，不调用刷新即可建立连接。
- 网络恢复、连接位置变化、系统唤醒、应用回到前台后触发有界恢复。
- 成员首次获得通信资格、对方被发现、连接断开和发送确认路径失败时触发恢复。
- 即使发现或系统通知丢失，运行中的节点仍在有限间隔内重试离线目标。
- 自动、手动及并发触发共用每目标连接尝试，不能重复拨号或互相关闭健康连接。
- 空间暂停、真正锁定安全会话、退出空间、设备移除和 Engine 关闭后，不产生越权或迟到连接。
- 测试同时证明在线状态、当前成员资格和实际内容传送；区分 Engine 本机验证与产品运行验收。

## 3. Non-Goals

- 不改变配对、安全认证、成员分叉处理、密码或邀请规则。
- 不自动接纳发现到的陌生设备，不允许暂停成员通过普通连接绕过成员恢复。
- 不因连接失败切换到 LAN 兼容线，不改变既有 Iroh 直连/中继选择。
- 不把每次普通离线升级为重建整个网络会话；保留 `NetworkRecoveryFacade` 的严格触发条件。
- 不引入持久重连队列、第二份成员名单或用户可调退避配置。
- 不承诺系统禁止后台运行的移动端仍能持续联网；不把界面锁定等同于撤销后台安全会话。
- 不在本仓维护 Desktop/mobile 的核心补丁副本；宿主事件接入在所属产品仓完成。

- Desktop 的 `src-tauri/crates/uc-tauri/src/update_scheduler/resume_listener_windows.rs` 已有 Windows 系统恢复通知，但当前用于更新检查，不能因为发现这个监听器就认定网络恢复已接线；进程归属和其他平台事件仍需核对。
- 上述路径分别相对 mobile、Desktop 仓库根目录；这是研究阶段的基线，最终宿主修改与验证见文末。

### 成熟方案与依赖核对

- [Iroh Endpoint 文档](https://docs.rs/iroh/latest/iroh/endpoint/struct.Endpoint.html)：`watch_addr` 随本机地址和中继选择变化更新；`online` 只是一次等待，不是持续自动重连。实现前已核对本机 `iroh-1.0.0-rc.1` 源码存在 `watch_addr` 与 `network_change`，不能照抄较新版本接口。
- 已安装 `iroh-mdns-address-lookup 0.3.0` 提供 `subscribe` 发现流。应持有 Endpoint 已注册的同一实例，不启动第二个发现服务。
- mDNS `Discovered` 只是地址线索，`Expired` 只是发现记录过期；二者都不能直接设置业务 Online/Offline。公网发现没有对应推送时依赖实际拨号解析与周期重试。
- [Syncthing 配置文档](https://docs.syncthing.net/users/config.html)：把自动发现和周期重连分开处理。这里采用“事件触发加有界周期兜底”的模式，不直接复制其参数。
- 现有 Tokio、futures、Iroh 已足够实现调度、取消、订阅与并发合并；不新增通用事件框架或重试依赖。

## 5. Proposed Design

### Components

**完整负责人：Application 的 `space/connectivity/PeerConnectionCoordinator`。** 它拥有目标选择、重复触发合并、重试、公平调度、暂停/恢复和结果结算。Runtime 只驱动这个完整行为；Engine 不读取成员、退避或内部任务状态。

| 组件 | 输入 | 输出与责任 |
| --- | --- | --- |
| `PeerConnectionCoordinator` | 当前成员范围、安全会话可用性、连接能力、环境提示、生命周期 | 每目标连接结果与既有在线通知；唯一重试/取消负责人。 |
| 受管 `ConnectionHint` 流 | 无业务请求；订阅现有基础设施通知 | 类型化的本机环境变化、已知目标连接资料变化提示；不包含公开地址，不直接授予资格。 |
| Infra 环境适配 | Endpoint `watch_addr`、同一 mDNS 实例、已确认传输失败 | 翻译提示，按已有身份资料定位候选；未知目标忽略，身份映射失败不能伪造已知目标。 |
| 当前成员范围通知 | 成员事实/效果成功提交、恢复完成 | 内部“范围可能变化”通知；订阅者重新读取唯一 snapshot，不在消息中复制权威名单。 |
| 宿主活动入口 | 前台、系统唤醒、宿主确认的网络变化 | 一个稳定 Engine 操作 `NotifyConnectivityOpportunity`，只提交机会，不暴露成员或要求宿主调用多步恢复。 |

自动连接与网络会话重建是两个完整行为：前者建立/恢复目标连接，后者替换故障网络会话。前者不得自行升级为后者；会话重建成功后由新连接负责人重新启动。

### Data Model

以下均为会话内私有状态，不写磁盘、不暴露给产品：

| 数据 | 含义与生命周期 |
| --- | --- |
| 运行代次 | 每次启动、暂停、关闭或范围失效后递增，用来拒绝迟到结果。 |
| 每目标状态 | 最近结果、连续失败次数、下一次到期时间、在途任务、合并后的待处理机会。 |
| 成员范围失效通知 | 触发权威范围重读；正式拨号前仍重新验证目标资格，不把旧 snapshot 当永久许可。 |
| 待触发机会 | 保留最近触发原因并合并为至多一次后续机会；不为同类事件建立无界消息列表。 |
| 手动等待者 | 等待共享任务的本轮结果；调用方取消只退出等待，不取消其他等待者或后台恢复。 |

目标状态数量不得超过当前允许通信的成员数；移除时取消并删除，不能长期保留陌生发现项。并发等待者使用有界通道，满时返回已有稳定繁忙错误，不静默丢失已接受请求。

### API / Interface

- `PeerConnectionCoordinator::refresh()`：保留手动刷新完整语义，返回既有 `PresenceRefreshReport`。加入正在执行的目标尝试，不启动重复任务。
- `PeerConnectionCoordinator::notify_opportunity(reason)`：内部有界通知；合并信号，不能等待全体拨号完成。
- 网络组装提供的受管提示流：返回受生命周期约束的提示流；结束和落后均有明确语义，不能因流关闭形成忙循环。
- `NotifyConnectivityOpportunity { reason }`：稳定业务输入，原因限定 `Foreground`、`SystemWake`、`NetworkChanged`。返回“已接受”，**不表示已连接**。同步更新 Rust、UniFFI、HarmonyOS 及生成契约；不为日志而扩展接口。
- 启动、Engine resume、成员变化和连接断开由内部自动处理；宿主不得重新实现计时器、目标循环或退避。
- 真正无法读取成员/安全状态时关闭式失败。新错误转换保留 source chain，日志/公开文本不得字符串化输出下层敏感错误；既有错误类型已丢失来源的边界须在相关实现步骤中修复，不能靠包装无来源分类声称完整保留。

成员通知在 `MembershipLedger::compare_and_commit` 和 `compare_and_commit_history` 的成功校验之后发布，失败不发布成功信号。启动恢复、完整 reset/切换和效果激活同样要核查覆盖；只给其中一个提交方法加通知不足以交付。通知只是使旧读取失效，不能把任何历史修订变化都视为“全体成员应立即重拨”。

### Workflow：触发矩阵

| 事件 | 作用范围 | 行为 |
| --- | --- | --- |
| 冷启动、进程重启、网络会话重建 | 全部当前合格成员 | Router 和安全会话可用后立即安排首轮；不阻塞 Engine ready 等待远端上线。 |
| Engine suspend 后 resume | 全部当前合格成员 | 新代次重新读取范围，立即安排；旧任务不得回写。 |
| 空间创建、解锁、恢复安全会话 | 当前合格成员 | 仅在完整激活成功后开始；不是收到 UI 操作就提前开始。 |
| 应用前台、系统唤醒 | 当前离线/未知成员，必要时验证已在线成员 | 打断旧退避，合并短时重复通知。 |
| 本机网络变化、网络/中继恢复 | 当前合格成员 | 等待短暂合并窗口后尝试，复用 Iroh 的地址解析和网络自恢复。 |
| 获得新成员资格、暂停关系恢复 | 新近可通信成员 | 立即尝试；仍暂停、待决定或已移除成员不拨普通 presence。 |
| 发现已知目标或其连接位置变化 | 对应合格目标 | 打断该目标退避；未知发现不触发全体扫描。 |
| 已在线连接断开、实际发送确认不可达 | 对应合格目标 | 安排恢复；普通内容/存储错误不能误判为网络故障。 |
| 入站认证连接成功 | 对应目标 | 记新鲜成功、清除失败计数，取消冗余待拨号，保留健康连接。 |
| 手动刷新 | 全部当前合格成员 | 立即核验，加入同一在途任务；结果按目标结算。 |
| 兜底定时到期 | 到期的离线/未知成员 | 不依赖任何通知，按公平队列重试。 |
| 真正暂停/锁定、退出空间、移除、关闭 | 全体或对应目标 | 先关闭资格和调度入口，再取消/等待任务、清除状态；迟到成功不能重新置在线。 |

“界面隐藏/锁屏/关闭窗口”本身不撤销后台同步；只有既有业务定义的安全会话撤销或 Engine 暂停才停止连接。前台事件和 Engine resume 必须按真实宿主状态分别接入。

### Workflow：调度与结果

1. 先订阅变化，再读取当前范围和安全状态，避免订阅建立前的启动遗漏。
2. 删除失去资格目标；为新目标安排首轮。每次开始目标任务前核验当前资格。
3. 对同一目标最多一个在途尝试，全局最多 4 个。慢/永久离线目标不能阻塞其他目标。
4. 不重写底层拨号重试：复用现有连接能力；每目标完整尝试外层最多 10 秒，包括等待基础设施能力。
5. 自动路径复用健康连接；手动/环境失效核验使用强制检查。双向同时拨号按一致规则保留连接，失败旧结果不得覆盖较新的成功。
6. 每次真实失败后按 `1s → 2s → 5s → 10s → 30s → 60s` 重新安排；采用 `0..20%` 有界抖动，最大等待 72 秒。连续失败不进入永久休眠。
7. 新的明确机会打断旧退避；同一目标机会合并窗口为 250ms。持续噪声不得无限推迟已到期任务，也不得每 250ms 发起一轮重试：重复无变化提示受最短 1 秒启动间隔限制。
8. 本轮尝试自身发出的 Offline 通知不得当成新的外部失败，避免失败立即重试的反馈循环。区分从 Online 变 Offline 与重复 Offline。
9. 如果机会发生在失败尝试进行中，合并为该次结束后的最多一次补尝试；若期间收到更晚的新鲜成功则清除补尝试。
10. 任一暂停、关闭或资格变化先撤销代次；取消释放拨号、等待者和连接占用，确认任务结束后才完成生命周期动作。

当前范围为空、通知漏发或某次读范围失败时，也必须保留低频全量重新核对的机会，避免“没有每目标任务就永远没有定时器”的空队列死角。正常在线状态的复核复用传输层连接关闭/活性证据，不按失败退避反复重建健康连接。

参数是本次明确的初始产品策略，不是库默认值。以受控时钟验证精确边界；真实网络只承诺满足前置条件后的预算，不保证互联网一定可达。

### 结果与观测

- Online 必须来自真实连接证据；调用成功、找到地址、名单出现或排入队列都不算连接成功。
- 连接成功不表示成员历史已一致，也不表示内容已送达。三个结果分别验证。
- 实际完成的连接尝试在运行诊断中记录固定触发原因及 online/offline/error 结果。取消由生命周期和等待者结算反映，不为正常清理制造业务入口。当前 typed 导出层不保留这些普通运行诊断，不能声称导出材料已覆盖全部自动连接原因。
- 跨层计时沿用 Engine 对既有完整能力的装饰方式；不为此暴露内部阶段、目标标识或步骤查询。
- 具体观测接入遵守[业务记录组织标准](../../design-docs/observability.md#业务记录组织标准)。设备名、地址、路径、指纹、内容、令牌及原始错误不得进入记录；没有双端关联材料时明确单侧证据。

## 6. Implementation Plan

| 步骤 | 修改位置 | 修改内容 / 风险 |
| --- | --- | --- |
| 1：建立失败复现 | `crates/uc-engine/tests/space_membership_auto_pairing_e2e.rs` 及其子目录 | 新增不调用刷新、RecoverNetwork 或 SendText 来促成连接的只读等待 helper；先跑已配对双端重启，确认当前实现失败。风险：其他隐式连接可能掩盖触发源，须记录是否真正运行 presence。 |

| 3：生命周期和手动入口 | `application.rs`、`space/facade/`、`space/lifecycle/session/`、`facade/roster/` | 自动启动/停止统一归 Space owner，手动刷新委托同一负责人；删除旧重复流程和过期 keepalive 注释。风险：启动订阅顺序、锁定回滚与关闭死锁。 |
| 4：成员变化 | `space/membership/ledger/` 与完整成员效果负责人 | 成功提交后发布有界失效通知，失效后重读权威范围；不公开步骤、不旁路受限成员历史恢复。风险：身份保留记录被误当现役成员。 |
| 5：网络与发现提示 | `crates/uc-infra/src/network/iroh/`、Engine 组装 | 复用本机地址 watcher、同一 mDNS 实例和既有离线信号；无新后台服务。检查双向拨号、取消及迟到失败处理。 |
| 6：宿主机会输入 | `crates/uc-engine/src/contract/`、`runtime/dispatch.rs`、`bindings/` | 增加窄输入，更新全部绑定与契约测试；Desktop/mobile 各自在产品仓接入前台/系统唤醒。Engine 最小端到端通过后才删除 mobile 已有 30 秒重试补偿，迁移完成不保留两套重试；没有宿主接线不能记真机通过。 |
| 7：全场景验收 | 测试宿主、现有网络隔离支持及本文矩阵 | 先本机真实双/三 Engine，再 Mac 桌面端与移动模拟器产品；保存命令、版本、断言和失败资料。单元、集成、产品验证分别报告。 |
| 8：收尾 | 架构圣经、稳定设计、active index | 稳定结论回写；完成全部适用门禁后归档，未验收保持 active，不伪造已完成状态。 |

## 7. Edge Cases

| Scenario | Expected behavior | Implementation |
| --- | --- | --- |
| 空空间、仅本机 | 无拨号，启动和刷新正常结束 | 权威范围为空时短路，不创建每目标状态。 |
| 成员资料损坏/不可读 | 不拨号，不用缓存名单兜底；保留失败来源 | 从唯一范围入口关闭式处理。 |
| 网络持续不可达 | 重试降频，但不永久停止 | 受控退避、72 秒最大等待和事件抢占。 |
| 一台永远离线，另一台刚上线 | 后者不能排在长等待之后 | 有界并发和到期队列公平性。 |
| 两端同时建立连接 | 保留可用连接，不互相反复关闭 | Infra 原子接纳/替换规则，真实双 Endpoint 测试。 |
| 旧失败晚于新成功返回 | 保持最新成功状态 | 连接实例/代次校验，不能只看时间相近。 |
| 移除或锁定发生在拨号中 | 迟到结果无权重新激活 | 撤销代次、取消与完成前资格检查。 |
| 一个手动等待者取消 | 其他调用方仍得到同一轮结果 | 等待者生命周期与共享拨号生命周期分离。 |
| 1000 个重复网络/前台提示 | 状态/队列有界，恢复不被饿死 | 合并、最短间隔、最大等待边界。 |
| 通知落后、流结束 | 重读状态，周期兜底；不忙循环 | 明确 Lagged/Closed 分支并停止轮询关闭流。 |
| DNS 或中继故障 | 复用已有网络自恢复 | 不为每个 peer 重置 Endpoint，不直接触发会话重建。 |
| 新旧版本设备混用 | presence 协议兼容则正常；不兼容明确失败 | 不改 wire protocol，验证真实旧版产物，不靠同版模拟。 |
| 移动系统冻结进程 | 无后台时延承诺；恢复运行后重新安排 | 使用宿主真实机会通知及 Engine 生命周期。 |
| GUI 锁定但后台授权有效 | 保持既有后台同步语义 | 不把 UI 状态当安全会话撤销。 |

## 8. Testing Strategy

所有新增行为先出现与本问题一致的失败，再实现。不得以静态文本断言、调用次数或“方法返回 Ok”代替真实路径验收。

### Unit Test：受控时钟、最小替身

使用 Tokio 暂停时间；只替换网络/存储边界，运行真实协调器。网络替身能阻塞、取消、按目标返回、发布真实顺序的 Online/Offline 提示；记录最大并发和取消完成，不模拟整个业务流程。

| ID | 输入与操作 | 必须断言 |
| --- | --- | --- |
| U01 | 启动时已有 2 个合格成员 | 首轮自动开始，无外部刷新；不等待首轮才返回启动。 |
| U02 | 首次离线，按每级时钟推进，目标随后上线 | 每级间隔/抖动有界；最终自动成功；成功清除失败计数。 |
| U03 | 达到最长退避，依次注入前台/唤醒/换网/中继恢复 | 每种机会都绕过旧等待，在合并预算内开始。 |
| U04 | 在途尝试中注入 1000 个相同和混合提示 | 每目标并发始终 1，队列有界，最多一轮必要补尝试。 |
| U05 | 自动尝试与 2 个手动刷新并发，取消其中一个等待者 | 底层尝试共享，另一等待者完成，后台重试未取消。 |

| U08 | 成员新获资格，再撤销，旧任务最后成功 | 新目标自动拨号；撤销后无迟到 Online/状态回填。 |
| U09 | 在途时 pause/shutdown，随后推进一天 | 所有任务和等待者结束，无新增拨号或后台残留。 |
| U10 | 暂停后 resume、激活失败、锁定失败回滚 | 正确代次恢复；失败不提前开放，合法回滚恢复原活动。 |

| U12 | 失败尚未返回时收到更晚的入站成功 | 迟到失败不覆盖成功，不执行多余补尝试。 |
| U13 | 丢失通知、接收器 Lagged、订阅关闭 | 状态可恢复、周期仍有效、关闭流无忙循环。 |
| U14 | 成员读取、网络能力、通知接线发生错误 | 稳定分类正确；有下层来源时 source chain 完整；敏感正文不外泄。 |
| U15 | 所有目标持续离线且没有事件 | 运行期间每目标仍不超过 72 秒加调度预算地重新尝试。 |

### Integration Test：真实连接与生命周期

复用独立 `DeviceHarness`、真实加密存储和 Iroh Endpoint、本地 rendezvous、现有 `DevOperation` 网络隔离。默认自动化不得依赖公网 rendezvous 或公共中继；若现有 `with_test_relay_fallback(true)` 允许公网回退，先为新场景配置本地可控路径，不能借它规避环境门禁。

只读 helper 查询准确目标的 `connected` 与当前成员资格，禁止调用 `RefreshPeerConnections`、`RecoverNetwork` 或发送内容来帮助它连上。确认连接后才发送唯一测试正文，校验接收记录内容一致；每个场景结束关闭两端并确认任务退出。

## 9. Acceptance Criteria

### 功能验收预算

- 计时起点是 Router、安全会话、当前成员资格和可用网络同时满足，不是用户按下电源键。安装签名、配对和系统要求的首次权限确认应先完成。
- iOS 模拟器用 `simctl privacy <设备> grant pasteboard <测试应用>` 配置测试粘贴权限；重启前由已在线应用写入测试剪贴板。准备数据后关闭两端，启动阶段禁止刷新和发送，连接确认后才注入新测试正文。
- 明确机会到首个可执行目标开始：不超过 1 秒；最多 4 目标的受控网络中，双方在线不超过 15 秒。
- 没有任何提示的晚启动/恢复：最多 72 秒等待，加 10 秒单次尝试与有界排队；4 目标内按 85 秒验收。
- 更多目标的上界按 `ceil(目标数 / 4) × 10 秒` 排队预算计算；不得声称固定 15 秒覆盖任意成员数。
- 真实互联网/移动后台的外部不可用时间单独记录，不从失败样本中删除；只有满足场景前提才测连接预算。

## 10. Risks and Trade-offs

- **电量与上线延迟**：纯事件方案会漏掉晚启动；固定高频扫描耗电。采用事件优先、最长 72 秒兜底，参数用可测预算限定。
- **双向拨号竞争**：过去只靠刷新较少暴露并发。协调器只能消除本端重复，跨端连接保留/替换必须由 Infra 正确处理并实测。
- **成员恢复循环依赖**：只有当前合格成员能普通连接；尚未恢复资格的成员继续由原有受限历史通道恢复，不能先要求普通在线才准核对历史。
- **所有权和关闭顺序**：连接任务跨越锁定或会话重建会回填旧状态；统一 owner、代次与取消必须一起验证，不能只增加定时器。
- **网络机会不是连通性证明**：本机有地址、mDNS 有记录、中继已连接都不保证目标可达，最终必须真实拨号。
- **通知完整性**：`watch_addr` 不覆盖所有同地址路由变化，mDNS 不覆盖公网目标；宿主机会与周期兜底都不可省略。
- **兼容范围**：新增宿主操作需要所有绑定更新，但不修改 peer wire protocol。不升级宿主的旧产品仍可获启动/内部通知/周期恢复，不能声称已获即时前台恢复。
- **替代方案**：启动后替用户调用一次刷新无法覆盖后上线和恢复；每次离线重建整个 Engine 破坏活动任务；均不采用。

## 11. Open Questions

- 原诊断包只有一侧 Mac，不能从本次修复反推原对端关闭连接的唯一原因。
- 物理网络拓扑、Windows、Android、HarmonyOS 和指定旧版组合未验收，详见 P03–P08。
- 当前基线的移动日志导出只保留既有 typed 遥测，普通连接尝试的触发原因不在其中；后续观测扩展应沿用现有完整能力装饰规则，不能增加第二套字段白名单或内部查询接口。
- 正式发布时仍需统一产品引用的 Engine 不可变版本；本次只完成本地实现与验收。

### 执行与验收记录

#### 实现结果

Application 统一拥有已配对合格成员的自动连接、手动刷新、事件合并、退避、公平调度、取消与恢复。Infra 统一观察入站/出站连接的关闭和新鲜成功，避免旧失败覆盖新成功、已撤销连接迟到回填。签名成员历史真实变化唤醒原有成员核对，普通进度提交不自触发。

Desktop 转发窗口前台与系统唤醒；mobile 转发前台和网络变化，删除原先 30 秒的产品重试循环。Rust、UniFFI、HarmonyOS 稳定机会输入保持一致。产品实现位于各自独立 `fix/automatic-peer-connections` 工作区，用户原工作区未被覆盖。

#### 失败先行与修复证据

- 原实现的双端冷启动在 15 秒内没有自动在线；实现后通过，随后双向正文核对成功。
- 原实现最后一条入站连接关闭未通知离线；修复后的真实 Iroh 测试通过。
- 原实现入站确认可在 `forget` 后返回接受；撤销代次核对后的测试拒绝该旧确认，21 项 presence 测试通过。
- 三设备测试最初把名单 `Active` 当作普通通信资格；失败现场实际是 `PausedUnverifiable`。现在只读等待 `Usable`，再开始原定 15 秒连接预算。三设备复验 125.07 秒通过（包含创建、两次准入、资格核对和重启），既有新成员传播测试 52.14 秒通过；这些总耗时不是单次连接延迟。
- iOS 完整应用编译发现旧传输通知的可空记录编号未处理，补齐后通过；原有扩展修订遗漏由已有失败测试锁定并修复。
- 未签名模拟器包不能使用应用共享存储；实际验收改用本地签名包。首次粘贴确认曾阻塞既有同步 host 读取，不能把这段系统授权等待当作已 Ready 后的连接失败。尝试过的 JS 启动顺序改动已撤回，最终交付没有这项推测性修改。
