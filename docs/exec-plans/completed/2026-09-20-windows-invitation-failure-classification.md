# Windows 首次邀请失败分类

状态：已完成实现与平台无关回归；Windows 实机验收由 Desktop `t-0016` 继续执行。

## 责任与结果

- 完整负责人：Application 邀请签发用例；调用方只提交一次 `IssueInvitation`。
- Infra 负责地址过滤、目录请求和局域网发布，并保留下层失败来源。
- 成功结果不变：目录可用时返回跨网络邀请；普通 DNS、TLS、连接或服务暂时不可用时，只要局域网发布成功就返回同网邀请。
- 明确失败分别为：无可发布地址、局域网发布失败、目录传输失败、目录拒绝、目录成功响应无效及未分类内部失败。
- 重试由产品依据稳定错误的 `retryable` 决定；本切片不增加持久恢复状态。

## 诊断结论

发布提交 `5e8d3d4322ca4eb83113f342068d4cb3297ea5eb` 与修复前主线的邀请实现一致。现场记录证明 Windows 端已有两个直连地址，但旧版只导出通用内部失败，因此不能从既有诊断包确认是局域网发布失败、目录拒绝还是目录响应无效。本切片不猜测 Windows 网络策略，只补齐可重复失败注入、稳定分类和安全输出。

目录成功后返回无效内容不能降级：服务端可能已经登记请求中的完整邀请，此时另行生成本地短码会造成两个发现渠道不一致。普通传输失败和 5xx 仍可安全降级，因为没有可用的目录签发结果。

## 公开约定

`IssueInvitation` 新增稳定错误码：1227 无可发布地址，1228 局域网发布失败，1229 目录传输失败且局域网也失败，1230 目录拒绝，1231 目录响应无效。原 1224 保留为无法进一步分类的内部失败。错误显示、调试输出和新增日志只输出固定类别，不输出地址、设备或空间标识、邀请、邀请码、令牌或响应正文。
