# ADR-014：应用层用动态 Port 表达外部能力

## 状态

已采纳。原始设计材料未记录最初决定日期。

## 背景

应用层需要依赖稳定的业务能力，而不应知道具体的存储、网络或平台实现。若把具体实现类型传入每个用例，组合处和测试都会被实现细节牵连。

## 考虑过的方案

### 用具体实现或泛型参数连接用例

这会让每种实现组合形成不同的用例类型，并把实现选择扩散到组合和测试代码中。

### 用动态 Port 连接用例

用例只接收所需的 Port，具体实现由组装位置一次决定。

## 决策

应用层用例通过动态 Port 接收外部能力。用例只依赖所需的最小能力面，不依赖基础设施的具体类型。

## 理由

这让用例类型保持稳定，组装位置不必暴露实现细节，测试也能直接提供所需的替身能力。

## 后果

- 具体实现只在组装位置出现。
- 每个用例必须选择最小的 Port 集合。
- 运行时调用会有很小的额外开销；对存储、网络和加密等操作可以接受。
