# ADR-017：配对作为工作空间内部的准入通道

- **状态**：已采纳，待实施
- **日期**：2026-08-10
- **补充**：ADR-016 的成员加入责任边界
- **相关文档**：`docs/adr/016-workspace-wide-convergence.md`、
  `docs/specs/016-workspace-wide-convergence.md`、
  `docs/architecture/architecture-bible.md`

## 背景

ADR-016 已确定工作空间收敛负责人必须对成员加入给出完整结果。但当前配对流程仍保存部分
加入状态、决定部分后续推进，并直接调用工作空间收敛。这样会出现两份流程知识：配对知道何时
准备成员资料，工作空间又知道何时把成员变更记入连续历史。

这会产生无法向调用方解释清楚的中间状态：配对已经成功，但成员尚未正式加入；本机已准备，
却不知道谁负责在重启、离线或交接失败后继续。把这种顺序和重试责任留给产品端，会再次形成
ADR-016 明确禁止的第二套队列和完成判断。

## 决策

### 成员加入由工作空间完整负责

成员加入是工作空间变化，不是独立完成的配对结果。`WorkspaceConvergence` 是邀请创建、准入
许可、已验证加入者接收、成员变化保存、后续交接、确认、重启恢复和完成判定的唯一负责人。

对外只保留两类动作：创建工作空间邀请，以及加入工作空间。调用方不接触握手阶段、就绪确认、
成员资料种子、交接唤醒或补送步骤，也不得自行排列这些步骤。它只收到明确结果：邀请已创建、
本机已加入并正在收敛、工作空间已完成，或不能继续的稳定失败。

一次“加入成功”至少表示新设备与发起设备都已保存加入所需的本地事实，且工作空间已经保存
该成员变化；它绝不表示所有既有成员已经恢复可用。后者仍只由 ADR-016 的完整工作空间状态
表达。

### pairing 只保留私有通信职责

配对不再作为独立的应用层流程负责人。它是工作空间准入实现内部使用的通信通道，只负责：

- 验证邀请、秘密和双方身份；
- 建立一次受限会话，并传递准入所需的安全材料；
- 把已验证的加入者事实和就绪回复交还给工作空间负责人；
- 在工作空间要求时关闭或拒绝该会话。

配对不得单独保存成员加入、创建成员交接、宣布成功、启动旧成员资料补送或定义重启后的恢复。
它也不得持有可选的工作空间负责人，以“不可用”方式绕过工作空间准入。通信细节可以独立测试，
但只能作为工作空间准入的内部实现，不形成第二个公开入口。

工作空间不应因此拥有底层拨号、报文编解码或密码握手的细节。它通过一个私有通信适配位置请求
“验证加入者”或“发送工作空间决定”，从而把通信替换、测试和协议演进限制在内部。负责完整结果
的仍是工作空间，而不是通信通道。

### 固定加入顺序和失败边界

工作空间按以下顺序推进加入：

1. 判断当前空间是否允许创建或接受该邀请；
2. 通过内部配对通道验证双方；
3. 保存加入方必要的本地事实并获得其就绪回复；
4. 在工作空间中原子保存连续成员变化；
5. 仅在保存成功后通知双方，并由工作空间继续交接和确认。

任一步在成员变化保存前失败，都不得留下新成员、普通内容权限或“配对成功”的对外结果。保存后
发生的离线、退出或交接失败是工作空间的 `Converging`、`WaitingForOfflineMember` 或
`RecoveryRequired`，由它在重启和重新可达后继续；调用方不重新拼接配对和补送步骤。

配对会话本身不是持久事实。进程中断后，工作空间只依据已保存的邀请和成员变化恢复；没有保存
加入变化的未完成会话不产生成员资格，也不得被误报为成功。

### 删除并行责任

实施本 ADR 时删除配对流程中直接保存或推进工作空间成员变化的责任，删除旧成员收敛流程被
配对直接唤醒、保存种子或补送资料的路径，并删除其可选依赖和无操作替身。不得保留新旧两套
加入路径、兼容回退或产品端补偿逻辑。

## 不做的事

- 不把配对底层通信、会话管理或密码握手细节公开给产品端。
- 不让工作空间负责人重写或直接掌握底层通信实现。
- 不把“对端可达”或“握手结束”当作成员加入或工作空间完成。
- 不让 P2P 失败自动切换到 LAN。

## 考虑过的方案

### 继续由配对和工作空间共同推进

两边都需要知道保存顺序、失败处理和重启后的下一步。复杂度会继续泄漏到两套流程和调用方，
因此不采用。

### 让工作空间直接实现全部通信

这会把拨号、协议和密码握手细节塞进负责成员结果的模块，反而扩大其职责，降低维护和测试的
独立性，因此不采用。

### 保留独立配对成功，再异步加入工作空间

这会永久保留“配对成功但并非成员”的含糊状态，并要求产品端猜测后续是否会完成，因此不采用。

## 后果

产品和绑定只理解一次工作空间加入及一份统一状态。成员加入、移除和重新加入都由同一负责人
保存和恢复，离线后的后续推进不再依赖配对流程是否仍在内存中。

代价是现有配对代码必须收回为内部通信能力，工作空间准入需要成为唯一的编排入口，相关测试也
必须从“握手完成”改为“成员变化已保存并可由工作空间继续推进”。这是 ADR-016 的既定完成边界，
不是兼容层或临时过渡方案。

## 验收标准

1. 外部调用者只能创建邀请或加入工作空间，不能直接推进加入的中间步骤；
2. 任一成功加入均可查询到已保存的工作空间成员变化；不存在“配对成功但未加入”的成功结果；
3. 成员变化保存前终止进程后，重启不会出现新成员、普通内容权限或成功通知；
4. 成员变化保存后终止进程后，重启由工作空间继续收敛，不要求调用方重新执行内部步骤；
5. 加入方、发起方和既有离线成员恢复后，最终完成仍以 ADR-016 的接收方实际可用为准；
6. 全仓库不再存在配对直接保存成员变化、直接驱动旧成员补送或绕过工作空间负责人的路径。
