# 核心信念

这些信念用于在规格没有覆盖具体情形时保持设计一致。

1. **隐私是存储模型，不是补丁。** 业务负载默认密文，日志和派生索引也属于威胁面。
2. **一个行为只有一个完整负责人。** Core 保存规则，Application 负责流程，Infra 提供能力，Engine 组装并隐藏实现。
3. **深模块优于步骤式接口。** 调用方只提交必要输入并接收少量稳定结果，不手工拼装内部阶段。
4. **事实来源必须唯一。** 不用缓存、投影、在线状态或旧兼容表反向授予业务资格。
5. **失败必须可解释、可恢复。** 跨层错误保留 source chain；正式提交后的暂时失败进入持久恢复，而不是伪装成未发生。
6. **P2P 是默认产品语义。** LAN 兼容能力只在用户明确选择后启用，不从 P2P 失败自动切换。
7. **外部只依赖 Engine。** 平台绑定和产品仓不理解内部 crate，也不维护核心补丁副本。
8. **生成物可再生，决策历史不可改写。** Schema、图表可以重新生成；ADR 被取代后仍保留原始上下文。
9. **文档说明意图与边界。** 能从代码轻易恢复的逐行调用关系不重复记载；难以恢复的约束、理由与验收证据必须记录。
10. **验证结果必须诚实。** 没执行的设备或发布检查只能记为“跳过”，不能记为“通过”。
