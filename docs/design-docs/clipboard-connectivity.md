# 普通剪贴板连接与独立交换

## 完整负责人和调用方式

业务调用方仍只调用 `ClipboardDispatchPort::dispatch(DeviceId, ClipboardHeader, SyncPayload)`，
发送密文并得到持久接受、重复、拒绝、不兼容或连接/交换失败。`uc-engine` 稳定入口及移动绑定不增加连接步骤。

Application 的 [`connectivity`](../../crates/uc-application/src/connectivity/) 负责一次完整连接获取、
共享拨号、请求撤销围栏、模式分配、租约、有限排队和关闭；它不选择发送内容，不重发内容。
普通剪贴板协议模块 [`network/clipboard`](../../crates/uc-infra-p2p/src/network/clipboard/) 只消费 Uni 连接和流，
负责原帧、每流接收交接及原 ACK。Iroh bridge 负责地址解析、密码握手、实际协商能力、原生半流、
现有成员准入与唯一连接登记。Engine 只把完整对象装配到现有节点。

重试仍由原业务发送/恢复负责人决定。P2P 失败不自动切换 LAN；presence、文件、组更新与成员恢复不共享本切片连接。

## 连接与撤销

同会话、同目标并且实际协商为多流的并发请求共用一个 flight 和活动连接。每个等待者有独立绝对截止时间；
首等待者退出不取消其他人的拨号，最后等待者退出才取消 flight，manager 的监督任务等待拨号结束。
剪贴板 manager 只弱引用活动连接；最后一个连接／流／本地工作租约释放即关闭，不存在空闲连接池。
通用半流提供本连接内流 ID 和显式 reset／stop，只终止当前交换。`StreamLease::into_parts` 可把 I/O 交给 SDK，
同时将连接、活动计数与额度交给 `StreamWorkLease`；网络结束后，本地导入／导出未结算前仍持有这份工作租约。
它不授予业务步骤或观测查询能力。
成员历史使用独立 manager，并启用有界跨轮保留，见[成员历史连接边界](membership-history-ownership.md#成员历史连接边界)。

内部协议通过同步的 `ConnectivityManager::request` 在任何排队前捕获自身 `AdmissionAttempt`
及会话代次，得到不透明的 `ConnectionRequest`；之后才等待该请求的 `connect`。
协议有自己的外部队列时，也必须先创建请求；网络恢复复用同一请求，不能重新取撤销快照。
断开会话后，即使 manager 再次接受工作，旧请求也不能启动。共用建连者的连接不替换调用者的快照：
开流前先检查请求快照，再检查连接 grant 的当前成员权威。旧请求不能借用移除再添加之后的新连接，
拒绝旧请求也不会关闭仍有效的新世代连接。当前成员拒绝、读取异常或连接授权失效由 grant 关闭整个连接。

Iroh admission 复用原身份目录、成员权威和同一 `AdmittedConnections`，不创建第二份授权表。
登记与撤销 epoch 保持原子围栏，迟到拨号和待排队请求都不能跨越撤销。

需要等待实际本地工作的协议启用 `supervise_local_work`；presence 保留原有监督行为。
取消或期限到达只结束自己的等待；还有其他等待者时不取消共同拨号，也不等待兄弟请求完成。
最后等待者退出时，拨号额度保留到已开始的工作实际结束；期间真实失败与取消／超时主因一起保留。
准入读取同样等待已经开始的本地工作，不因停止而补启动尚未 poll 的读取。业务负责人负责监督整个
请求 future，不能用外层超时直接丢弃它来代替这些结算。

需要独立入站准入预算的协议可配置 `InboundAdmissionPolicy`：Uni 在接收入口同步冻结会话与撤销围栏，
先取得未知身份额度；Infra 解析出身份后，经 `InboundIdentityReservation` 原子申请每端额度，
成功交接后才读取当前成员权威。失败不得继续成员读取。受管准入任务归原 manager 的任务集合，
丢弃调用等待不会丢弃已开始的本地读取；期限到达先关闭本连接，再等待读取并保留真实失败。
未知额度在身份交接后释放；尚未识别就失败时，仍覆盖实际读取及连接关闭。旧协议的拒绝回执仍保留原处理额度。

`connections_per_peer_direction` 将每端的入站与出站方向分别计数，名额由连接工作使用权及实际关闭
监督者共同持有，覆盖建立、准入、流、本地结算和关闭。两者全部结束才归还，不建立第二套原生连接缓存。
关闭收集还包括已接受拨号晚返回时登记的关闭任务；会话监视持原 token，不在重新启用时改取新 token。
失活连接的 `refresh` 消费旧使用权，保存原请求资格和会话，移除原空闲保留；方向受限时等待旧连接实际关闭、
兄弟流及本地工作全部释放名额，再在原截止时间内重获连接。该等待可取消，不持有旧 record，不能因重连刷新撤销基线。
Blob backend 每轮只调用一次原生连接；内容流程统一负责网络恢复。Blob 的空闲保留也必须经当前成员准入检查，
其他协议沿用各自的保留权威与策略。提供端交换限额和业务取消仍归完整 transfer owner，不能用连接限额代替它们。

需要兼容空预热的协议可启用首流准入：候选先等原生首流，不读取业务内容，仍持入口围栏与未知额度；
第一份流使用准入入口的原截止时间，后续流从自身到达起算。可选即时拒绝策略先取得当前流再检查额度，
超额显式停止两半流并保留停止失败，只拒绝本交换；许可仍附着在实际 SDK 工作租约上。
Blob 的完整提供端由 Application `transfer/blob/transport/runtime` 负责，生产 Router 通过薄 handler 交接，
原 SDK provider 自管连接入口已经移除。获取只交给 Uni 的请求级不透明地址提示，不为票据地址另开预热连接。
票据认证公钥可在同步排队时区分来源；业务设备身份与授权仍读取当前权威，原会话与撤销围栏在异步目录查询前冻结。
接收物化由 `transfer/receive/materialization` 接受唯一 `ReceiveWorkPlan` 入口；模型、专属 port 与流程按职责组织，
原剪贴板模块只交接计划、接收聚合结果并继续保存，不再持有物化实现。
下载额度和内容保护归 transfer 的完整获取、适用输出和引用结算持有；对端通知通过有界合并交接，不进入停止等待链。
旧行扫描只恢复当前没有未结算获取／取消负责人的记录，不能抢占受管请求的阶段时钟。
条目取消由 Application `transfer/receive/cancellation` 完整负责权威 CAS、实际子任务停止、投影、暂存清理和终态提交；
同一条目与尝试共享原协调任务。接收动作在 attempt 写入前登记内存工作寿命，子获取继承同一停止 token；
取消在停止已有子获取后继续等待原接收动作（含目标预留和部分结果保存）实际结束。
五秒只限制调用等待，调用方退出不丢弃工作，transport 关闭收集取消协调结果。
清理前重新读取持久权威；原接收已提交部分取消时只补活动投影，不用 NoEntry 或 staging 清理覆盖成功文件。
子任务停止失败时不继续清理产物，取消通知在实际停止结算后交接。
独立文件使用各自的项会话，失败或单项取消继续后续文件；整计划取消才封住剩余项。
`transfer/receive/batch` 汇总所有有效项的事实，完整接收动作在持久保存结算后才交接远端终态；
单项最后成功不能覆盖之前失败，必要会话结算失败也不能报告完成。批次与获取共用 200ms 的普通进度节流。完整接收和结果结算的迁移状态只在当前执行计划维护。

bridge 对出站连接在握手后订阅既有确认离线事件；已排队的 Offline 即便随后 Online，获取租约及原生开流前仍同步判旧连接失效；后台观察同时推进同步游标，其他 peer 的健康事件不积压成假失活。消息尚未发送时，准入后已确认失活的连接最多更新一次，仍用原准入快照和原 deadline；迟到共同结果已关闭时有界重新获取，不重发已写出的内容。manager 的原 JoinSet 监督连接结束并在 shutdown join，监督只持原生能力，不保活租约。Offline/Lagged 关闭本条连接，不推进成员 epoch、不复用 presence 连接、不自行重发内容；明确不可达的网络 I/O 返回原 Offline，本地授权来源保持 Io source。

原 Application 发送 owner 内部按内容/目标围栏在途尝试：新 Pending 持久成功后才能取代旧写入权，旧 deferred 不覆盖同条内容的新结果；失败的新意图不丢失旧回执。私有 token 只存内存且弱表可回收，不改变持久格式。跨内容 Superseded 的既有竞态见[技术债](../exec-plans/tech-debt-tracker.md)。

## 协商和回执

| 实际协商 | 能力 | 连接分配 |
| --- | --- | --- |
| `uniclipboard/clipboard-applied/2` | 多条独立 bi stream | 共用活动连接，每份内容独立结算 |
| `uniclipboard/clipboard-applied/1` | 原单次交换 | 每连接仅一次交换；共同拨号结果仅一人领取，其余有界独占拨号 |

双方同时 offer 时生产 Router 优先 `/2`；与修改前只支持 `/1` 的端点协商 `/1`。
只在实际握手选择旧协议时采用旧模式；不能在坏帧、拒绝、超时后改协议重发。`/clipboard/0` 仍不支持。
帧、header 和 ACK 字节没有改动，也没有新持久化格式。

`Accepted` 表示 Application 已持久接受；`DuplicateIgnored` 表示重复内容已被确认。
两者都不承诺宿主已写入系统剪贴板。每条流持有自己的 receipt，兄弟流不等待它的应用结算。
广播交接仍有界且由原 Application 接收运行期处理，没有消费者、丢失 receipt 或应用拒绝均不能伪报成功。

## 有限资源和失败

初始 policy：每目标 4 条活动出站流、每连接 4 条活动入站流、每会话 16 个活动入站交换；
每目标 32 个等待者、每会话 128 个等待者与入站连接处理、64 个 flight。
等待槽满返回固定 `Busy`；已有槽位公平等待，取消释放排队位置，不复制额外密文。

接收等待先持本连接额度，拿到原生流后再等待全局交换额度；空闲连接不占全局活动交换额度。
同一连接至多一条已接收流等待全局额度，未取得额度前不读取/分配负载。
未经准入的连接也只允许一次有限拒绝处理；过载直接关闭。

出站从 dispatch 开始共用 75 秒绝对 deadline，覆盖地址、准入、排队、开流、写帧与 ACK；
上层原 5 秒 fan-out 取消仍可更早结束本请求。原生错峰拨号使用原来更短的预算。
入站一次接受/准入等待最多 60 秒，帧与负载后的准入重检共用 60 秒读帧 deadline，
应用 receipt 最多等待 60 秒，ACK 写入另有 60 秒有限预算。
慢读、坏帧、超限、RESET、单个发送取消或 ACK 流控挂起只结束该流，Drop RESET/STOP 未完成的半流。
已确认失活、观测历史丢失、成员撤销、Space 退休和节点关闭结束整体连接。

地址缺失与已诊断的建立失败保留业务 `Offline` 分类；地址能力读取或成员能力读取异常、
排队/超时/流/任务异常保留带 source 的 `Io`。共享失败保留同一来源；错误采用穷举 `ErrorClass`
与固定公开文本，不输出原生错误正文、身份、地址或业务负载。

## 世代、观测和关闭

多流接收使用同一个 generation scope 中的 `FuturesUnordered`，不为各流 spawn 任务，
所以原 dispatcher task-local 世代自然延续。接受 future 持续 pin 到完成/超时，
兄弟流完成不能取消已经接收但正在准入的流，不能重置公平排位或截止时间。
每流认证之后设自己的远端 trace parent，并在该 scope 中捕获 `ClipboardDelivery`；
共享拨号监督任务不继承首条消息的业务父 span。
原写入 owner 在自己的异步任务与阻塞线程分别恢复不透明 ObservationContext；
手动重发的完整观测入口也延续该上下文，技术 span 不进入 OT 层时仍归属本次业务记录。
计时和结果分类保持在原 Engine port decorator，不新增业务阶段读取。

会话/节点关闭停止新获取、关闭所有登记的活动连接并取消、等待所有 flight。
拨号任务 panic 保留 `JoinError` 并通过固定 `clipboard_connectivity_worker` task.kind 上报；
重复 shutdown 仍返回已记录的任务失败。正常释放不新增业务记录。

实施与验证历史见[执行计划](../exec-plans/completed/2026-10-11-clipboard-connectivity-plan.md)。

## 当前剪贴板状态与按需拉取

当前状态通知和按需拉取分别使用独立的 Uni manager。四个网络入口由 Application
`clipboard/active/transport` 完整负责；Iroh handler 只转换连接并调用一次 receiver，wire
只适配既有 codec。两个 ALPN 的唯一常量在 `uc-sync-protocol`，字节、状态码和持久格式保持原契约。

每次入口先建立 10 秒绝对期限，排队、身份检查、拨号、开流、帧、等待准备和关闭共用该期限。
FIN 后最多等待 3 秒，且不能超过入口剩余时间。通知完成只表示本地发送结束，不确认远端应用。
两类 manager 各有每目标 4 个出站交换、全局 16 个入站交换、每目标 32 个等待者、
全局 128 个等待者及 64 个 flight；每连接只有一次交换，不保留空闲连接。

完整准备沿用共享出站 owner 的重建、blob 发布、编码与加密。停止信号阻止后续动作，
已开始的不可安全中断动作仍完整结算。网络等待取消不释放正在执行的本地工作所持的原流额度
与会话世代许可；阻塞池中尚未开始的工作在执行前检查停止信号。

恢复广播使用一个最新待发槽，原子保存状态、类别、版本及到达时刻。旧回调与重复状态不能
刷新最新值的防抖时刻；正在发送的轮次完成后，按到达时刻仅等待剩余的 300 毫秒。
每轮最多并发 4 个目标，恢复、入站收敛及上线补发共用有界执行；上线补发仍保留自身目标集合
和 1500 毫秒防抖。广播记录说明触发原因与本地发送结果，远端 register 和系统写入仍由原 owner 结算。

本机连接终态保留原 `purpose`，不依赖非阻塞日志输出中的开始记录始终存在。原生 bridge 通过既有
不透明物理上下文关联一次完整接收；`channel` 只允许 Direct/Relay/Unknown 枚举词表。选路验收使用
同进程连接匿名编号与实际终态或完整接收的原连接 channel，不按跨端内容哈希或时间猜测关系。
日志丢弃与关联缺口仍按原有限输出统计；路径已验证不等于整条诊断记录无丢失。

实施验收见[当前剪贴板执行计划](../exec-plans/completed/2026-10-14-active-clipboard-connectivity-plan.md)。
