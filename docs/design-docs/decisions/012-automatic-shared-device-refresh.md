# ADR-012：主动刷新共享设备采用自动连接与状态通知

- **状态**：Accepted（已实现）
- **日期**：2026-08-07
- **修订**：2026-08-09 补充“会话恢复后自动查找”触发路径
- **相关文档**：`docs/architecture/architecture-bible.md`、`docs/design-docs/ports.md`、`docs/design-docs/features/012-automatic-shared-device-refresh.md`

## 背景

用户将两台设备配对后，任一设备可能已经与同一 Space 中的其他设备建立了关系。新配对设备若尚未取得这些已有设备的资料，就无法与它们建立同步关系。

现有成员关系收敛能力负责交换已验证的设备资料、确认新设备身份、保存可信关系和在对方离线时继续重试。本决策为它增加一个由用户明确发起的刷新动作：用户点击“刷新设备”后，系统立即向已配对设备查询缺失的设备资料，并自动尝试建立关系。

产品端需要在这个过程中弹出提示，告知用户正在连接哪些设备。该提示是进度告知，不是授权步骤。用户不选择设备，也不能取消已经开始的自动共享。

## 决策

### 一个自动完成的用户动作

Engine 提供一个稳定的“主动刷新共享设备”动作。调用成功只表示本次刷新已启动，并返回本次请求编号；调用方不参与查询、身份确认、重试或关系保存。

同一 Space 已有刷新正在进行时，Engine 不启动第二轮重复查询，而是返回正在进行的请求编号。产品端据此继续展示同一份进度。

### 过程由状态通知驱动

设备资料需要经过网络查询和逐台确认，不能要求产品端等待一个长调用结束，也不能让产品端轮询。Engine 在动作开始后，通过同一类状态通知向调用方发送进展：

```text
开始刷新
  -> 发现待连接设备
  -> 正在确认设备
  -> 已连接 / 已存在 / 等待对方上线 / 未通过确认
  -> 本轮完成
```

每条通知包含请求编号、阶段、稳定状态和必要的数量统计。发现待连接设备时，通知包含已去重、稳定排序后的设备展示资料，供产品端在弹窗中列出“正在连接的设备”。最终通知包含各状态的数量和本轮是否仍有等待对方上线的设备。

产品端弹窗没有确认或取消按钮。关闭弹窗只隐藏界面，不会停止 Engine 中的工作；后续设备列表和同一请求的状态通知仍反映真实结果。

### 对外展示资料最小化

产品端只接收展示所需的资料：稳定设备标识、设备名称和状态。不得向产品端暴露连接地址、身份指纹、签名、安全资料或底层网络错误原文。

来源设备返回的资料只代表候选信息，不代表已建立关系。Engine 必须直接与每台候选设备再次确认身份、Space 和准入状态。确认成功后，才使用既有的原子提升流程写入成员、可信关系和可连接地址；任何一项确认失败都不得将该候选设备显示为“已连接”。

### 复用既有成员关系收敛能力

主动刷新复用现有成员关系收敛通道、消息边界、设备资料校验、候选状态和离线重试。不得为此创建剪贴板同步动作、剪贴板网络通道、第二份设备名单、第二套可信关系或产品端编排流程。

Engine 负责以受限并发向当前 Space 中已配对且仍可信的设备查询。查询结果按设备身份去重；已存在的成员不会再次建立关系。被移除、不同 Space、版本不兼容、身份不匹配或资料超限的候选必须被拒绝。

候选设备暂时离线时，本轮状态为“等待对方上线”。候选仍由既有成员关系收敛机制保存和重试；它上线后完成确认，不要求用户再次点击刷新。一次请求的完成通知不承诺无限等待离线设备，而是如实报告仍在等待的数量。

### 日志与隐私

日志记录请求编号、脱敏设备标识、阶段、候选数量、结果数量、耗时和稳定失败类别。日志不得记录设备名称、地址、身份指纹、安全资料或剪贴板内容。

任何新增持久化资料继续遵守默认加密规则。主动刷新不新增明文持久化字段，不把候选资料写入临时明文文件。

## 不做的事

- 不同步剪贴板、历史内容、文件或“最新内容”。
- 不要求用户再次输入邀请码、口令或手动逐台配对。
- 不把弹窗设计为选择、确认或取消设备共享的权限界面。
- 不自动连接已移除设备、不同 Space 的设备或无法完成身份确认的设备。
- 不创建独立于既有成员关系收敛机制的后台队列或重试系统。

## 后果

产品端只需发起一次刷新并订阅状态通知，就能展示发现设备、连接中、完成和等待上线的真实进展。它不再根据本地猜测推导连接状态，也不需要把多个 Engine 调用拼接成配对流程。

Engine 的公开契约需要增加刷新启动结果和状态通知模型；移动绑定与桌面调用方必须映射同一套状态。成员关系收敛模块继续是完整流程的唯一负责人，网络层只负责受认证的消息传递和既有边界校验。

## 修订：会话恢复后自动查找

设备重启并自动解锁后，仅靠既有成员之间的常规同步无法发现同一 Space 中本机尚未认识的设备，因为常规同步只在已建立关系的成员之间交换信息。因此，成员关系收敛运行期在会话恢复成功时自动调度一轮与手动刷新相同的已有设备查找。

自动调度由收敛运行期管理，按 Space 合并：会话锁定时不调度；一次恢复只启动一轮，重复解锁、就绪或在线事件不产生重复查找；来源设备离线时等待其重新上线后再完成本轮，不进入无限重试。产品端无需保存查找队列，也没有新的可见状态。此修订不改变手动刷新的任何对外契约。

## 验收标准

1. A 已与 C 建立关系，B 与 A 配对后发起刷新；B 先收到包含 C 的“发现待连接设备”通知，再在 C 在线且确认成功后收到“已连接”，并能在本机设备列表中看到 C。
2. C 离线时，B 收到“等待对方上线”，不把 C 误报为已连接；C 上线后由既有重试完成连接。
3. 重复点击刷新不会产生第二轮并发查询、重复成员或重复可信关系。
4. 已移除、不同 Space、资料被篡改或版本不兼容的设备均不会进入设备列表；状态和日志只给出稳定失败类别。
5. 所有设备展示、状态通知和持久化均不泄露地址、身份指纹、安全资料或剪贴板内容。
