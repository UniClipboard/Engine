# ADR-024：将 ResetSpace 定义为设备管理重置

- **状态**：已采纳并实施
- **日期**：2026-08-20
- **修订**：ADR-022 和现行接口说明中“`ResetSpace` 只清除设置状态和未消费邀请”的规则
- **相关文档**：`docs/design-docs/decisions/022-user-initiated-join-supersession.md`、
  `docs/design-docs/decisions/023-legacy-profile-isolation-and-re-pairing.md`、
  `docs/exec-plans/completed/023-durable-membership-proof-and-admission-activation.md`、
  `docs/exec-plans/completed/026-legacy-profile-isolation-and-re-pairing.md`、
  `docs/design-docs/uc-engine-interface.md`、

## 背景

变更前的 `ResetSpace` 只在全部准入工作静止后清除本机设置状态、未消费邀请和公开加入结果。它保留成员、
设备关系、旧空间安全状态和恢复材料，因此不能让一台已经陷入矛盾成员关系或无法继续恢复的设备回到干净
配对环境。名称所表达的重置范围也明显大于实际行为。

`FactoryResetSpace` 可以解决这类问题，但它同时销毁本机历史、受管文件、设置、设备身份和全部密钥。
当用户只想放弃所有设备关系并重新配对时，这个代价过大。

ADR-023 已经证明第三种边界可行：保留本机资料、设置、身份和解锁材料，废弃全部旧设备关系，建立只含本机
的新空间，并在中断后继续同一次独立化。该能力目前只服务于旧资料升级，不能由用户在正常资料上主动执行。

桌面端已经接通 `ResetSpace`，但当前产品界面没有实际调用点；iOS、Android 和 HarmonyOS 绑定也没有开放
该操作。虽然现有产品风险较低，`ResetSpace` 已是稳定 Engine 操作，后续修改必须按公开行为变更记录，不能
把它当作无人使用的内部方法。

## 决策

### 保持公开操作不变，重新定义完整结果

保留现有 `ResetSpace` 操作名称、无参数输入和 `SpaceReset` 成功结果。它的新含义固定为：

> 保留本机内容、一般设置、设备身份和解锁能力，永久废弃本机保存的全部旧空间设备关系，建立一个只含
> 本机的新空间，使设备可以从零邀请或加入其他设备。

这里的“新空间”是不可降低的结果要求。仅删除成员、邀请或关系表，但继续使用旧空间标识、旧活动安全状态
或旧恢复范围，不属于 `ResetSpace` 成功。该类轻量操作若将来需要，必须使用另一个含义明确的产品动作，
不得作为本 ADR 的简化实现。

这是公开行为的有意变更，不承诺兼容旧的“只回到未设置页面”含义。版本说明、接口说明和产品确认文字必须
同步更新。

### 只允许明确的用户操作触发

`ResetSpace` 是正常修复无效后的最后兜底，只能由用户在危险操作区域明确触发。产品必须在调用前说明：

1. 本机与所有旧设备的关系会永久失效；
2. 其他设备不会被远程清空；
3. 所有希望继续同步的设备都必须重新配对；
4. 本机历史、文件、一般设置和身份会保留。

产品必须提供与后果相称的二次确认。Engine 不因启动失败、网络错误、成员分歧、配对失败、升级检测或超时
自动调用 `ResetSpace`。旧资料升级仍可在自己的明确条件下复用同一内部重建能力，但不能通过伪造用户操作
进入公开入口。

### 一个负责人完成全部重建

应用层空间生命周期负责人完整拥有设备管理重置。调用方只调用一次 `ResetSpace` 并接收成功或稳定失败；
不得依次编排取消邀请、取消加入、删除成员、清关系、切换空间、创建空间或恢复运行。

负责人按以下顺序完成结果：

1. 串行取得 profile 级重置资格，阻止新的发送、接收、配对、成员变化和空间切换进入旧空间；
2. 持久保存本次重置和唯一目标空间，使重复调用与重启继续同一次工作；
3. 停止旧空间运行，断开现有设备连接并取消内存中的未消费邀请；
4. 从已停止变化的旧空间取得一致快照，在不修改旧空间的独立目标世代中完成资料重封装；
5. 在目标世代中建立只含本机的成员历史、安全状态和当前范围，并排除全部旧准入、关系、地址、投递待办、
   后台重试和切换状态；
6. 从独立读取入口验证目标历史、已完成文件、解锁、搜索、成员、安全状态和新邀请能力；
7. 通过一次原子活动清单替换，将整个 profile 从旧空间切换到目标空间，同时持久表达“全部设备需要重新配对”；
8. 从新活动清单恢复运行；确认运行入口一致后返回成功，随后清理旧世代和过渡文件。

内部实现应复用 ADR-023 已有的本机独立化规则，但必须移除应用版本判断等旧资料专属条件。不得长期保留
用户重置和旧资料独立化两套清理顺序。

### 原子生效边界

活动空间清单的原子替换是 `ResetSpace` 唯一的生效点，也是判断结果的唯一事实来源。数据库连接、受管文件
根、安全状态、设置投影和运行会话不得分别充当生效标志。

生效点之前：

- 旧空间必须保持完整且可重新启动；不得从旧空间原地删除成员、关系、准入、安全状态或恢复记录；
- 目标空间只能写入独立的暂存世代，不能被普通查询、连接、投递或恢复入口观察到；
- 任一步骤失败都返回未生效，并恢复旧空间运行。重复调用复用同一目标，或在确认未生效后安全重建该目标。

生效点之后：

- 新空间是唯一有效空间，不得因后续启动或清理失败回到旧空间；
- 重启和重复调用必须识别已经提交的目标，直接完成新空间启用和清理，不得再次创建单设备安全状态；
- 若调用仍在等待，负责人必须优先完成新空间启用并返回成功；无法恢复运行时返回“已切换但需要恢复”的稳定
  结果类别，不能把它描述为重置未发生。

进程退出或调用方断开可能使成功响应无法送达，但不能使持久状态含糊。下一次查询或重复调用必须能根据活动
清单确定重置究竟未生效还是已经生效。

### 保留与清除的边界

必须保留：

- 本机剪贴板历史、已完成文件和受管内容；
- 一般设置和设备显示名；
- 本机设备身份、网络身份、profile 主密钥、解锁材料和当前可读内容；
- 证明旧内容归属和解密所必需、但不会重新授予旧成员资格的最小历史事实。

必须清除或永久退出普通运行范围：

- 所有远端成员及其成员资格、信任、地址、在线状态和同步偏好；
- 旧空间的活动成员历史、安全组、内容钥匙目录和成员收敛状态；
- 未消费邀请、未完成加入、入站候选、移除、待确认消息、后台重试和切换状态；
- 任何能让旧设备重新成为普通发送、接收、探测或恢复目标的状态。

保留的历史事实不得出现在成员列表、设备信任、候选选择、在线探测或普通内容投递中。若无法同时满足
“旧内容仍可读取”和“旧成员不能恢复资格”，重置必须失败并保留可继续状态，不能扩大成员范围或删除内容
来伪造成功。

### 完成后的稳定状态

成功后，本机处于已完成、已解锁且可运行的单设备空间，不回到首次设置页面。设备列表只包含本机，可以
立即签发新邀请，也可以通过现有 `JoinSpace` 加入另一台设备的空间。

“全部设备需要重新配对”状态必须跨重启保留。第一次成功建立新的设备关系后，负责人按统一规则清除该提示；
关闭提示、离开页面或查询状态不得清除它。

其他设备仍保留各自的旧空间和对本机的旧记录。重置不伪造远端移除确认，也不等待网络；旧设备后续连接
本机时必须因不属于新空间而被拒绝。用户需要选定一台设备作为新空间起点，再让其他设备逐一加入。

### 失败、重启与临时数据

重置不要求网络在线。每个阶段必须可识别、可重复，进程崩溃、断电或重复调用后继续同一个目标空间，不能
创建多个单设备空间，也不能同时暴露新旧空间。生效前允许回到未被修改的旧空间；生效后只能向前恢复新空间。

成功结果只在新空间成员历史、安全状态、当前范围、设置状态和运行入口全部一致后返回。失败时返回稳定类别，
并保留足够状态供重试或启动恢复。若本机身份、解锁材料或保留内容已经损坏到无法建立安全的新空间，返回
明确失败并引导用户使用 `FactoryResetSpace`；不得自动扩大到彻底重置。

准备期间允许短期同时保存旧活动世代、目标暂存世代和一条重置记录，但每份数据必须由目标标识和阶段明确
归属。启动恢复依据活动清单处理：清单仍指向旧空间时，继续或丢弃目标暂存；清单已指向目标空间时，只清理
旧世代和暂存。清理必须幂等，失败后保留待清理记录并在后续启动重试，不能猜测或扫描删除未知目录。

开始复制前必须估算可用空间；空间不足时在生效前拒绝重置并保持旧空间可用。实现可以对不可变的已完成文件
使用经验证的复用方式减少额外占用，但不能让新旧空间共享会被任一方修改或删除的可变资料。所有暂存资料
继续遵守密文落盘规则。

### 与其他操作的边界

- `CancelInvitation` 只取消尚未消费的邀请，不清成员关系；
- `CancelJoinSpace` 只请求结束指定加入，不清当前空间；
- `RemoveMember` 只移除指定远端成员并按正常规则收敛；
- `ResetSpace` 保留本机资料和身份，废弃全部旧设备关系并建立单设备空间；
- `FactoryResetSpace` 继续是销毁本机资料、设置、身份和密钥的唯一操作。

## 不做的事

- 不向远端设备广播“恢复出厂”或远程删除其资料。
- 不等待所有旧设备在线或确认后才完成。
- 不逐台执行正常成员移除，也不要求旧空间先收敛。
- 不保留旧成员作为离线、待确认、历史设备或自动恢复候选。
- 不新增参数让调用方选择清理阶段或保留某个旧成员。
- 不因 P2P 失败自动切换到 LAN 兼容线。
- 不改变 `ResetSpace` 的名称、输入和成功结果。

## 考虑过的方案

### 新增另一个公开操作

这可以保留旧 `ResetSpace`，但旧操作当前没有产品调用价值，两个名字相近的重置会长期要求产品和维护者理解
细微差别。现有 `ResetSpace` 的名称也更符合设备管理重建，因此不采用。

### 复用 FactoryResetSpace

它能得到干净环境，但会删除用户仍然需要的历史、文件、设置和身份，超出设备管理重置范围，因此不采用。

### 逐台移除全部成员

正常成员移除需要当前安全状态可继续、可能等待离线设备，并会保留完整收敛过程。最后兜底正是用于这些条件
不再可靠的情况，逐台移除无法保证完成，因此不采用。

### 只删除设备关系相关表

该方案改动较小，但旧空间标识、安全状态、内容钥匙目录和恢复资格仍然存在，无法保证旧设备永久失去新空间
资格；误删与历史解密有关的状态还可能使本机资料不可读。它只能实现“清空设备列表”，不能实现本 ADR 要求
的全新配对环境，因此不采用。

### 只公开 ADR-023 的旧资料独立化入口

现有流程包含版本判断和升级完成记录，直接公开会混淆触发原因，并把旧资料专属状态变成长期产品接口。因此
只复用其内部重建能力，不公开旧资料操作。

## 后果

- `ResetSpace` 从轻量设置清理变为不可逆的设备关系重建，必须作为行为变化发布。
- 产品需要危险确认和新的完成后页面，不能继续跳转到首次设置入口。
- 用户可在不删除本机内容和身份的前提下摆脱无法恢复的旧设备关系。
- 离线即可完成本机重建，但其他设备必须由用户逐一重新配对。
- 应用层需要一个跨重启的完整负责人；Engine、绑定和产品不增加逐步清理入口。
- ADR-023 的独立化实现应成为共同内部能力，减少两套高风险清理流程发生偏差。
- 重置期间需要临时磁盘空间；旧世代采用可恢复的延后清理，因此完成后可能短期保留受管数据，但不得形成
  无归属、无上限或只能人工删除的垃圾数据。
- 当前先修改旧空间、后提升目标世代的实现不满足原子生效要求，必须改为目标世代完整准备和验证后再切换。

## 验收标准

1. 有多个当前、离线、已移除和待处理成员时，成功后公开设备范围只含本机。
2. 旧设备后续连接、重放消息或恢复旧邀请时，不能取得新空间成员资格或触发普通内容传输。
3. 无网络时可以完成本机重置并签发仅在网络恢复后可使用的新邀请。
4. 未完成加入、入站候选、成员移除、待确认消息、后台重试和空间切换均不能阻塞最后兜底，也不能在完成后恢复。
5. 在每个持久阶段终止进程并重启，只能继续同一次重置，最终只有一个目标空间。
6. 并发或重复 `ResetSpace` 调用合并到同一次结果，不创建多个目标空间。
7. 本机历史、已完成文件、一般设置、设备身份和解锁能力在成功后保持可用。
8. 成功后设备列表只含本机，可立即邀请新设备或加入另一空间。
9. 重新配对提示跨重启保留，只在新的设备关系成功建立后清除。
10. `FactoryResetSpace` 继续删除本机资料和身份，行为不因本 ADR 改变。
11. 桌面端必须显示不可逆后果并二次确认；没有产品入口的平台不得被记录为已验收。
12. 接口说明和版本说明将 `ResetSpace` 描述为设备管理重置，不再描述旧的轻量设置清理行为。
13. 在活动清单切换前的每个持久步骤注入失败，旧空间的成员、关系、历史、文件、搜索和解锁能力均保持原样，
    并能重新启动。
14. 在活动清单切换后的每个步骤终止进程，重启后只能进入同一新空间，不得重建安全状态或回到旧空间。
15. 使用包含长期历史、已完成文件、既有活动世代、旧升级记录和多个设备关系的持久 profile 完成重置、重启
    和重复调用验证；仅有全新临时 profile 的测试不能满足本项。
16. 活动清单、数据库、受管文件根、安全状态、设置投影和运行会话最终全部指向同一目标空间；任何可见的
    半成功状态均为失败。
17. 生效前空间不足会保留旧空间并给出明确失败；生效后的旧世代和暂存文件能够在中断后继续清理，且不会
    删除当前活动资料。
18. 资料转换失败与设置保存失败使用不同的稳定错误分类；诊断记录能区分准备、验证、切换、启用和清理阶段，
    且不记录用户内容、文件名、路径、身份或密钥。
