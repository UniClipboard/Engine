# ADR-026：配对尝试采用固定期限、可终止结果与精确成员绑定

- **状态**：已采纳；S0–S8 已实施，2026-09-21 由最终确认提交与双端有界收尾规则修订
- **日期**：2026-09-13
- **取代**：ADR-017 中“正式提交后只能继续到成功”和 ADR-022 中“Prepared 后不能由本机终止或取代”的规则
- **保留**：每次用户明确提交创建独立尝试、邀请一次性消费、正式 Add/Remove 不回滚、成员撤销只保证前向安全
- **相关文档**：`docs/design-docs/decisions/011-reliable-member-revocation.md`、
  `docs/design-docs/decisions/017-pairing-as-workspace-admission.md`、
  `docs/design-docs/decisions/022-user-initiated-join-supersession.md`、
  `docs/exec-plans/completed/2026-09-13-admission-expiry-and-replacement.md`

## 背景

当前加入在 Prepared 后可能因网络中断长期占用本机入口。旧规则要求正式决定后恢复同一尝试到成功，
不能满足用户放弃旧尝试并开始新配对的要求，也把普通网络不可达变成长期阻塞。

两台设备不存在可以同时落盘的最后一步。邀请方可能已经正式应用成员关系，但加入方没有收到最后消息；
加入方也可能已经准备完成，而邀请方的正式决定未知。因此终止不能依赖“先证明远端没有提交”，正式 Add
也不能通过删除本机文件伪装成从未发生。

## 决策

### 一次尝试共用五分钟

Engine 接受一次有效 Join 操作时创建新的 attempt，并记录开始时间。截止时间固定为开始时间加 300 秒。
邀请解析、排队、认证、准备、正式应用和等待确认共同消耗这 300 秒；重试、重连和重启均不续期。

首次认证共同验证 attempt、邀请、加入方通道身份、邀请方通道身份、开始时间和截止时间。首次认证尚不
知道正式 Space 与 Add 事件，因此不能伪造该阶段已经绑定成员资格。

Sponsor 生成候选 Add 后，再以首次契约摘要绑定 Space、精确 member instance 和 Add event。后续确认、
放弃和撤销都引用这组精确绑定，不按 device id 重新寻找“最新成员”。两层绑定均使用固定用途前缀产生
稳定验证字节；修改任一字段或跨 attempt 重放都会得到不同摘要。

### 本机终止不等待远端

加入方或尚未正式提交的邀请方到期后，本机结束该尝试。加入方把稳定失败或放弃保存为可重复发送的终态；
邀请方即使收不到通知，也依据“尚未保存最终确认提交”的本机证据独立终结候选，只丢弃该尝试尚未启用的
准备资料。终止不要求目标设备在线。

旧尝试只有在通知确认、独立期限收尾或明确人工处理后才释放新尝试入口。旧清理未安全结束时，新请求返回
稳定冲突，不能叠加第三条悬挂记录。持久化失败必须报告未完成，不能只更新前台状态。

### 最终确认是正式成员的唯一提交点

邀请方处理 `Applied` 时只保存候选、准备资料和可重放的 `Complete`，不写正式成员历史或安全通信成员集合。
验证 `CompleteAck` 时，以一个持久提交同时写入正式成员、启用安全资料并保存可重放的 `Settled`。因此期限
到达且仍停在 `Applied` 可以安全终结；已经保存正式提交的记录无论是否越过期限都不能回滚。

`Settled` 回复丢失时，邀请方重放原成功结果；加入方重发同一 `CompleteAck` 并取得原结果。正式提交后的
设备只能由用户明确移除。已保存安全终止围栏的旧候选不接受迟到确认，也不能扩大成员同步权限。

设备查询把每条待确认、失败或需处理尝试独立投影。安全终结已经丢弃候选准备资料时，只保留尝试编号和
失败状态，不补造设备名称或身份；这些投影不进入正式设备列表，也不影响已有正式设备使用。

### 状态和过程逐记录密文保存

过程记录继续使用 userdata 内现有独立密文准入仓储，不为每一步创建文件，也不写进正式成员记录。
正式应用时才写成员历史、安全状态与关系投影；正式 Add 之后的取消以 Remove 结束，不能删除 Add。

清理完成后回收大过程材料，保留识别终止 attempt、邀请消费和精确撤销所需的最小记录。保留记录不占加入
入口。没有安全回收边界时不能为了容量静默删除；容量不足应拒绝新的接纳。

### 兼容边界

网络协议版本与本机持久格式分别演进。新版首先提供独立的五分钟尝试契约和成员绑定规范；后续切片接入
认证与准入消息。旧持久字节继续由原版本读取，不能直接给旧布局增加字段。

不支持新规则的对端在消费邀请或正式提交前得到升级提示并结束本次配对，不自动降级到会永久阻塞的旧流程。

升级前记录按持久证据迁移：可以证明未正式提交的候选进入期限收尾；可以证明已经正式提交的记录保留正式
成员并恢复成功重放；无法证明者进入 `NeedsAttention`，停止自动清理并阻止新尝试。不得根据日志猜测、补造
期限或静默删除记录。旧尝试后来到达的消息不得重新占用入口或覆盖新尝试。

## 后果

- 用户可以在普通网络失败后结束本机尝试；新配对必须等待旧尝试安全收尾，不要求旧设备重新上线。
- 系统需要持久保存终止围栏、未知远端提交责任和邀请方确认状态，并允许受限的迟到确认。
- 一端已经本机完成、另一端放弃而永久失联时，两端可能暂时保留不同看法；系统不声称全局同时撤销。
- 精确撤销必须复用现有完整成员移除流程和后续安全效果，不能只删设备关系。
- S0–S8 已接通公开结果、双端共同期限、任何阶段的本机终止、精确撤销、跨 Space 隔离、可靠放弃投递和有界恢复索引。真实设备与产品前台接入仍需由各产品仓单独验收。

## S0 验收

1. 公开结果能区分 Pending、Rejected 与本机 Terminated，并区分取消、到期和被新尝试取代。
2. 设备结果包含可选的等待确认、未确认和已确认状态；缺少新记录的旧成员保持无值。
3. 配对确认状态不改变成员同步资格。
4. 新尝试契约严格要求 300 秒；缩短、续期、溢出和相同双方身份均被拒绝。
5. 固定验证向量绑定 attempt、邀请、双方通道身份和时间；修改任一项都会改变摘要。
6. 正式成员绑定引用尝试摘要、Space、member instance 和 Add event；旧 attempt 不能匹配新 attempt。
7. 新契约的调试输出不泄露身份或时间，旧 V1 准入测试继续通过。

## S1 验收

1. Join 从 Engine 接受操作起只有一个五分钟期限；第 299999 毫秒仍进行中，第 300000 毫秒本机到期。
2. 正式决定前的取消不等待网络；旧尝试到期或被替换后不再占当前加入入口，新尝试使用独立身份和期限。
3. 尝试时间线和终止原因随现有准入记录整体加密保存，关闭并重开仓储后仍可查询；旧记录继续读取且不伪造期限。
4. 新意图和旧结果在同一个仓储事务保存；注入写入失败时不会出现一半替换。
5. 准确截止由唯一成员维护运行期唤醒，恢复先处理本机到期再尝试网络；短码只解析一次且解析耗时计入原期限。
6. Prepared 及以后不在 S1 本机结束，继续等待后续精确撤销切片。
