# 冷启动维护

## 责任与顺序

HistoryMaintenanceRuntime 是历史维护的完整负责人，调用方仍只调用一次启动和一次关闭。
启动先完成文件引用安全检查；配额清理和保留策略在同一受管后台任务继续执行，
不再让正常服务等待整轮全量维护。首次文件检查失败时跳过该轮删除，后续周期重新检查。
周期维护仍按文件检查、缓存清理、保留策略的顺序串行执行，不产生并行清理队列。

关闭可以打断周期等待，但不能丢弃已开始的清理。显式 shutdown 等待任务完成；
不存在新旧两条启动维护路径。旧测试文件此前未被编译入口引用，本次接入真实测试模块。

## 安全读取

文件安全检查的读取能力归 Application 历史模块所有，通过 HistoryFileReferencePort 表达。
Infra 用表示 ID 的稳定游标分页，在数据库中筛选 URI-list MIME 或 files 格式，
仅提取这些候选的密文清单，沿用 BlobCipherPort 与事件/表示 AAD 认证解密。
不根据历史分类跳过检查，因为旧分类回填可能面对密文而不准确。

普通文本、图像正文不会被该检查解密。无内联清单的表示保留原先的跳过语义。
Application 仍决定哪些路径属于受管缓存，检查真实存在性，先完成所有扫描再调用既有
条目删除流程。读取或认证失败不会把密文当作 URI，也不会触发该轮部分扫描后的删除。
entries_scanned 现在表示实际检查的文件候选条目数，不再包括无关正文条目。

## 搜索版本

维护查询和实际读写使用同一个保护策略版本选择。V3 使用 v12，旧策略仍使用 v11，
避免成功重建后再次被错误判定为过期。没有删除旧格式兼容能力或绕过搜索完整性检查。

已激活的 V3 布局即使还有上次升级的清理记录，也不再次声明需要升级；记录的核验、
清理和失败关闭仍完整执行。这个产品标记不作为跳过恢复或校验的条件。

## 验证

- 真实 SQLite 和认证密文：5000 份无关正文、2 份文件清单，只解密 2 份；游标分页正确，损坏清单被拒绝。
- 首次配额清理阻塞时启动仍可完成，但关闭等待该清理结束。
- 文件引用检查阻塞时启动继续等待；检查失败后不执行删除，并由周期任务重试。
- 多组 V3 搜索的维护期望版本与实际索引版本一致。
