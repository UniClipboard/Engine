# Entry thumbnails

Desktop list and search consumers call `Operation::ReadEntryThumbnail(HistoryEntryInput { entry_id })`. Success is `OperationResult::ThumbnailRead(BinaryResourceSummary { bytes, media_type })`. The media type is `image/webp`. The standard generator uses a maximum edge of 128 pixels and preserves aspect ratio. The operation completes synchronously; it does not create a queryable background job.

The Application resource module owns resolution, generation, caching, and final ownership validation. It reads the existing committed entry resource snapshot. Only the selected preview representation may supply image bytes. Search results do not need a representation ID or a thumbnail URL. The entry ID from search is sufficient.

An existing stored thumbnail uses the existing authenticated blob reader. If thumbnail metadata is absent, the owner reads the preview's authenticated inline bytes or blob bytes and generates a thumbnail. This repairs reads for historical entries and background generation failures without changing original content, representation identity, or persistent metadata. Derived thumbnails generated by this operation are held only in a 4 MiB weighted process cache. Restart discards that cache. Eviction causes regeneration on a later read. Persistent blobs and inline data continue to use the existing encryption adapters.

The owner validates the current entry event and preview again before returning any bytes, including cache hits. A concurrent deletion or replacement cannot use the cache to bypass current ownership. A read that completes its final validation before a deletion may succeed. A later read must fail. Cache entries for deleted representations remain bounded and inaccessible until eviction.

| Result | Code | Category | Retryable | Host behavior |
| --- | --- | --- | --- | --- |
| Entry absent or deleted | 1462 | NotFound | No | Remove or hide the image. |
| Generation slot occupied, or source still staged/processing | 1465 | Unavailable | Yes | Keep a placeholder; retry with bounded backoff only while visible. |
| Non-image, missing preview, lost/failed source, or source byte limit | 1466 | Unavailable | No | Keep a placeholder. |
| Storage, authentication, decoder, or task failure | 1464 | Internal | No | Keep a placeholder; expose the sanitized failure through normal diagnostics. |

A stored thumbnail whose metadata exists but whose blob is unreadable returns 1464. It is not silently replaced after an authentication or storage failure. Missing source blob files also return 1464. Decoder limits and invalid encodings return 1464. No error response contains source bytes, paths, filenames, or internal error messages.

On a cache miss, one Application request may read or generate a thumbnail at a time. The request does not wait in a queue holding a source image when the slot is occupied. The shared Infra generator additionally permits one decode/resize at a time across foreground and background thumbnail calls. It runs CPU work on `spawn_blocking`. The blocking task holds its permit until it ends, including after caller cancellation. No detached Application workflow or persistent job is created.

On-demand source bytes are limited to 32 MiB. The generator limits each dimension to 8192 pixels and configures the image decoder allocation limit to 64 MiB. Decoder allocation limits are not a total process RSS bound. Codec working memory, conversions, source buffers, output buffers, existing background original-image conversion, and allocator retention are additional costs. Existing original-image conversion is outside this operation's memory limit.

## Desktop integration

1. Add an authenticated binary route whose input is an entry ID.
2. Invoke `ReadEntryThumbnail` once through the stable `uc-engine` entry point.
3. Return the bytes with their media type. Do not send JSON-encoded image data to list items.
4. Use this route for history-list and quick-panel images, including entries returned by search.
5. Keep original-resource reads for explicit original-image actions.
6. Bound visible requests and retries. Cancel requests when their items leave the view.
7. Clear object URLs and host caches when content authorization is revoked.

Do not fall back automatically to original-image loading after any thumbnail error. Engine does not publish host HTTP URLs. The host owns authentication, URL construction, HTTP status mapping, and frontend resource lifetime.

## Reproducible acceptance

Run from the repository root:

```bash
UC_TEST_ARTIFACTS_DIR="$PWD/target/test-artifacts/entry-thumbnails" \
  just cargo test -p uc-engine --test host_contract \
  entry_thumbnails_use_public_identity_and_survive_restart --locked -- --nocapture
```

The acceptance uses public Engine operations with a real isolated encrypted profile. It emits `result.json` and `thumbnail.webp`. It covers blob-backed and inline images, source-byte preservation, cache hits, concurrent misses, absent derived metadata, restart, invalid encodings, decoder dimension limits, deletion, and unavailable previews. Synthetic fixture mutations affect only the test profile. It does not prove Desktop HTTP routing, GUI image decoding, GUI RSS, scrolling, or object URL release.

The Desktop observation of a missing thumbnail after 60 seconds is separate evidence. Its retained JSON has no failing representation state, worker error chain, or spool/queue snapshot. The precise cause cannot be identified from that JSON. The confirmed background path marks an original BlobReady and deletes its spool before thumbnail generation; a later thumbnail failure is logged but is not repaired by the startup spool scanner. On-demand generation removes that failure path as a prerequisite for list rendering.
