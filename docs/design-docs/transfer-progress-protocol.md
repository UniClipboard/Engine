## 显式旧协议的完整出站通知

[完整通知负责人](../../crates/uc-application/src/transfer/progress/producer.rs)只在受管连接实际协商为`/1`时使用
[兼容流程](../../crates/uc-application/src/transfer/progress/producer/legacy.rs)。调用方继续提交原Contact、Update或终态动作，
不汇总单项、不拼装单向流；`/2`上的拒绝、畸形帧、超时或授权失败不会触发旧协议发送。
登记与任务核对仍对旧协议明确返回Unsupported，不伪造binding、挑战响应或结果ACK。

兼容流程读取同一原接收负责人的`ProgressSnapshotProviderPort`，用原计划、描述、内容修订和分页覆盖规则取得完整事实，
再由[Core批次通知规则](../../crates/uc-core/src/file_transfer/progress_summary/rules.rs)生成粗粒度状态和字节汇总。
仍有等待、传输、重试或本地处理项时保持InProgress；全部真实完成才Completed；全部结算后，失败优先于取消，
末项成功不能覆盖前项失败。取消原因一致时保留原原因，混合原因归Unknown；任一总量未知或不可表示时保持未知，
字节总和不可表示时拒绝本轮，不截断成较小的已完成批次。

读取、等待实际本机能力与单向发送共用原截止、取消及当前成员／会话围栏。旧单向流使用原`ConnectionLease`与工作许可，
成功路径完成原帧及传输结算后才释放，不建立原生连接缓存或独立业务重试循环。已经开始的本机读取监督到实际结束；
取消、到期或原尝试退休后不补发旧帧，读取失败保留source。

旧终态帧即使传输结束，完整终态动作仍返回Unsupported，表示无法取得新版业务采用确认；原监督器停止该结果补发，
不记作已确认送达。Contact与普通Update可以完成旧一轮传输，不产生业务ACK。
当前已证明真实专属profile的批次通知、读取边界，以及实际接收失败清理后的最大原始计划汇总。
生产Router／接收hook已接线，完整新旧设备矩阵继续按执行计划完成。

## 显式旧协议的保守入站通知

[旧版入站动作](../../crates/uc-infra-p2p/src/network/iroh/transfer_progress_v2/legacy.rs)仅接受实际协商为`/1`的受管单向流。
旧34字节帧与精确FIN共同使用原交换期限；损坏、截断或尾随字节不开始Application采用，
FIN等待后重新核对原连接、当前成员与会话资格、取消及期限。`/2`连接不能通过此动作解释为旧协议。

旧帧缺少尝试、producer、修订及逻辑项关联，因此只把认证设备和源条目交给同一投影负责人的
`ProgressUnattributedReceiverPort`完整动作。网络消息不能创建意图；只有原完整发送动作已经接受且仍保留、
尚未被登记或完整查询确认的意图，才能显示结果未确认。旧字节、总量和粗粒度终态不进入逐项事实，不刷新有效联系。

[Core登记围栏](../../crates/uc-core/src/file_transfer/progress_registration.rs)拒绝这类通知覆盖已登记或查询确认的任务；
查询没有通知binding、连接更换后保留描述时也一样。无关联通知不消耗待完成挑战；后续真实登记与有效活动仍可正常采用。
[原接收负责人](../../crates/uc-application/src/transfer/progress/receiver_unattributed.rs)在同一投影锁内保存未确认程度，
注册表沿用原删除、退休、封口及变化发布围栏。重复旧通知不重复发布，未知或已删除意图不被重建。

已开始的Application能力继续持有同一单向流工作许可直到实际结束，取消或网络期限不遗弃本机采用；失败保留完整source。
此动作不发ACK，不据传输FIN确认业务结果。生产节点已注册两个进度版本，保守投影经同一Application运行期和稳定宿主快照提供；完整新旧矩阵仍按执行计划验收。

## 帧边界和观测载体

一帧为：

```text
UCP(3 bytes) | version=2(u8) | body_length(u32 BE) | body
body = context_present(u8) | [context_length(u16 BE) | traceparent] | message
```

完整帧最多 64KiB，正文长度必须为 1–65528；读取方先检查 8 字节头部，再分配正文。
`context_present` 只能为 0 或 1，存在时 traceparent 为 1–256 字节 UTF-8，长度核验先于载体分配。
复用现有 `WireTraceContext`；这里只承载字节，Infra 才负责从当前 span 注入以及认证后采用有效上下文，
Application 消息、Core 规则及 Engine facade 不获得观测字段。载体的 W3C 格式与父节点合法性不由此 codec 授权。

`decode_frame` 必须消耗整个输入，拒绝尾随字节；`read_frame` 每次读取一个有界帧，可在同一双向流顺序读取登记握手的多帧。
完整交换负责人限制消息顺序、帧数、最终流结束与截止时间，不能将合法握手多帧误作尾随字节，也不能把任意后续帧当成合法业务消息。
编解码不负责拨号、刷新期限、重试、成员授权、结果采用或自动生成 ACK。

## 身份、游标及结果

所有定宽整数为大端。ID 只在本次协议交换内流转，日志和普通 Debug 不展示其原值。

| 结构 | 线上字段顺序 |
| --- | --- |
| TaskScope | source_entry(16)、receive_attempt(16) |
| ProducerDescriptor | producer(16)、owner_revision(u64)、TaskScope、item_count(u16) |
| LogicalItem | kind(u8)、原始位置 index(u16) |
| ActiveProgress | LogicalItem、round(u32)、sequence(u64)、bytes(u64)、可选 total、phase(u8) |
| TerminalResult | LogicalItem、round(u32)、sequence(u64)、result_revision(u64)、bytes(u64)、可选 total、outcome |
| 可选 total／snapshot_revision | present(u8)，为1时跟 u64；None 与 Some(0) 不混淆 |
| SnapshotPage | snapshot_revision(u64)、offset(u16)、total(u16)、count(u16)、逐项类型及记录 |

消息 tag 和原因码以模型中的声明为唯一数值清单。当前合同包含：

- Register → Challenge → CurrentDescriptor → Bound 所需字段。Bound 回显精确 descriptor 和挑战并提供 binding；codec 不判断挑战是否新鲜、producer 是否已退休或描述是否权威。
- Update 与 Contact 绑定 binding、TaskScope 和登记修订。Contact 有独立新消息序号，不增加字节；实际有效性和期限由 owner 判断。
- Terminal 与 TerminalAck 绑定同一任务并携带完整 TerminalResult，避免只确认条目 ID 或错误结果版本；有 ACK 帧类型不等于结果已经采用。
- Query 携带挑战、源条目、可选预期 attempt、分页 offset 与可选快照修订；QueryResult 区分 Current、Superseded、NotRetained、Unsupported、AccessDenied。
- Rejected 仅含固定原因；实际 IO、存储或解析错误不由 codec 伪造为 NotRetained／Unsupported。

### 完整身份与精确回执

设备身份取自已准入连接，源条目和原始逻辑项取自原意图及原接收权威；登记、活动和终态共用同一权威与围栏。
producer 通过当前连接的新挑战和精确 descriptor 关联 binding，不在每个 ACK 重复增加 producer 字段。
ACK 必须保留 binding、源条目、attempt、owner 修订、逻辑项种类与位置、round、sequence、结果修订、
字节数、total 的存在性及数值、最终结果与原因。None 与 Some(0) 分别比较，不能归一化后冒充精确确认。

专属 progress profile 的真实 Iroh 组合在 Application 采用后覆盖21个回执字段／边界场景，
并对当前14种完整结果原因逐一核对线上值。错误回执不回滚接收事实，原完整动作的正确重试仍可获得精确ACK；
[字段证据与验收范围](../exec-plans/active/2026-10-24-transfer-progress-connectivity-feasibility.md#阶段1身份与精确ack校验)
分别列出纯规则、Application和真实连接证据，不把本项等同生产迁移。

### 明确拒绝与错误来源

`Rejected.challenge` 是本轮关联值：登记尚未发出Challenge时回显请求source_entry，已发出Challenge后回显本轮nonce；终态回显请求binding；查询继续回显Query challenge。发送端先核对关联，再确认响应FIN，才采用固定拒绝原因。错误关联为Stale，尾随字节或畸形帧为保留原来源的协议错误，不转成Busy、UnknownTask或旧版不支持。

服务端只有明确业务拒绝才发送Rejected：AccessDenied／Stale／Busy／UnknownTask分别保留原因；非法逻辑范围和冲突终态使用既有InvalidScope码。冲突不会产生TerminalAck，已采用结果保持不变；远端InvalidScope归为计划／范围拒绝。IO、时钟、存储来源或帧解析失败继续保留错误链，不伪造业务拒绝。生产Query提供方使用原实际接收目录。

早期登记拒绝先发Rejected，等客户端不再发送描述并结束请求后再发送本端FIN，避免客户端提前释放发送半流使服务端丢失拒绝结果。已经完整读到请求FIN的交换不重复消费结束边界；每次仍检查当前准入及原预算，不重建期限。
等待FIN之前和实际读到FIN之后均核对同一原连接的当前准入及原预算。若等待期间撤销或会话退休，不得再开始Application采用或快照读取；已经开始的本机工作仍由原负责人监督到真实结束。

Application区分带source的Malformed与暂时Exchange失败：前者和明确访问拒绝停止该结果补发，真实IO失败及Busy只使用原有剩余预算。准入失败保留ConnectivityError分类和完整source，不再统一包成可重试的普通交换失败。这些规则不改变本地下载实际结果，也不增加协议版本、帧字段或原因码。

业务接收设备来自认证连接，不信任自报设备名或地址；Space／会话世代绑定在完整负责人上下文内，不由源条目 UUID 授予访问权。
来源设备与实际 blob provider 可以不同，这些线格式字段不将二者合并。

## 分页与拒收边界

一个描述有 1–1024 个逻辑结果项；目录结果按完整单元描述，其 index 必须为0。
一页有 1–64 项，`offset + count <= total <= 1024`，total 与对应 descriptor 的 item_count 一致。
页内不能重复 LogicalItem；item index 必须小于1024。读取方检查 count 后才创建记录集合，不能按未验证数量分配。
后续页请求必须携带快照修订；首批请求可没有修订。
同一快照按不可变原始逻辑计划的顺序分页，offset 是计划中的位置；页内项种类与索引须逐位匹配该计划。

codec 只检查当前帧结构。跨页修订一致、页覆盖完整、原始清单身份匹配、跨页重复、旧尝试和旧轮次隔离，
均由后续完整负责人验证，不能仅凭一页已解码就宣称整批结果已确认。
网络字节计数与真实交付状态的业务一致性也不能交给 codec 猜测。

未知 magic／版本／tag／原因码、截断、尾随字节、非法 option、超限正文、超额页计数、非法目录索引及页内重复均拒收。
IO、UTF-8 和未知数值错误保留具体 source；错误显示及 Debug 采用固定分类，不输出原始帧、身份或载体正文。

## 验证及当前限制

```bash
just cargo test -p uc-sync-protocol --tests --locked
```

当前有36条无观测载体的完整消息／状态／原因固定向量和1条带载体向量；15个新增用例还验证每条向量的全部截断前缀、
额外字节、页计数、精确帧大小边界、最大合法页、未知／零总量、原因映射、变体级固定错误分类及完整来源、载体界限。
旧协议测试和旧 golden 向量继续执行。

Core 的 `ProgressRegistration` 现在提供单个已授权设备／源条目的纯登记围栏。
连接世代是完整负责人从实际连接分配的本地单调值，不能取自帧；替换连接保留最近描述但退休原 binding 和挑战。
同连接固定 producer；同 producer 重连仍检查 owner revision，较低修订拒收，同修订的不同 attempt／计划也拒收。
新 producer 必须换连接并响应新挑战，不能按 UUID 大小或跨进程 revision 排序。
挑战单次消费，新挑战淘汰先前未完成挑战；通知还须精确匹配世代、binding、源条目、attempt 和登记修订。
规则只返回身份判定，不代替逻辑项／轮次／序号校验、终态采用和 ACK。
完整负责人必须按 Space 世代／认证设备隔离实例、生成不复用的挑战及 binding，并将迟到交换保留在原连接世代；
不能因帧晚到而重新激活旧连接，也不能在普通重连时重建规则丢失修订。

Producer在完整登记或通知动作入口、读取本地权威之前冻结原连接请求，连接阶段只消费该请求。
本地读取跨过会话退休时，旧动作不能在返回后重新取得新会话的拨号资格；原单轮截止和取消责任保持。

真实双端登记原型和未覆盖边界见[阶段 0 证明](../exec-plans/active/2026-10-24-transfer-progress-connectivity-feasibility.md)。
Application `transfer/progress` 现在提供从原始发送意图授权的单任务登记及终态采用能力。
Infra `transfer_progress_v2` 有界入站适配取得真实连接对端身份，等待完整描述／终态采用成功后才写 Bound／TerminalAck；
帧结束、传输 FIN 或事件排队均不能代替采用。精确重复终态可再次确认，冲突不得覆盖已有结果。
请求末尾额外字节在采用前拒收；取消或原 deadline 到期只停止后续网络，已开始的 Application 采用仍持流使用权至实际完成。
取消／过期后已采用结果继续可读，后续精确重复仍可确认，不承诺跨重启 ACK。

此入站能力已接入生产Router的登记、Update、Contact、终态和完整查询交换。
当前接收权威从原接收负责人在持久 CAS 接受后交接，每次新挑战须实时读取同一运行期 catalog，不能返回旧任务闭包捕获的描述。
来源条目提示由既有已认证激活消息保留；没有提示的旧 bulk 只接受一致的 blob 来源身份，不能按内容摘要猜测。
原始计划和 producer／revision 不依赖保留文件路径或原始包，目录按完整单元；删除、清空和会话封口退休旧关联。
出站登记由 Application 负责，Challenge 到达后通过此权威生成 CurrentDescriptor，Bound 回来后再核对最新描述。
已结算结果通过 Application `ProgressExchangeService::submit_settled` 一次提交通知意图：
输入携带产生结果的原 attempt 和逻辑项，当前接收权威原子领取并返回完整冻结描述；
同一当前尝试／项只能领取一次，重复 handoff 不重置领取标记。标记随有界当前任务退休，
不创建独立的永久历史或持久化 outbox；终态缓存淘汰、ACK、时钟故障及重连均不能重新领取预算。
本机提交不等待网络，成功保留只表示有界运行期通知意图，不改变原本地结算结果。

`ProgressExchangeWorker::run` 是全部实际单轮 future 的唯一监督者。
保留终态全局最多 256 项／每端 64 项，满时按原生成时间淘汰最老项；
交换等待全局最多 64 项／每端最多 16 项，当前调度每端只放一个候选，
由保留记录的有界对端索引轮转补队，未获额度不消费补发时点。
实际在途全局最多 4 轮／每端 1 轮，原 600 秒期限和 8 个补发时点由 Core 纯规则决定；
恢复机会只使用剩余时点，挂起后不追补过去轮次。每轮子取消令牌与保留项令牌分开，
单轮五秒耗尽可在原剩余预算内继续补发。淘汰、过期或关闭仅禁止后续网络，
已开始的本机工作仍由同一 worker 等到真实结束；活动额度和关闭完成均不得提前归还。
调用方须持有并等待 worker 的运行 future，后续生产组装不得将其遗弃。

单轮由 `ProgressTerminalRoundPort::report_settled` 接收冻结描述和原绝对截止，
`TransferProgressProducer` 预检与登记后都核对同一描述，不能把迟到结果重新贴到新绑定。
当前登记、终态发送和精确 ACK 共用原五秒预算；返回成功必须已经收到完全相同的采用回显，
并在实际连接保留读取后再次核对当前权威。只有可恢复网络失败使用剩余时点，
过期身份、协议拒绝和关闭停止该项；失败保留原 source chain。
同一可信经过时间读数供保留和各轮使用，任一读数不可用或回退切换连续性世代；
旧世代的各轮 clock lease 及保留预算永久退休，不能因下一次读数恢复而复活。
并发提交与 worker 使用同世代高水位，迟到的旧采样不使新提交误判回退，也不淘汰恢复后的新预算。
经过时间能力由该 Application 模块消费，Core 只保留纯预算规则。原生 IO 每次 poll 前检查同一预算；
已开始的本机准入或保留读取仍监督到真实结束，超时／取消只禁止后续网络，实际工作结束前不归还许可。
当前同进程真实 Iroh 双端已结合独立 Application 接收 fixture 进程验证文件、空目录、乱序、重启及实际失败结算后的监督投递；
另有共用本机 Endpoint 的两个已认证对端证明：一端采用卡住不妨碍另一端精确 ACK。
该多端原型使用各自受管连接 fixture，不代替生产全局连接组装与平台挂起验收。生产Router和完整运行期另有接线验证。

完整生产终态链路、补发、成员撤销、Router 迁移、
独立进程网络及平台矩阵继续以第八片执行计划为准。


## 完整单轮快照读取

Application `TransferProgressSnapshotReader` 从已授权原始计划及当前登记描述开始，
在调用方提供的同一个原绝对截止内连接并依次读取各页。每页独立新挑战，后续请求绑定首个快照 revision；
Core `ProgressSnapshotCoverage` 核验完整 descriptor、总项数、连续位置、原始项身份与同一快照 revision。
重复、跳页、跨页重复项和修订混合均封口；只在最后一页通过后返回完整快照。
完整快照仅表示本次读取完整，不表示所有项已经实际成功，也不直接修改已有投影。

临时结果只预留原始计划的最多 1024 项，各页最多 64 项；核验失败或IO失败丢弃本次暂存。
读取方不自行创建查询队列／补发循环或重新启动五秒期限；该 round 由同一个 progress 监督器的等待队列与实际活动额度调度。
已开始的本机准入／连接保留读取仍等待到真实结束，并持本页流许可；原期限到达后不再开下一页或返回快照。

明确 Current 才参与此已登记任务的覆盖核验；Superseded 只返回同源的新尝试描述。
该描述与登记共用Core修订规则：同producer不能回退，同一修订不能改变描述；跨producer不比较修订大小。新尝试可以有不同计划数量，不从旧原始计划拼装新尝试的完整快照。明确 NotRetained、Unsupported、AccessDenied 与 Busy 分别返回；
读取失败、损坏、错误挑战、请求／响应尾随字节和经过时间到期保留错误，不伪装为资料缺失。

当前阶段 0 证明使用实际 Application 接收 fixture 进程从最大 V3 清单 CAS 交接的 1024 项身份，
经真实已认证受管 Iroh 流读取16个64项页。状态载荷为合成fixture，用于验证映射、覆盖和资源边界；
不能据此声称1024个文件实际交付、生产查询权威已接线、旧轮次状态已采用或完整核对业务已完成。
生产Query入站与实际接收结果读取已接同一Application对象图；平台矩阵及各生命周期验收继续按执行计划实施。


## 查询与终态共享监督

完整查询在入队前同步冻结原连接请求，并交给监督器一个尚未poll的读取future；只有取得实际额度后才执行IO。
首个准入者的原截止交给被保留读取，其他观察者仍遵守各自原截止；取消继续由原监督器管理，单个观察者退出不结束其他人仍需的读取。
去重或过载丢弃未启动的future，不在调度时重取会话或五秒预算。
旧查询跨会话后停止且不采用，新一次显式核对仍可取得当前会话，不能把reader整个寿命永久绑定到旧会话。

`ProgressExchangeService::read_snapshot` 是本运行期一次完整快照核对的提交与等待入口，
与 `submit_settled` 共用唯一 `ProgressExchangeWorker`、全局4／每端1实际在途和全局64／每端16等待队列。
查询直接进入同一队列，满时返回 Busy，不再建立第二个查询队列；终态缓存256／64仍独立保留。
同端已排队终态优先于普通查询，不同对端仍由同一个轮转队列安排。

同设备、完整登记描述及相同原计划的并发查询合并为一轮，结果通过同一个watch值共享；
单个合并查询最多16个并发观察者，超额返回Busy，不积累无限waker或等待者列表。
单次查询的原五秒从提交采样开始，覆盖排队、连接和所有页；重复请求不刷新该期限。
每个观察者也保留自己的原五秒预算，较早采样但较晚准入的调用不能借后到请求延长等待。
取消一个观察者只退出自己的等待，其他观察者继续；最后观察者离开才停止该次后续网络。

过期、时钟世代失效、停止或最后观察者离开均可封口等待结果；若实际round还在执行，
该活动记录、每端名额及全局名额仍保留到实际future结束。此时同目标的新调用只能观察该封口结果，
不能重新起预算。完整结束后用户可以再次显式核对，不由此重建终态补发预算或自动重新下载。
返回结果前再次核对原时钟，迟到成功不得替换已封口结果；已有实际接收结果不随通知／查询失败回滚。
关闭先封口队列和观察者，再等待全部实际round结束；调用方必须等待worker返回。

以上共享调度能力已接生产Router、实际接收结果查询port及发送投影采用围栏。
真实Iroh证明覆盖成功、原期限耗尽和最后观察者取消：本机成员准入读取暂停期间调用已经结束，
该round仍在监督范围内，另一认证对端仍能完成精确终态ACK；读取真正结束后才完成worker关闭。


## 恢复机会的生产接线

Application在启动Space运行期之前订阅既有对端可达性事件，将观察者交给同一ProgressRuntime监督。
Online只向对应对端的原交换服务提交一次机会；Offline和Unknown不授予资格。提示丢失时合并一次全局机会，
不据此声明对端在线、恢复文件任务或修改逐项事实。原worker仍核对当前授权、单项不重叠、原时点及绝对保留期限，
重复机会不能增加次数或延长任何期限。停止与事件流意外结束由同一运行期监督，不新增Engine步骤、持久队列或补发循环。

## 中间值提交与采用

`ProgressExchangeService::submit_live` 接收当前接收尝试的单项活动值，不等待网络。
Application 保留每项最新值；中间缓存独立限制为全局256项／每端64项，不占终态保留额度。
同一任务的全部逻辑项共用最多5Hz资格；从实际单轮结束到下一次中间值开始至少200毫秒，
避免登记或本机读取延迟后集中发送。终态不受此冷却约束，但仍等待同端旧轮实际结束并共用4／1活动额度及64／16等待额度。
中间候选在终态之后排入同一队列，每端最多一个；没有独立后台发送任务。

为防缓存淘汰重置序号和发送资格，另保留最多256／64个当前任务的有界元数据，
每任务只保留原始计划内最多1024个单项已见状态和一个发送时点，不保存历次消息。
元数据满时只回收权威已退休的任务，不能为接受新scope淘汰仍有效任务的节流历史。
时钟连续性失效退休旧待发值；恢复后的新值保留已见序号并重新等待200毫秒资格。
普通值不按终态时点表自动补发；新值或显式网络恢复可提供机会，不能重置任务节流。

Core `ProgressItemProjection` 统一活动及终态规则：同round序号前进、字节不回退，
已知总量在同round不能改变或退回未知，字节不得超过已知总量；新round允许真实回落。
终态由独立result_revision结算，同round终态不能因活动序号数值较大而丢失，旧round终态拒收；
采用后拒绝所有活动值，重复终态幂等，冲突终态保留既有结果。
接收投影的完整快照只通过同一个items字段返回活动或终态。

源权威的运行期notification_closed集合在终态通知被一次性领取时封口该项，
用于拒绝迟到活动值，不表示通知已送达；重复交接、终态缓存淘汰或ACK不能重新打开。
新尝试有新描述和新集合，旧快照不会因集合更新被追溯修改。
`TransferProgressProducer` 在原五秒内完成当前登记和Update发送，并在本机连接保留读取后复核当前授权。
入站按认证设备、连接世代、binding和当前描述核验完整帧及结束后交给同一采用负责人。
Update不产生业务ACK；流结束仅说明本轮传输结束，不证明文件输出或业务完成。
Contact及失联判断见下节；生产接收回调和宿主视图接线仍由后续任务完成。


## 任务联系与结果未确认

原接收尝试接受后可通过 `ProgressExchangeService::track_current` 跟踪等待状态；
`submit_live` 同样建立该有界跟踪。重复跟踪不刷新首次10秒时点，使用同一256／64任务元数据。
没有其他新通知时，Contact在原10秒到达后进入同一个交换队列，仍使用4／1活动、64／16等待及单轮五秒约束。
每任务独立递增联系序号，不借用逻辑项round／sequence；原任务保留期间不因中间缓存淘汰重置。
前轮未实际结束不启动下一轮；延迟结束后从实际结束计算后续10秒，不追补过去联系。
全部逻辑项终态后停止联系，终态仍按原补发算法独立通知。

发送意图的 `TransferProgressReceiver` 创建时接收经过时间能力并建立首次60秒期限。
完整快照返回 Waiting／Live／Unconfirmed／Settled；联系不能修改items中的字节或真实结果。
只有已采用的新活动、独立新Contact或新终态刷新联系，重复／旧序号、登记、重连及精确ACK不续期。
原期限到达只显示结果未确认，匹配的新有效状态仍可恢复Live；全部真实终态永久保持Settled。
同一attempt更换producer只重置独立联系序号，不刷新时点或重开终态；新attempt按新身份清理旧单项投影，登记本身也不续期。

同一连续性时钟规则同时供交换与联系视图使用。不可读或回退令旧联系未知，
完整快照的freshness错误保留完整source chain，items中的已知事实仍可读；
仅时钟恢复或重复帧不能恢复确认，必须收到当前身份的新有效通知。
实际已结算的全部终态无需时钟证明；旧世代交换迟到结束也不能删除新世代待发状态。

Contact不产生业务ACK；独立正常流结束后本轮才结束，认证、采用及当前权威后置核对沿用Update边界。
此能力仍未组装生产Router、原下载回调和稳定宿主视图，也不代表真实设备挂起矩阵通过。


## 全局发送投影与原意图生命周期

Application `ProgressIntent::accept` 是等待投影的唯一创建入口；原发送负责人先从同一注册表冻结本机所有权世代，
只由原完整发送负责人在接受原发送意图后调用。认证入站的登记、Update、Contact和终态只查找已有授权；
网络消息、首次字节或相同内容不能创建投影。重复接受同设备／源条目和同一原计划不刷新原60秒，
同一意图的计划不能悄悄替换；完整快照在首条通知之前已经返回等待项。

Core `ProgressProjectionCapacity` 按原意图接受顺序保留全局256／每端64个当前投影，每投影最多1024项。
每端超额只退休该端最早投影；否则全局超额退休全局最早投影，更新、查询及重连不改变顺序。
淘汰只释放运行期投影，不取消文件动作或修改接收侧真实结算、通知领取和补发预算。
删除单个关联、整个源条目、对端退休、清空和会话封口都由注册表直接完成，调用方不枚举内部对象。

被退休的单任务对象立即封口并释放原计划和项状态。已启动挑战仍等待实际返回，
但返回后必须再次核对原实例仍有效；不能把旧结果交给同键新意图，也不能迟到发布Bound。
登记采用直接复用Core交换准入规则，最多全局4／每端1，不保留登记等待者；超额明确Busy。
此采用额度不创建额外网络交换，实际IO仍由受管入站流和原截止负责。
原实例淘汰或关闭不提前释放其登记额度，关闭只发起封口，生命周期future返回才表示已启动采用全部结束。

`ProgressProjectionWorker` 只驱动投影变化，不发送网络或另建心跳循环。
60秒未知由该完整负责人发出变化提示，宿主不用自行推算期限；
没有计时变化的未知／全部终态投影停止时钟轮询，新有效通知或新意图再唤醒。
变化提示最多128条，发送无订阅者是正常情况；提示丢失后可从注册表重读全部仍保留的完整快照。
发布修订只前进，迟到发布不能令已发布修订倒退或使重复终态重复发布。

真实Iroh原型已通过同一注册表采用等待意图、Update、Contact和终态；
另用真实流暂停挑战，验证替换／关闭后的迟到描述不能重建绑定，关闭等待原交换实际结束。
这些fixture仍使用现有Clipboard准入profile，不代表专属progress profile、30秒／16连接保留或生产Router已验证。
生产原发送动作、节点、稳定宿主事件、历史删除、成员退休及再次发送已接同一Application对象图；完整生命周期和矩阵继续按执行计划验收，不把单项验证当作整片完成。


## 专属连接profile与空闲保留

`ConnectivityProfile::TransferProgress` 使用实际Iroh backend和既有ConnectivityManager，
只发起一次原生拨号；`/2`与兼容`/1`在同一次TLS握手提供，不使用通用交错拨号器创建并发影子连接。
Iroh使用服务端ALPN偏好；生产`ProtocolRouterBuilder`统一将已注册的`/2`排在`/1`前，
无论handler注册顺序或客户端提供顺序如何，双方都支持新版时选择`/2`。调用方只注册实际可用的handler；
旧端只支持`/1`时仍协商原单向帧，不改变旧字节，也不因此切换LAN兼容线。

Application `transfer_progress_connectivity_policy` 是组装所用策略入口：
每端每方向最多1连接，包括拨号、实际本机结算和关闭尚未结束；
主动流每端1、入站流每连接1／会话4，共享等待16／64及拨号4的有界能力。
未知入站4、识别后每端1采用和原5秒截止；旧`/1`首流为单向，不能套用只等待双向首流的配置。

进度grant核对实际协议，拒绝把Clipboard／Blob等连接当作进度连接采用。
只有当前身份、成员及撤销资格仍有效的`/2`grant可授予空闲保留；`/1`单次使用，不能留作多轮连接。
原生角色和撤销仍使用同一个AdmittedConnections登记，不维护新的私有连接池或影子成员集合。
保留全局最多16连接，按真实空闲时点淘汰最早空闲项；全部保留项都活动时，新连接明确不保留，不能关闭活动项腾位。
工作租约实际结束后才开始30秒空闲计时，入站accept等待及QUIC保活不算业务活动。
空闲回收只关闭本profile的相应连接，成员撤销则统一使该成员的各profile旧连接失效。

当前真实主机验证通过实际backend完成双版本协商、完整终态采用／精确ACK及跨请求复用，
并以17个真实对端验证16保留、仅淘汰空闲和全活动拒绝保留；方向名额在旧本机工作未释放时继续占用。
另有实际31秒本机工作租约加30秒空闲回收验证，不用缩短后的参数代替30秒策略。
这些是Direct主机／运行期租约证明，不代替物理系统挂起、Relay／实机矩阵或生产Router/reporter迁移。


### 挂起恢复与无网络唤醒

单轮可中断网络等待除每次poll前检查原生经过时间外，还以100毫秒有界唤醒重新检查同一预算。
恢复后即使socket没有新事件，也能观察已过期的原五秒截止；检查到期后不再次poll网络工作。
原生时钟读取失败或回退仍按既有规则永久退休旧预算。该检查不包装不可安全中断的本机读取／采用，不提前释放实际工作额度。
系统挂起期间不承诺执行任务；物理平台证明及通用连接空闲计时边界见[平台审计](../exec-plans/active/2026-10-24-transfer-progress-connectivity-feasibility.md#各平台经过时间审计与物理挂起入口)。


### 进度连接空闲期限与原子复用

进度profile在创建时必须注入包含挂起的 `ElapsedClockPort`；该能力与来源错误归入Application connectivity，
progress继续消费同一接口，不建立第二个时钟port。`IdleRetentionPolicy`显式指定该来源；其他协议保持各自既有清醒计时策略。

每次最后一个真实活动租约释放时固定原空闲30秒预算；挂起计入该预算，后台最多100毫秒重新检查。
复用连接与取得流／实际工作许可还在同一活动锁内检查原预算，因此后台尚未回收也不能重新打开已经过期的连接。
过期、不可读、相邻读数回退和截止不可表示均使该旧空闲预算永久失效；不可读保留完整错误来源，空闲连接关闭后不能恢复旧预算。
有实际活动时不因该空闲预算关闭连接；最后一份实际租约释放后才开始新的空闲期。

淘汰仍只选择空闲连接并保持16条上限；关闭未完成的方向许可仍由原连接寿命监督到实际结束。
过期连接不再复用，新请求继续原准入／截止与拨号流程，不新增连接池、业务补发循环或Engine步骤接口。
源时钟不可读作为固定 `elapsed_clock_unavailable` 来源错误；缓存监督只写运行诊断，不创建业务根。

## 实际接收快照提供端

`ReceiveWorkRegistry` 在原接收目录锁内关联认证设备、源条目、已接受尝试和完整计划，再从原 `ReceiveFacts` 及实际保存事实生成逻辑状态。查询不枚举任意本机条目，不触发下载；没有新增持久化或另一次数据库读取，运行期未保留来源时返回 `NotRetained`，会话封口时返回 `AccessDenied`。既有存储读失败不经过该路径，也不被改写成资料缺失。

网络字节齐而尚未保存的文件、尚未完成父结算的目录保持 `Processing`；失败或取消仍在清理时也不提前报告终态。成功释放重试 receipt 后，原动作只把最小最终逻辑状态交给同一来源目录，继续支持查询，不延长原始材料或路径的寿命。该事实与完整快照随原目录的全局256／每端64额度和退休路径回收，每份最多1024项。

完整快照的内容修订独立于登记的 owner revision。重复读取同一内容保持修订；任一项变化使快照修订增加，继续页必须匹配同一修订，不能拼接不同事实。每页仍最多64项；旧尝试查询返回当前描述的 `Superseded`，退休来源不可因查询复活。生产通知hook从同一事实负责人取得精确终态和序号，不能另造序号源；生产Router及宿主结果采用已接同一对象图。

## 完整快照的原子采用

`TransferProgressReconciler` 在组装时持有原发送投影和统一交换监督，调用方只发起一次核对。当前已登记任务从原投影取得不可变范围，网络等待不持投影锁；查询去重同时绑定每次原发送意图的固定本地身份，同一意图共享原在途结果，新意图不能共享旧在途查询，即使远端描述相同也一样。该身份在意图建立时创建，不由每次核对重建，也不进入线格式。完整分页读取通过后，仍须核对同一原意图实例、当前描述和内容修订，随后一次保存全部合并结果并发布变化。原意图被替换、删除或封口时，迟到成功不能写入新实例；失败不修改投影，并保留原共享结果及完整错误来源。

Core复用单项活动／终态规则进行全量合并。快照中任一项缺失、错位、非法或与已采用终态冲突时，整份不采用；较旧活动值不能覆盖较新活动或终态。重复或全部落后的快照不延长有效联系；同一快照修订不能改变其内容，较低修订不能回退已核对事实。完整终态可结束未知等待，不能由字节数或超时推断实际结果。

尚无当前描述时，完整核对只携带原源条目与不可变计划，使用既有可选expected attempt发出第一页请求；认证回复须匹配源条目和计划数量，随后全部页仍通过同一覆盖核验和原预算，才能确认当前任务。查询确认不授予通知binding。更早的在途登记仍受已确认producer／revision围栏约束，匹配的登记可以完成且保留已核对事实，旧描述不能回退任务。若等待期间其他登记已推进到不同范围，迟到查询不采用。

未保留、旧端不支持、访问拒绝、忙碌和已替换等业务回复同样须经过原意图实例与查询起止范围核对；等待期间登记已改变当前任务时返回过期，不把旧回复用于判断新任务。这些回复不更新逐项事实或联系期限；下层失败保留原来源。

对已确认但尚未全部结算的当前任务，NotRetained或Unsupported还会撤销活动确认、通知绑定与在途挑战，保留原描述、修订高水位和已采用的逐项事实，发布Unconfirmed；
旧绑定的迟到通知不能恢复活动。重复负面回复幂等，初始尚无任务时仍保留原Waiting意图，
已确认的完整终态保持Settled。之后通过完整核对可以恢复确认；重复快照不会延长原联系期限，只有有效新事实或新联系按原规则推进。

完整快照分别提供当前确认任务与实际通知绑定；没有binding不等于没有已核对事实。未保留、旧端或明确拒绝不制造任务、终态或下载。稳定宿主查询结果由原完整动作映射，不让Engine或宿主拼接内部步骤。

## 入站连接的完整寿命

`TransferProgressTransport`接收一个原生连接能力，先固定原会话准入围栏，再在同一首轮期限内完成当前成员核验、保留资格与首流。
`/2`后续流从实际收流时刻起算；受管连接在异步准入读取前保存包含挂起的经过时间，仅在Application内部交接，不能等读取结束后重新获得五秒。
旧`/1`只完成一次受管单向交换并关闭，不授予跨轮保留。协议选择只读取实际协商结果，失败不触发旧版重拨。

同一连接允许原manager在实际交换进行时接收并拒绝超量流；单流错误只结束本交换，既有流和其他对端继续使用各自原许可。
连接监听不算业务活动，空闲回收仍由原16连接／30秒策略负责；入站负责人只使用原保留容量与在途额度合计的有界工作位置，不建立新业务等待队列。
投影注册表通过`inbound_transport`创建完整入站能力并持有连接世代命名空间；同一投影重新组装transport仍继续单调分配，不能用实例内从零计数或未承诺数值单调的原生connection id代替。连接重建只退休旧binding，不重置producer修订或真实终态。

调用方取消等待、会话封口、期限消耗及shutdown等待被丢弃，都不能abort已开始的准入或业务采用。
入站连接任务与唯一关闭任务由负责人持有可重复等待的完成结果；关闭先封口，再关闭连接并等待实际本地工作及原manager收尾。
期限与迟到能力同时失败时分别保存来源，复合结算失败不自动补发；任务异常退出按既有进度监督类别进入运行诊断，不新增heartbeat／ACK业务入口。

原生`IrohTransferProgressHandler`只做连接桥接与完整关闭；新版仍由Application登记／采用后响应，旧版只交接未关联通知，查询使用原提供能力。
节点通过同一对象图安装完整Router端点，Engine只组装，实际发送意图／接收hook由Application负责；稳定宿主映射只调用完整动作和变化提示。完整矩阵仍须按执行计划验收。


## 无blob目录的源身份传递

纯空目录没有blob引用，接收端不能从现有V3正文恢复发送端条目UUID。
剪贴板`clipboard-applied/3`提供带可靠源身份的传输头能力，仍使用原多流、正文和应用确认语义。
一次握手按`/3`、`/2`、`/1`协商；消息头布局由实际协商结果决定。携带可靠源身份时，`/3`使用前缀`UCT2`和
原头字段后固定16字节源UUID；原头版本仍表达普通内容／目录语义。`/2`与`/1`继续使用
原`UCT1`字节，不能附加或借用trace字段。没有可靠源身份的旧端空目录只能保持未确认。

原发送动作从同一原始计划确定源身份，并在首条网络消息前登记目标设备与完整逻辑项。
接收端只在原CAS接受后将已认证消息的源身份交给原接收目录；网络头本身不创建进度任务，
也不授予ACK资格。新布局不能经旧协议携带，解析仍拒绝尾随／损坏和超限内容。
本节为已批准合同，实际codec、节点和完整文件链路验收仍由第八片计划跟踪。


宿主完整视图不公开binding、producer、登记修订或线上sequence。原任务／ACK及查询事实继续保留
接收端原始取消原因；发送侧展示只在Application展示边界翻转LocalUser／RemotePeer视角，
Timeout等设备无关原因不变。本机经过时间读取失败保留已确认成果，未结算项显示未确认，
不伪装成对端离线。宿主直接读取完整逐项事实和同锁汇总，无需自行聚合或推断协议阶段。


## 本机所有权与历史删除

协议源UUID与本机历史entry分别承担身份和所有权。原发送动作在第一次异步等待前冻结本机所有权世代，
仅在原待投递记录保存后，用该世代接受目标设备及完整原始计划；不能按迟到顺序重新取得删除前资格。
没有本机历史归属的原raw入口，以其明确的原源UUID作为临时所有者，不借provider或内容hash关联。
每个保留Slot只持有本机owner及其世代，线上登记和稳定DTO仍沿用原源UUID，不向Engine暴露所有权围栏。

History完整删除负责人在等待接收停止、数据库或文件清理前，先取得同一进度注册表的删除围栏。
围栏退休该本机owner的全部设备关联，并封住已经开始及删除期间产生的意图；嵌套清理直到最后一个围栏退出才允许新动作。
清理返回后，旧意图仍永久退休，新的明确动作才取得新世代；另一本机owner的结果不受影响。
原清空/保留清理复用同一删除负责人，不在Facade或Engine枚举slot。删除不会推断接收端取消，也不会清理对端已保存文件。

所有权元数据只包含运行期身份与资格，不保存结果或第二套重试状态。Slot及在途意图释放后，弱引用键在下一次动作时回收，
没有永久墓碑、持久outbox、schema或新明文字段。清空/封口同时退休在途世代，不能用普通连接重建重开旧意图。

主机证据：真实源历史删除先复现“数据库已删除但完整查询仍有卡片”，修复后覆盖已结算删除与接收输出暂停后迟到终态两种实际Engine/SQLite/文件场景；
查询/列表均不复活，接收端两个已保存文件精确保留。原发送在加密能力等待期间遭删除后，即使继续实际投递，也不能重建进度；该端口边界测试不冒充实际加密算法或网络证明。


## 原再次发送动作内的完整核对

`ResendEntryUseCase` 校验本机来源与当前成员，在读取本地原内容或发布 blob 前取得完整核对结果。
`ReconcileSentEntryPort` 由同一 Application 对象图中的 `ProgressViewOwner` 实现，按本机 owner 查找
原投影的协议 source；两种条目身份不必相同，多个保留身份存在歧义时明确拒绝，不能任取一个。
缓存无映射时只返回 NotRetained，不增加持久索引或任意远端枚举权限；开始及返回仍核对当前成员。

每个目标沿用统一交换的预算和并发额度，核对不复原本地 payload，也不刷新旧补发期限。
返回时再次检查可采用的当前视图，缓存退休或尝试替换不能冒充原任务的已结算结果。
完整决策与稳定字段见[规格§5.7](../exec-plans/active/2026-10-24-transfer-progress-connectivity-spec.md#57-原任务核对再次发起与持久化边界)。

只有明确新传输意图和允许的核对结果才进入 `ExistingLocalEntryDelivery`；该能力继续服务自动内容重投，
不植入手动核对策略。接收端仍由原 `prepare_redelivery`／`accept_retry` 对活动、成功项、清理和
expected_attempt 最终 CAS 判定，发送侧快照不授予接收权限。Engine 只映射完整结果和安全错误；
原重新发送记录表达已有成果或等待，查询、heartbeat 和 ACK 不另建业务根。
