# 安全架构

安全问题的私密报告方式和受支持版本见仓库根目录 [`SECURITY.md`](../SECURITY.md)。本文件是工程安全知识入口。

## 不可破坏的边界

- 用户内容（来自剪贴板或经同步收到的内容及其派生数据）写入 SQLite、磁盘缓存、搜索索引或配置文件前必须先经 MasterKey AEAD 加密；唯一例外是下文已批准的受管缓存 basename。
- 凭据和密钥材料（MasterKey、passphrase、KEK、relay 访问令牌、鉴权令牌等）只能保存在系统安全存储中，不得写入配置文件、日志或其他普通文件；Engine 内已有兼容例外仅限「运行期密钥材料」的 `vault/profile-secrets-v1`，不得扩大，宿主侧的已有例外由宿主仓库规定。
- 配置（用户或程序的偏好与参数，如本机设备名、保存目录、relay 地址、局域网地址）可以明文保存，无需逐项审批；配置不得包含用户内容或凭据，日志与观测规则不变。
- 除配置外，可明文保存的只有内容类型枚举、文件内容本体，以及入站文件在受管缓存中经安全清理且仅作实际 basename 的原始文件名。
- 原始目录路径、数据库/搜索字段、日志和其他关联元数据仍须加密或脱敏。
- 除配置外，新增持久字段或文件默认按敏感数据处理；明文例外必须在 PR 说明并取得明确批准。
- 日志、公开错误和观测事件不得包含内容、密码、密钥、完整令牌、邀请、设备名、地址、文件名或路径。
- 网络使用认证加密通道；业务授权仍需核对当前成员范围，不能把认证身份等同于权限。

## 活动安全材料的发布边界

`ActiveSpaceSecuritySession` 独占活动材料的完整安装。更新当前 Space 时，先在私有快照中校验新材料，
再将 catalog 安装到 Profile vault；期间已经提交的材料继续服务内容加密、读取和子密钥派生。
只有 vault 成功且 session generation、Space 与关闭状态仍有效，才在同一临界区发布完整快照。
失败或取消不撤下原会话；清理或关闭后，迟到的安装不得恢复旧密钥。已写入的 catalog 由既有恢复流程幂等复用。

跨 Space 激活及从仓储恢复仍使用未提交事务隔离候选材料；当前 Space 更新的连续可用性不授予读取候选密钥的权限。

## 已批准的本机升级副本例外

2026-09-13 用户批准计划 043 的原样文件副本不额外加密，以保证钥匙串不可用时仍能保留升级前现场。例外仅适用于独立于活动资料的当前用户私有备份目录：保留原文件原有密文或历史明文，不解密、不新增敏感日志，不将钥匙串导出的密钥明文写入副本，不作为可分享导出格式。权限限制不等于加密；副本不提供磁盘损坏、系统账户失陷或密钥丢失后的恢复保证。细则和验收只在[计划 043](exec-plans/active/043-pre-upgrade-profile-backup.md)维护。

使锁文件中的 `libcrux-kem` 升级为 0.0.10，修复 RUSTSEC-2026-0330 与 RUSTSEC-2026-0331。
