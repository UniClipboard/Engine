# t-0010 配对失败与进程退出后的双端收敛

## 完成标准

- 正式提交前，加入方失败、退出或失联都能由持久状态恢复或在共同期限后收尾。
- 邀请方不依赖对端通知，也能终结可证明尚未正式提交的候选；只清理该尝试未启用的准备资料。
- 正式提交后，即使回复丢失或越过期限也不回滚成员，并重放同一成功结果。
- 无法证明是否提交的旧记录进入 `NeedsAttention`，不自动清理。
- 未安全收尾的旧尝试阻止新尝试；候选状态不影响既有正式设备查询和使用。
- 独立进程矩阵、完整门禁、严格审查和本地原子提交完成。
- 真机与保留模拟器只在明确授权后原地验收；未执行时不得报告整体完成。

## Phase 10：正式提交前的双端有界收尾

- [x] 加入方最终启用失败保存为可重发终态。
- [x] 明确失败通知丢失后按持久重试时间恢复，早到唤醒不重复发送。
- [x] 邀请方对可证明未提交的候选独立到期收尾，迟到确认不能复活。
- [x] 到期但尚未落盘收尾的候选继续阻止普通成员维护。
- [x] 补齐重复通知、双方分别重启和加入方各阶段退出的公开行为矩阵。
- [x] 补齐加入方永不恢复时邀请方独立收尾的确定时钟验证；独立进程覆盖早期退出与最终确认后退出。

## Phase 11：正式提交后的成功重放与旧记录迁移

- [x] 两条旧 V3 未确认候选可重建索引并原地收尾。
- [x] 未收尾尝试从仓储事务入口阻止不同邀请创建新尝试。
- [x] 完成回复丢失并越过期限后，双方仍收敛到原成功结果。
- [x] 覆盖可证明未提交、可证明已提交、无法证明三类旧记录。
- [x] 为最终启用失败提供不含身份资料的安全细分类；现场日志不足，具体类别保留未知。

## Phase 12：独立进程、审查、门禁与本地提交

- [x] 双方独立进程覆盖早期退出、最终确认连接失败、邀请方重启和加入方重启；丢消息、重复消息与独立期限由确定性协议测试覆盖。
- [x] 严格检查流程分支、事务一致性、错误来源、日志隐私和模块边界，并修复发现。
- [x] 运行相关完整测试、全仓编译、格式、代码规则、架构与隐私门禁。
- [x] 更新执行计划、架构圣经和 Herdr 报告。
- [x] 按逻辑形成清晰的本地原子提交；不推送、不创建 PR、不发布。
- [x] 自动验证完成后，仅报告真机与模拟器原地验收所需的具体协调步骤。

## Phase 13：统一的空间设备状态

- [x] 以公开查询固定正在更新、已完成、可重试失败和需要用户处理四种整体结果。
- [x] 只有设备效果、设备关系、限制更新和历史确认全部收敛才返回完成。
- [x] 旧 `maintenance_health` 只作兼容投影，Desktop/Mobile 迁移期间不会把新的正在更新误报为健康。
- [x] 本地诊断导出补齐历史交换阶段、安全错误链和固定调用路径，公开结果不暴露内部步骤或敏感资料。
- [x] 测试进程可在邀请方真实提交后一次性丢弃成功回复，并有序观测原成功的重放。
- [x] 完成严格复核和可通过的完整门禁；真实网络长组的独立既有恢复失败单独记录，不冒充通过；形成本地原子提交。

## 安全边界

- 不清空、重置或静默改写身份、正式成员历史和已启用安全资料。
- 不依赖离线状态自动删除；主动通知只加快收尾，不是唯一机制。
- 不新增第二份配对模式开关；所有状态从同一份加密准入记录推导。
- 状态与安全资料变化必须在同一持久动作中完成，崩溃后可重复执行。
