# 调查发现

## Requirements

- 不是给残留路径逐个打补丁，而是定义长期一致的修复方案。
- 成员历史继续作为已接受成员事实的唯一来源。
- 已移除设备不得出现在当前设备列表，也不得进入普通连接、升级、发现、内容和恢复任务。
- 历史事件、历史身份和用户决定必须保留。
- 本地决定、远端事件、重复消息、失败恢复和重启必须得到相同结果。
- 规格必须让未参与调查的实现者可以直接执行。

## Research Findings

- 接受远端移除和接收远端历史各自维护一套新应用事件循环，两处都只处理新增资料和安全状态，没有处理移除后的运行资料。
- 当前运行流程从不同存储选设备：普通名单读取成员表，连接和发送常读取地址表，旧版升级遍历成员表，部分路径再额外调用成员历史门禁。
- 文档声明成员历史是唯一成员事实来源，但部分代码注释仍把地址表称为权威名单，实际存在多个答案。
- 当前分支新增在线接纳确认，只阻止未获当前空间接纳的连接被报告为在线，不能停止拨号、旧版升级或其他候选选择。
- 现有测试覆盖成员历史、安全状态和部分入口拒绝，没有覆盖接受移除后所有运行候选立即退出。
- 成员、信任、地址位于同一加密关系存储，已有一次事务写入多类关系的能力；工作空间状态另有独立加密存储。
- 历史信任身份不能无条件删除，否则会损害旧事件解释和历史关系查询；当前资格与历史身份必须分开。
- 候选来源不仅存在于应用层：多个 Iroh 接收适配器用成员表反查网络身份。规格必须区分“解析身份”和“授予当前权限”，不能以删除历史身份替代授权判断。
- 当前已有三类零散门禁：内容交换、设备列表可见性和安全组接纳。它们表达的用途不同，不能继续扩展成更多彼此独立的布尔规则；需要由同一当前资格结果派生。
- 地址表被主动拨号、成员核对连接和内容发送当作枚举来源；成员表被普通列表和旧版升级当作枚举来源；信任表被手动重发当作枚举来源。三者都不是成员资格来源。

## Technical Decisions

| Decision | Rationale |
|----------|-----------|
| 统一定义“当前运行资格” | 所有普通运行流程需要同一个允许集合，不能各自解释成员表或地址表 |
| 历史是权威事实，运行资料是可修复投影 | 保留验证能力，同时允许启动时从已接受历史恢复一致 |
| 所有候选选择必须通过负责人提供的统一查询 | 从根源消除每个任务自行加过滤条件的重复规则 |
| 投影更新必须可重复执行并有持久化进度 | 跨存储无法天然构成一次事务，必须支持中断后继续 |
| 身份解析与当前授权分离 | 已移除设备仍需被识别和验证，但不能因此获得普通运行资格 |
| 受限成员历史通信不属于普通运行资格 | 接受决定后仍需向移除目标发送有界决定，不能被普通候选清理误伤 |
| 不要求跨工作空间状态与关系存储建立分布式事务 | 先持久化权威历史，所有读路径立即失败关闭；投影以幂等校正最终一致 |
