# 规格 021 实施发现

## 初始事实

- 当前工作区只有规格 021 和架构维护记录，生产能力尚未实现。
- 当前稳定汇总缺少来源、选择影响、逐设备四维事实、动作许可和稳定决定结果。
- 恢复共同设备组仍依赖五项产品决定，本轮不实现。

## 数据源与设计

- `MemberRosterFacade::list_with_presence` 已证明可信设备资料、本机标记和在线缓存可聚合；完整负责人应直接依赖相同端口，而不是让 facade 拼接结果。
- `MembershipReconciliation::pending_removal_facts` 现在从事件父历史解析签名来源和精确目标。
- 已完成本机决定本来就在加密成员历史中，幂等结果不需要新增数据库表或第二队列。
- `peer_history_relationships` 同时驱动内容门禁，可作为逐设备关系结果的权威来源。
- Engine 稳定层只转换应用层完整结果，不重新组合判断；状态提醒只携带版本号并要求重新查询。
- 锁定状态下旧诊断查询仍拒绝读取；新产品查询返回只含本机标识的稳定不可用结果，不解密成员历史，也不暴露其他设备资料。
- 新旧决定入口必须共享同一把决定锁；旧入口对相同的已完成决定返回当前快照，避免迁移期并发或重试被误报为状态错误。
- 正式 Engine 和三个平台已删除旧查询、旧决定和旧提醒；旧观察能力只在明确开启的诊断构建中保留，供多设备测试读取内部进度。
- 三个平台透传同一份完整 JSON 结果，避免三套嵌套映射漂移；稳定字段和未知字段兼容由契约测试与验收宿主固定。
- 完整查询在构建结果期间持有权威状态锁，避免成员变化与设备资料聚合跨越两个逻辑时点。
