# Spec 027 实施计划

## Goal

完整实现 `docs/specs/027-application-space-membership-one-shot-rewrite.md`，只重写 `uc-application` 及同步文档，不把 Core、Infra、Engine、绑定或数据库适配纳入本规格。

## Completion Criteria

- [ ] `SpaceFacade` 是 application 唯一公开 Space 业务入口，内部用例、owner、coordinator 和 runtime 不公开。
- [ ] 正式用户动作、查询、网络消息和后台维护各自只有一个完整入口。
- [ ] 旧成员总对象、旧准入总对象、旧 gossip/候选/公告编排、旧综合状态与旧 runtime 全部删除。
- [ ] V2 成员历史是唯一成员资格来源，普通消费者统一使用最终授权范围并在读取失败时关闭权限。
- [ ] 历史、加入、关系、传输、待处理效果和唯一修订号通过一个条件原子提交接口更新。
- [ ] 查询、移除、决定、历史收发、准入恢复和维护满足规格中的结果、幂等、恢复与错误语义。
- [ ] 敏感资料只传给加密持久接口，日志不含规格禁止的原文。
- [ ] 强制删除清单和模块可见性检查通过，不存在兼容别名、双写、回退或第二实现。
- [ ] 规格要求的 application 测试数量非零且全部通过；格式、架构、差异和仓库规定检查均有明确结果。
- [ ] 架构总览正文与维护记录同步更新。
- [ ] 完成严格复审并提交本任务改动，不夹带无关工作树变化。

## Phases

| Phase | Status | Description |
|---|---|---|
| 1. 需求与现状审计 | complete | 将规格要求映射到当前源码、测试和删除项 |
| 2. 目标接口与 ledger | complete | 先写失败测试，再实现统一事实、原子提交与最终授权范围 |
| 3. 正式成员与历史用例 | complete | 重写查询、移除、决定、历史发送和入站处理 |
| 4. 准入与维护 runtime | complete | 重写完整准入入口，合并维护和生命周期 |
| 5. Facade 与消费者切换 | complete | 切换唯一入口和所有普通 application 消费者 |
| 6. 旧路径删除与文档 | complete | 完成强制删除清单、日志清理和架构文档更新 |
| 7. 验证、复审与提交 | complete | 运行聚焦/全量检查、逐条验收、严格复审和原子提交 |

## Decisions

- 当前工作树中已有的大量改动视为并行工作；不回退、不擅自归属，只有与 Spec 027 直接相关的路径才纳入本任务。
- 外层当前是否能接入不反向决定 application 接口；本规格只证明 application 的 ports 和内存闭环。
- 所有行为改动遵循失败测试先行；若发现已有未验证实现，先补能证明缺口的失败测试再继续。
- 不保留旧接口来换取全工作区编译通过。

## Errors Encountered

| Error | Attempt | Resolution |
|---|---|---|
| 活动计划值与预期不一致，首次 patch 未应用 | 1 | 读取原始字节确认实际值后精确更新；没有文件被部分修改 |
| application 测试清单在编译阶段失败 | 1 | 记录为中间迁移基线；先建立只依赖目标接口的失败测试，不修补旧总对象测试 |
| 首次目标测试被旧聚合测试编译错误阻断 | 1 | 停止编译强制删除范围内的旧测试树，保留目标测试并重新运行 |
| 首次 GREEN 命令过滤到 0 个测试 | 1 | 用 `--list` 取得完整测试名，随后精确执行 1 个测试通过 |
| 聚焦测试进程在动态加载阶段长时间零 CPU | 1 | 抓取线程栈确认尚未进入测试；继续等待后实际执行，后续用非零数量和最终退出码判定 |
| 外部全工作区检查在每次编辑后占用默认构建锁 | 1 | 不终止外部进程；将本任务聚焦测试固定到独立临时构建目录 |
| 待决定查询测试把远端移除直接应用为本机当前事实 | 1 | 改用 Core 远端历史合并生成真实待决定分支，撤下实现后重新观察正确 RED |
| 拒绝测试把多成员直接放入建立基线，Core 无实际父事件可验证 | 1 | 改为先追加一条真实历史事件，再生成远端移除；application 只调用 Core 标准决定规则 |
| 入站测试被尚未实现的发送目标测试阻断编译 | 1 | 临时停用发送测试，完成入站后立即重新启用并实现发送目标接口 |
| 两页历史被 4 MiB transfer 总限制误判 Invalid | 1 | 保留逐页 4 MiB；新增固定 16 MiB application transfer 总上限 |
| 消费者测试命令把 `--message-format` 传给测试二进制 | 1 | 改为放在 Cargo 参数区；编译本身未失败，随后实际测试通过 |
