## Key Questions

1. 当前哪个模块实际负责“最终升级完成”？
2. 调用方现在必须知道多少内部步骤和状态？
3. 哪些接口只有一个实现，却把内部步骤公开成了长期契约？
4. 如何在不失去断网、重启、并发和身份校验能力的前提下收敛结构？

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| 先完成方案再实施 | 先锁定职责和行为边界，再按方案完成替换并验证 |
| 不以文件数量作为问题判断 | 真正问题是基本流程的知识散落和接口过浅 |
| 排除剪贴板接收策略断言改动 | 它是并行变更，与自动升级无关 |
| 由 `AutomaticLegacyUpgrade` 独自负责完整生命周期 | 让组装方和测试只面对一个深模块 |
| 保留两个单方法远端端口 | 它们是真实网络接缝且有生产、测试两种适配器 |
| 用一个内部保护端口替换安全步骤和仓储步骤 | 保留分层方向，同时隐藏证明、缓存和恢复细节 |
| wire v1 本次保持不变 | 把结构重构与协议升级分开，降低风险 |
| 先修复旧 `Ready` 数据兼容再搬结构 | 避免把现有缺口带入新模块 |
| 实施阶段严格执行红灯、绿灯、重构循环 | 证明每项行为由测试真实约束 |

## Errors Encountered

| Error | Attempt | Resolution |
|-------|---------|------------|
| 错误归因无关测试改动 | 1 | 读取具体差异后纠正并排除出方案 |
| 删除核心唯一哈希依赖后 `--locked` 拒绝旧锁文件 | 1 | 先由 Cargo 同步锁文件，再恢复全部带锁验证 |
| 搜索不存在的旧 `ports/space.rs` 路径 | 1 | 根据搜索结果改用实际的 `ports/space/access.rs` |
| 同步规划文件时使用了不存在的标题 | 1 | 补丁未写入，读取实际标题后拆分补丁 |
| 记录阶段测试时多区域补丁未匹配 | 1 | 补丁未写入，拆分更新后继续 |
| 网络边界缺少计划要求的错误路径测试 | 1 | 补齐错误版本、超大消息、未知身份和超时四项验证，均已通过 |
| 身份测试替身引用了错误的错误类型 | 1 | 改用仓库现有身份计算实现后通过编译与测试 |
| 过早把间接证据记为完整验收 | 1 | 重新打开阶段 5；要求真实网络接入测试和排除禁止改动后的完整引擎验证 |
