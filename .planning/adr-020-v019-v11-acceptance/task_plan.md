# ADR-020 0.19 -> 1.1 验收计划

## Goal

用正式 `v0.19.0` 程序与当前 `1.1` 实现完成真实升级混跑，证明旧设备可被发现但内容暂停、升级提示持久化，以及全部升级后自动恢复双向同步。

## Completion Criteria

- 正式 `v0.19.0` 标签可重建并作为旧端运行。
- 两个 `0.19` 端先建立真实关系，再让 A 原地升级到当前实现。
- A 能识别仍为 `0.19` 的 B，并保存升级提示；A 重启后提示仍存在。
- A 与 B 之间双向普通内容均不送达。
- B 原地升级后，A 的提示清除，双向内容实际送达。
- 每个新增目标 case 上方有中文流程说明。
- ADR 与架构文档记录真实结果，不夸大未验证边界。
- 定向测试和仓库交付检查全部通过。

## Phases

### Phase 1: 固定旧版本运行证据

- [x] 从官方 `v0.19.0` 标签构建 `uniclipd` 和 `uniclip`
- [x] 确认旧端初始化、配对、发送和接收的可驱动入口
- **Status:** complete

### Phase 2: 建立跨版本宿主

- [x] 先写失败验收 case，并添加中文流程说明
- [x] 复用两代现有宿主，避免创建第二套产品流程
- [x] 支持 A、B 原地重启和版本切换
- **Status:** complete

### Phase 3: 跑通完整升级场景

- [x] 两个 `0.19` 端建立关系并验证基线同步
- [x] 只升级 A，验证发现和升级提示保存
- [x] 验证 A 重启后提示保留，以及 A、B 双向内容暂停
- [x] 升级 B，验证提示清除和双向恢复
- **Status:** complete

### Phase 4: 文档与最终验证

- [x] 更新 ADR 和架构维护记录
- [x] 跑定向测试
- [x] 跑全部交付检查
- [x] 确认无本次验收遗留构建或测试进程
- **Status:** complete

## Errors

| Error | Attempt | Resolution |
|---|---:|---|
| 原活动计划属于已经完成的其他任务 | 1 | 新建本次独立计划并切换活动指针 |
| 单机接管 case 错把新签名历史条数当成旧关系保留 | 1 | 改为验证旧设备身份仍在、未被移除且没有持久故障；完整状态交给双机验收 |
| 正式 0.19 的默认邀请依赖公共配对服务且订阅失败 | 1 | 使用同标签隐藏的本地地址邀请工具，保持 A/B 实际连接完全本地 |
| 0.19 隐藏开发 CLI 有两个未覆盖的显示分支，无法编译 | 1 | 仅在临时旧检出补齐显示映射；不进入当前仓库，也不改变协议和产品行为 |
| 同机两个旧后台争用默认本地控制端口 | 1 | 从初始化开始分别使用 `UC_PROFILE=a` 和 `UC_PROFILE=b` |
| 配对后切换 profile 使网络身份变化并污染成员视图 | 1 | 废弃该组临时资料；profile 与固定网络端口必须从初始化起保持不变 |
| 1.1 首次启动生成第二个网络身份，旧设备不再认可升级后的 A | 1 | 让运行节点和配置接管共用独立网络身份目录；主安全存储不再保存网络身份 |
| 身份修复后单边升级仍在约 68 秒超时，A 未保存 B 的升级提示 | 1 | 停止重复跑慢速场景；改用运行入口局部测试验证启动时已在线成员是否会被核对 |
| 首次局部测试筛选执行了 0 项，79 秒仅用于重编译 | 1 | 使用完整模块路径配合 `--exact`，并把实际执行数量作为判定条件 |
| 启动主动核对发生在资料解锁前，因存储锁定退出；解锁后没有补跑 | 1 | 把红测升级为锁定后恢复时序，并接入现有会话恢复完成生命周期，不使用定时轮询 |
| 空间生命周期句柄无法引用私有运行模块中的活动类型 | 1 | 从负责人模块内部导出该内部类型，不扩大 crate 外公共入口 |
| 已导出的内部活动类型的方法仍只允许原子模块访问 | 1 | 将两个生命周期方法调整为 crate 内可见，公共 Engine 入口不变 |
| 解锁后核对正常返回但没有选择 B，真实 0.19 资料没有 1.1 签名成员历史 | 1 | 回归改为真实迁移形态；从已保存的可信配对地址选择核对对象，仍由同一负责人完成判断 |
| B 正确报告 A 离线时 0.19 CLI 返回非零，测试误判为命令未执行 | 1 | 解析发送报告，明确断言 0 接收、1 离线、0 错误，再检查 A 未保存文本 |
| 格式检查发现前一轮收敛代码仍未统一格式化 | 1 | 运行仓库统一格式化后继续，未改变行为 |
