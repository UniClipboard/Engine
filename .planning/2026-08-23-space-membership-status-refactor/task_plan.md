## 完成标准

- 旧安装升级后不会恢复旧成员资格，只保留本机并要求全部重新配对。
- 缺少成员状态时不会通过旧成员表补造成员范围。
- 普通成员状态查询不创建或保存成员状态。
- 查询用例不依赖 `WorkspaceMembership`。
- Engine 只通过 application Facade 查询。
- 外部 `QueryDeviceTrust` 操作和结果格式保持兼容。

## 已做决定

| 决定 | 原因 |
| --- | --- |
| 不把 `load_state_with_presence()` 原样迁入共享状态模块 | 它混合了普通读取、懒初始化和旧安装恢复三种责任。 |
| 删除旧成员自动恢复 | ADR-023 已用单设备隔离和全部重新配对取代 ADR-020 的逐台恢复。 |
| 普通查询遇到缺失记录时不创建状态 | 创建初始状态属于初始化或恢复行为，不属于查询。 |
| Engine 不直接持有用例 | application Facade 是 Engine 与内部应用流程之间的唯一入口。 |
| 暂停使用新建的 `space/membership/state.rs` 草稿 | 当前草稿建立在“通用读取负责创建状态”的错误前提上。 |
| 保留 application 成员状态仓储接口 | 接口归属迁移与旧恢复策略无关，application 仍需要读写成员状态。 |
